# 007 图表中文说明

## 本次目标

在页面上直接说明 `Bitrate Trend` 和 `Latency Trend` 两个图表的含义，避免只看到曲线但不知道每条线代表什么。

## 做了什么

在 `public/index.html` 的两个图表下方加入中文说明：

1. `Bitrate Trend`：解释 send、recv、target 分别代表发送端真实码率、接收端统计码率和手动设置的目标上限。
2. `Latency Trend`：解释 rtt 和 jitter 分别代表 ICE 选中链路往返时间和 RTP 到达间隔抖动。

在 `public/styles.css` 中新增 `.chart-help` 样式，让说明文案和图表保持视觉关联。

## 遇到的问题

图表已经能显示数据，但对于面试展示或自己复盘来说，只有英文 legend 不够直观。尤其 target/send/recv 以及 rtt/jitter 的语义，如果不在页面上标清楚，讲解时容易临时解释不完整。

## 怎么排查

查看当前页面结构，确认图表由 `canvas` 绘制，legend 是画在 canvas 内部的英文短标签。最简单稳定的方案是在 canvas 下方加中文说明，不影响绘图逻辑。

## 怎么解决

新增静态说明文案，不改动 stats 采样和绘图逻辑。这样风险小，也方便后续继续补充弱网、ABR 或端到端延迟说明。

## 技术取舍

没有把中文说明画进 canvas，因为 canvas 文本不利于响应式布局和复制阅读。使用普通 HTML 文案更适合面试讲解和后续维护。

## 涉及的关键知识点

1. target bitrate、send bitrate、recv bitrate 的区别。
2. ICE RTT。
3. RTP jitter。
4. 指标可视化的解释层。

## 和我过往经验的连接

这一步对应工程展示中的“指标可解释性”。以前做 RTMP 或实时预览优化时，不只是看曲线，还要能解释曲线代表的链路位置和问题含义。这里把说明直接放到页面上，能帮助面试时快速建立上下文。

## 面试讲法

我在 stats 图表下面补了中文说明，因为实时音视频指标不是只要展示出来就够了，还要能解释每条曲线对应链路中的哪个位置。码率图里 target 是控制目标，send 是发送端真实输出，recv 是接收端统计；延迟图里 rtt 是网络路径往返时间，jitter 是 RTP 包到达抖动。这样面试官看页面时，我可以直接围绕这些指标讲排查思路。

## 后续可扩展

后续加入弱网模拟和自动 ABR 后，可以继续在页面上补充策略说明，例如“为什么 loss 高时降码率”或“为什么 jitter 高时可能增加播放缓冲”。
