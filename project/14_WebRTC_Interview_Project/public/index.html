这个页面用来验证什么

打开两个标签页并加入同一个房间后，页面会通过 WebSocket 交换 offer / answer / ICE candidate，再由 WebRTC 建立 P2P 视频链路。下面的控件负责控制采集源和编码上限，指标区和图表区负责观察真实链路表现。

控制区

这里控制一次 WebRTC 实验的输入源、采集规格和发送端编码上限。修改 Max Bitrate 后点击 Apply Encoding，会通过 RTCRtpSender.setParameters 动态限制发送端码率。

视频区

Local 是本端采集并送入 PeerConnection 的视频；Remote 是对端通过 WebRTC RTP 传过来并由浏览器解码渲染的视频。若 Local 有画面但 Remote 没画面，优先排查信令、ICE 和 track 事件。

Local 本地采集 / 发送源
Remote 远端接收 / 解码渲染

实时指标区

这些数值来自 getStats 和 DataChannel。它们把“卡、糊、慢”拆成可观察指标：网络往返、抖动、丢包、码率、帧率、分辨率、ICE 状态和应用层 RTT。

RTT-ICE 网络路径往返时间，越高互动延迟越明显。
Jitter-RTP 包到达间隔抖动，越高越容易触发缓冲和卡顿。
Packet Loss-接收端统计的丢包数量，丢包高会影响清晰度和流畅度。
Send Bitrate-本端实际发送码率，用来判断编码输出和发送 pacing。
Recv Bitrate-本端实际接收码率，可和 send 对比判断链路损耗。
FPS-编码或解码帧率，下降时可能是编码、网络或渲染压力。
Resolution-当前视频帧分辨率，决定清晰度和码率需求。
ICE-ICE 连接状态；connected / completed 表示路径建立成功。
Data RTT-DataChannel ping-pong 应用层 RTT，用来补充网络指标。
Target Bitrate-手动设置的码率上限；它是目标，不等于真实发送码率。
ABR State-当前码率策略状态；用于观察自动降码率和恢复过程。

趋势图区

趋势图展示最近 60 秒采样，Export Stats 会导出本次会话全部采样。面试讲解时重点观察“控制量”和“结果量”的关系：target 改了以后 send / recv 是否跟随，RTT / jitter 是否随网络波动变化。

Bitrate Trend 码率趋势

send 表示发送端真实码率，recv 表示接收端统计到的码率，target 表示手动设置的目标上限。用它观察 setParameters 后真实码率是否跟随变化。

Latency Trend 延迟 / 抖动趋势

rtt 表示 ICE 选中链路的网络往返时间，jitter 表示 RTP 到达间隔抖动。用它观察网络波动、抖动缓冲和卡顿风险。

事件日志区

这里记录信令和连接状态变化。排查建连问题时按顺序看：是否加入房间、是否发送 offer、是否收到 answer、是否交换 candidate、PeerConnection 是否 connected。
