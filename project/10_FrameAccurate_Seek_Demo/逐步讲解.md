## 二、Demo 覆盖的流程

```
用户输入 2.0s (UI 层 double)
        │
        ▼ Step 1  av_rescale_q：秒 → int64 pts
        │         对比 float 直接换算的差异
        ▼ Step 2  读 index_entries，找目标前最近关键帧
        ▼ Step 3  决策 Classic Seek vs Smart Seek
        ▼ Step 4  avformat_seek_file(BACKWARD) + avcodec_flush_buffers
        ▼ Step 5  av_read_frame → send/receive 直到 pts >= target_pts
        ▼
    输出命中帧信息 + 保存 PPM
```

---

## 三、Step 1：2.0 秒 → pts

### 核心公式

```
真实时间(秒) = pts × av_q2d(time_base)
```

反过来：

```cpp
// ✅ 推荐
int64_t ms = llround(2.0 * 1000);
int64_t pts = av_rescale_q(ms, {1,1000}, stream->time_base);

// ❌ 不推荐用于 Seek 边界
int64_t pts_bad = (int64_t)(2.0 / av_q2d(stream->time_base));
```

### 为什么要先变毫秒整数？

`2.0` 这个 double 本身没问题，但 `(int64_t)(2.0 * 90000)` 和 `av_rescale_q(2000ms)` 在部分 time_base 下可能差 1 个刻度。  
**Seek 边界差 1 个 pts = 可能偏一帧。**

---

## 四、Step 2：index_entries 与 stss

打开 MP4 时 FFmpeg 解析 `moov`，把 `stss`（关键帧表）填进内存索引。

FFmpeg 6+ 不再直接暴露 `stream->index_entries`，改用公开 API：

```cpp
avformat_index_get_entries_count(st);
avformat_index_get_entry(st, idx);
avformat_index_get_entry_from_timestamp(st, target_pts, AVSEEK_FLAG_BACKWARD);
```

Demo 里 `FindPrevKeyframePts()` / `HasKeyframeBetween()` 基于上述 API，用于 Smart Seek 的 GOP 判断：  
**current_pts 到 target_pts 之间有没有关键帧？**

---

## 五、Step 4：Classic Seek

```cpp
avformat_seek_file(fmt, stream_idx,
                   INT64_MIN, target_pts, target_pts,
                   AVSEEK_FLAG_BACKWARD);
avcodec_flush_buffers(dec_ctx);
```

| 动作 | 原因 |
|---|---|
| `BACKWARD` | 跳到 ≤ target_pts 的最近 I 帧，保证可解码 |
| `flush` | 清空 DPB，避免旧 GOP 参考帧污染 |

---

## 六、Step 5：顺解到目标帧

H.264 的 P/B 帧不能随机解，即使 Seek 到了关键帧，还要 **顺序 decode 并丢弃中间帧**，直到：

```cpp
frame->pts >= target_pts
```

这才是 **Frame-Accurate Seek**，和用户「从 2.0 秒开始裁剪」的语义一致。

---

## 七、Smart Seek（第二次 Seek 可选）

若当前已在 2.0s 附近，再 Seek 2.5s，且中间没有新关键帧：

- **不** 调用 `avformat_seek_file`
- **不** `flush`
- 直接从当前解码器状态顺解到 2.5s

对应自动剪辑高频抽帧场景。运行：

```bash
./build/frame_accurate_seek_demo test.mp4 2.0 2.5
```

观察第二次输出 `[Smart Seek] 跳过 demux seek / flush`。

| Demo 步骤 | 自动剪辑项目 |

| 用户 2.0s | 上层/UI 时间输入 |

## 九、自检问题

1. `pts * time_base` 等于什么？→ **真实秒数**
2. 为什么 Seek 后要 flush？→ **清空解码器参考帧状态**
3. 为什么 BACKWARD 而不是 FORWARD？→ **保证从可独立解码的 I 帧开始**
4. float 换算和 av_rescale_q 何时会不同？→ **time_base 非整除、边界刻度**
5. Smart Seek 何时不能用？→ **回退、跨 GOP、首次 Seek**
