## 三、Part A：关键帧索引源码

`avformat_find_stream_info` 打开 MP4 时，内部 `mov_read_header` 函数自动解析了 `moov` box 中的 `stss` 表，结果存入 memory index。

FFmpeg 6+ 不再直接暴露 `stream->index_entries`，改用公开 API：

```cpp
int count = avformat_index_get_entries_count(stream);
const AVIndexEntry* e = avformat_index_get_entry(stream, idx);
const AVIndexEntry* hit = avformat_index_get_entry_from_timestamp(
    stream, target_pts, AVSEEK_FLAG_BACKWARD);

// AVIndexEntry 包含:
//   e->timestamp  ← 来自 stts 的 PTS
//   e->pos        ← 来自 stco 的字节偏移
//   e->flags      ← AVINDEX_KEYFRAME 位来自 stss
```

这就是把 MP4 的 stss/stts/stco 三张表合在一起读出来了，不需要手写 MP4 parser。

## 四、Part B：完整帧索引

关键帧索引只覆盖 I 帧。完整帧索引需要知道**每一帧**的信息。Demo 中 `BuildFullFrameIndex()` 做了：

```cpp
av_seek_frame(..., 0, AVSEEK_FLAG_BYTE);   // 回到开头
while (av_read_frame → avcodec_send_packet → avcodec_receive_frame) {
    info.frame_id    = frame_cnt++;         // 绝对帧序号
    info.pts         = frame->pts;          // 精确PTS（解码器填充）
    info.byte_offset = frame->pkt_pos;      // 字节偏移
    info.is_keyframe = frame->key_frame;    // 关键帧标记
    info.gop_index   = ...;                 // GOP归属
}
```

**生产环境的区别**：这一步在线上做就慢了。正确做法是：
1. 上传时异步跑一遍解封装，不丢给消费者
2. 把 FrameIndex 序列化存起来（Redis/Metadata DB/对象存储 sidecar）
3. 线上直接读 FrameIndex → AVSEEK_FLAG_BYTE Seek

## 五、Part C：Smart Seek 决策

核心判断函数 `MakeSeekDecision()`：

```cpp
if (首次Seek || 目标在当前之前)
    → Classic Seek

if (同GOP内向前)
    → Smart Seek (不调 demux seek, 不 flush, 直接顺解)

if (跨GOP)
    → Classic Seek
```

"同GOP内" 的判断依赖索引：**current_pts 到 target_pts 之间没有关键帧**。

这就是 `HasKeyframeBetween()` 做的事，它依赖 Part A 建立的关键帧索引。

## 六、Part D：三种抽帧方法详细对比

| 方法 | API | 精度 | 适用场景 |
|------|-----|------|---------|
| **AVSEEK_FLAG_FRAME** | `av_seek_frame(fmt, idx, frame_id, AVSEEK_FLAG_FRAME)` | ⭐⭐⭐⭐⭐ | CFR MP4/MKV |
| **FrameIndex + BYTE** | `av_seek_frame(fmt, idx, byte_offset, AVSEEK_FLAG_BYTE)` | ⭐⭐⭐⭐⭐ | 所有格式 |
| **av_rescale_q 时间戳** | `av_seek_frame(fmt, idx, pts, AVSEEK_FLAG_BACKWARD)` | ⭐⭐⭐⭐ | CFR 可靠 |
| **float 直除时间戳** | 同上，但 pts 来自 float 计算 | ⭐⭐ | 仅供反面教材 |

### 为什么 AVSEEK_FLAG_FRAME 最好

```cpp
// 这一行代码内部做了什么？
av_seek_frame(fmt, video_stream_idx, 42,
              AVSEEK_FLAG_FRAME | AVSEEK_FLAG_BACKWARD);

// FFmpeg 的 MOV demuxer 内部：
//   1. 收到 FLAG_FRAME → 知道 42 是帧号
//   2. 查内部的 sample table → 找到 sample[42]
//   3. 从 stco + stsc 算出 sample[42] 的字节偏移
//   4. 从 stss 找 sample[42] 前面最近的关键帧
//   5. 用 AVSEEK_FLAG_BYTE 跳到那个关键帧
//   6. 顺解码到 sample[42]
//
// 全程 0 次时间戳转换！
```

## 八、自检问题

1. `stss` Box 存的是什么？→ **关键帧的 sample 编号列表**
2. 为什么 `AVSEEK_FLAG_FRAME` 比时间戳 Seek 精确？→ **它用帧号直接映射到 sample，零时间戳参与**
3. 完整 FrameIndex 需要哪些字段？→ **frame_id, pts, byte_offset, size, is_keyframe, gop_index**
4. Smart Seek 什么时候不能用？→ **目标在当前之前、跨 GOP、首次 Seek**
5. VFR 视频下为什么时间戳方案不可靠？→ **帧间隔不固定，不能用 `frameId × avg` 硬算**
6. 生产环境为什么不每次 `BuildFullFrameIndex`？→ **首次扫描耗时大，应在上传链路异步完成并缓存**
