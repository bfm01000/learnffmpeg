## 关键决策摘要（已锁死,不要重新讨论）

### 项目定位（A/B 分层硬约束）

- **A 层**：基于 libwebrtc m120 做 1v1 视频通话最小 demo（不自己实现整套 WebRTC）
- **B 层**：自己重写 RTP 打包/解包器 + 视频 Jitter Buffer（200-500 行 + 单测）

### 平台与技术栈

- **平台**：macOS 端到端
- **libwebrtc 获取**：CocoaPods GoogleWebRTC（跳过自编译）
- **信令**：C++17 + uWebSockets + JSON over WebSocket
- **NAT 穿透**：coturn（Docker）
- **B 层项目**：独立 CMake 项目,纯 C++17 + GoogleTest,不依赖 libwebrtc

### 学习哲学（这次会话验证的关键原则）

- **先全景再细节**：进入任何技术领域前,先建立"地图感"和"当前阶段定位",再深入代码。已落地为 `engineering-overview` skill。
- **跑通测试 ≠ 学到东西**：用户必须**自己思考、卡住、突破**才算学到。代写代码再让他点 cmake,等于他啥都没学。
- **诚实暴露简化**：B 层模块明确声明"用 EWMA 不用 Kalman"等取舍,主动暴露简化点反而是面试加分项。

### 用户偏好（memory 里已记录）

- 文档/代码命名禁用 `lo / hi / i / j / tmp / buf` 等无语义缩写
- commit message 用描述性中文,别跟着历史 "update" 偷懒
- 简历精简、重成果、避免口语化
