# C++ 移动语义与右值引用：面试速记与原理详解

> 相关：移动构造 `noexcept` 与容器扩容见 [[12-STL容器底层]]；完美转发常配合智能指针工厂，见 [[06-智能指针与资源管理]]。

## 面试常问问题

**问题 1：什么是右值引用？**

右值引用是 C++11 引入的一种引用类型，写作 `T&&`，主要用来绑定右值，也就是临时对象、即将销毁的对象。它让程序可以识别“这个对象的资源可以被拿走”，从而实现移动语义。

**问题 2：为什么要引入右值引用？**

为了解决临时对象深拷贝带来的性能浪费。比如一个对象内部有一大块堆内存，临时对象马上就要销毁，如果还完整拷贝一份数据就很浪费。右值引用允许新对象直接接管临时对象的资源。

**问题 3：移动语义和拷贝语义有什么区别？**

拷贝语义是复制资源，两个对象各自拥有一份独立资源；移动语义是转移资源所有权，把源对象的资源交给目标对象，源对象进入“有效但内容不再保证”的状态。

**问题 4：`std::move` 会真正移动对象吗？**

不会。`std::move` 本质上只是一次类型转换，把左值转换成右值引用。真正的资源转移发生在移动构造函数或移动赋值函数里。

**问题 5：类里有 `std::vector` 成员，需要自己写移动构造吗？**

通常不需要。`std::vector`、`std::string`、`std::unique_ptr` 这类 RAII 成员本身已经支持移动，编译器生成的默认移动构造会自动移动它们。只有当你手写移动构造时，才需要在初始化列表里写 `std::move(other.member)`。

**问题 6：什么时候必须手写移动构造？**

当类自己管理裸资源时通常要手写，比如裸指针、文件描述符、socket、C API handle 等。因为编译器默认移动裸指针只是复制指针值，可能导致两个对象指向同一块资源，最终重复释放。

**问题 7：为什么移动构造函数常写 `noexcept`？**

因为标准库容器在扩容、搬迁元素时更愿意使用不会抛异常的移动构造。如果移动构造没有 `noexcept`，容器为了异常安全，可能会退回使用拷贝构造。

**面试官**：请你讲一下什么是右值引用？为什么要引入右值引用？

## 一句话回答

右值引用是 C++11 引入的引用类型，写作 `T&&`。它的核心作用是识别“即将不再使用的对象”，从而支持**移动语义**：不再对资源做昂贵的深拷贝，而是直接接管资源所有权。

## 1. 先区分左值和右值

可以先用面试里好理解的方式说：

- 左值：有名字、通常可以取地址、表达式结束后还存在的对象。
- 右值：临时值、字面量、函数返回的临时对象，通常表达式结束后就要销毁。

```cpp
int a = 10;       // a 是左值
int b = a + 1;    // a + 1 是右值
int c = 20;       // 20 是右值
```

严格来说，左值/右值是表达式的值类别，不完全等同于“能不能取地址”。但面试中可以用这个规则先建立直觉。

## 2. C++11 之前的问题：临时对象也只能深拷贝

假设有一个类内部管理堆内存：

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>

class Buffer {
public:
    Buffer(std::size_t size)
        : size_(size), data_(new int[size]) {
        std::cout << "construct\n";
    }

    ~Buffer() {
        delete[] data_;
    }

    Buffer(const Buffer& other)
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + other.size_, data_);
        std::cout << "copy\n";
    }

private:
    std::size_t size_;
    int* data_;
};

Buffer makeBuffer() {
    return Buffer(1024);
}

int main() {
    Buffer b = makeBuffer();
}
```

如果没有移动语义，当 `makeBuffer()` 返回一个临时 `Buffer` 时，初始化 `b` 只能依赖拷贝构造函数。拷贝构造会重新申请一块堆内存，再把原对象的数据逐个复制过去。

问题在于：这个临时对象马上就要销毁，它内部那块堆内存本来可以直接交给 `b` 使用，没必要做一次完整深拷贝。

## 3. 右值引用解决什么问题

C++11 引入 `T&&`，让我们可以专门为“右值对象”写一个移动构造函数：

```cpp
class Buffer {
public:
    Buffer(std::size_t size)
        : size_(size), data_(new int[size]) {
        std::cout << "construct\n";
    }

    ~Buffer() {
        delete[] data_;
    }

    Buffer(const Buffer& other)
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + other.size_, data_);
        std::cout << "copy\n";
    }

    // 移动构造
    Buffer(Buffer&& other) noexcept
        : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
        std::cout << "move\n";
    }

private:
    std::size_t size_;
    int* data_;
};
```

关键点在这段移动构造函数：

```cpp
Buffer(Buffer&& other) noexcept
    : size_(other.size_), data_(other.data_) {
    other.size_ = 0;
    other.data_ = nullptr;
}
```

这里没有重新申请内存，也没有复制数组内容，只是把 `other.data_` 这个指针接管过来。随后把 `other.data_` 置空，避免两个对象析构时重复释放同一块内存。

所以移动语义的本质不是“复制资源”，而是“转移资源所有权”。

## 4. `std::move` 做了什么

右值引用常和 `std::move` 一起出现，但要注意：

- `std::move` 本身**不移动任何东西**，它只是一个类型转换（转成右值）。
- 真正执行移动（偷内存）操作的，是类自己实现的**移动构造函数**。
- 如果你对一个没有实现移动构造函数的类（比如普通的 `int` 或者老旧的 C++98 类）使用 `std::move`，它会退化调用普通的拷贝构造函数，什么优化都没有。

```cpp
Buffer a(1024);
Buffer b = a;             // a 是左值，调用拷贝构造
Buffer c = std::move(a);  // 把 a 转成右值引用，调用移动构造
```

执行 `std::move(a)` 之后，`a` 仍然是一个有效对象，但它的内部资源可能已经被转移走了。之后只能对它做析构、重新赋值等安全操作，不应该再依赖它原来的内容。

## 5. 什么时候需要手写移动构造

判断原则是：**优先不手写，除非类自己管理资源，或者移动时有额外语义要处理。**

如果类的成员本身都是 RAII 类型，比如 `std::vector`、`std::string`、`std::unique_ptr`，通常不需要手写移动构造函数。编译器生成的默认移动构造会逐个移动成员：

```cpp
class User {
public:
    std::vector<int> scores;
    std::string name;
    std::unique_ptr<int> age;

    User(User&&) noexcept = default;
    User& operator=(User&&) noexcept = default;
};
```

这里的默认移动构造会自动移动 `scores`、`name` 和 `age`。也就是说，它会调用这些成员自己的移动构造函数，不需要我们手动写 `std::move(scores)`。

但如果你选择手写移动构造函数，就要注意：`other` 虽然类型是 `User&&`，但 `other` 这个变量有名字，所以它本身是左值。要移动成员，必须显式写 `std::move(other.xxx)`：

```cpp
class User {
public:
    std::vector<int> scores;
    std::string name;

    User(User&& other) noexcept
        : scores(std::move(other.scores)),
          name(std::move(other.name)) {
    }
};
```

如果写成下面这样，就不是移动，而是拷贝：

```cpp
User(User&& other)
    : scores(other.scores),  // other.scores 是左值，调用 vector 拷贝构造
      name(other.name) {
}
```

真正需要手写移动构造的场景主要有三类：

- 类里有裸指针、文件描述符、socket、C API handle 等裸资源，编译器不知道怎么安全转移所有权。
- 移动后需要重置额外业务状态，比如把 `id` 置为无效值。
- 已经手写了析构函数、拷贝构造或拷贝赋值，需要按“五法则”检查移动操作是否还会被正确生成。

简单记忆：

- 只有 `vector/string/unique_ptr` 这类成员：优先 `= default`，甚至不写。
- 有裸资源：通常要手写移动构造和移动赋值。
- 手写移动构造时：成员要用 `std::move(other.member)`。

## 5.5 万能引用与完美转发（std::forward）

这是右值引用的进阶高频考点，常和模板一起出现。

### 万能引用（Universal / Forwarding Reference）

`T&&` 不一定是右值引用——**只有在“类型推导”语境下**（模板参数 `T&&` 或 `auto&&`），它才是“万能引用”，既能绑左值也能绑右值。靠的是**引用折叠**规则：

```text
T&  &   → T&        T&  &&  → T&
T&& &   → T&        T&& &&  → T&&
```

```cpp
template <typename T>
void wrapper(T&& arg);   // T&& 是万能引用：传左值 T 推导为 U&，传右值推导为 U

void g(SomeType&& arg);  // 这个 && 不是万能引用：没有类型推导，就是普通右值引用
```

### 完美转发：std::forward

写转发函数（如工厂、`emplace`、包装器）时，我们希望把参数**原封不动**（保持左值/右值属性）传给下游。问题是：`arg` 一旦有了名字就变成左值，直接传会丢掉右值属性、退化成拷贝。`std::forward<T>` 解决这点——**按推导出的 T 有条件地还原右值属性**：

```cpp
template <typename T>
std::unique_ptr<Widget> factory(T&& arg) {
    // 传进来是右值就转发为右值（触发移动），是左值就保持左值（拷贝）
    return std::make_unique<Widget>(std::forward<T>(arg));
}

Widget w;
factory(w);             // 左值 → forward 后仍是左值 → Widget 拷贝构造
factory(Widget{});      // 右值 → forward 后还原为右值 → Widget 移动构造
```

**`std::move` vs `std::forward`**：

- `std::move`：**无条件**把实参转成右值（“我确定不再用它了，资源拿走”）。
- `std::forward`：**有条件**转换，只在原本是右值时才转成右值（“原样传递，别人是什么我转什么”）。
- 经验法则：**右值引用参数用 `std::move`，万能引用参数用 `std::forward`**。

> `emplace_back` 比 `push_back` 高效，正是因为它用完美转发把构造参数原地转发给元素构造函数，省掉临时对象（见 [[12-STL容器底层]]）。

## 6. 面试总结

可以这样收尾：

> 右值引用的引入，是为了让 C++ 能区分普通对象和即将销毁的临时对象。对于临时对象，程序可以通过移动构造或移动赋值直接接管它的资源，避免不必要的深拷贝。`std::move` 则是把一个左值显式转换成右值引用，它本身不移动资源，真正的移动发生在移动构造函数或移动赋值函数里。

## 7. 常见追问

**追问 1：右值引用变量本身是左值还是右值？**

右值引用变量本身是左值，因为它有名字。

```cpp
void f(Buffer&& x) {
    Buffer a = x;             // x 有名字，是左值，调用拷贝构造
    Buffer b = std::move(x);  // 显式转换后，调用移动构造
}
```

**追问 2：为什么移动构造函数通常要加 `noexcept`？**

标准库容器在扩容时更愿意使用不会抛异常的移动操作。如果移动构造没有标记 `noexcept`，为了保证异常安全，`std::vector` 等容器可能退回去使用拷贝构造。

**追问 3：移动语义是不是一定比拷贝快？**

不一定。对 `int`、`double` 这类简单类型，移动和拷贝几乎没有区别。移动语义主要优化的是管理堆内存、文件句柄、网络连接等资源的对象。
