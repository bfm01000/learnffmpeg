## 面试速记

- **编译四阶段**：预处理（宏展开、`#include` 文本插入）→ 编译（生成汇编）→ 汇编（生成 `.o` 目标文件）→ 链接（合并目标文件 + 库，解析符号）。
- **编译单元（Translation Unit）**：一个 `.cpp` 连同它 `#include` 的内容，是独立编译的最小单位。`.cpp` 之间编译期互不可见，靠链接期符号连接。
- **ODR（单一定义规则）**：每个实体在整个程序里**定义只能有一份**；但 `inline` 函数、模板、类定义允许在多个编译单元出现“相同的”定义。
- **声明 vs 定义**：声明告诉编译器“有这么个东西”，定义分配实体。头文件放**声明**（和 inline/模板/类），`.cpp` 放**定义**。
- **静态库（.a/.lib）**：链接时把用到的目标代码**拷进**可执行文件；**动态库（.so/.dll/.dylib）**：运行时才加载，多个程序共享一份。
- **两类经典错误**：`undefined reference`（链接期找不到定义）vs 重复定义（违反 ODR）。

## 一、编译四阶段

```text
源码 .cpp
  │  ① 预处理 (cpp)      宏展开、#include 文本插入、条件编译
  ▼  → .i
  │  ② 编译 (cc1plus)    语法/语义分析、优化，生成汇编
  ▼  → .s
  │  ③ 汇编 (as)         汇编 → 机器码目标文件（含符号表、重定位表）
  ▼  → .o
  │  ④ 链接 (ld)         合并多个 .o + 库，解析符号引用、重定位
  ▼  → 可执行文件 / 库
```

`g++ -E`（停在预处理）、`-S`（停在汇编）、`-c`（停在目标文件、不链接）可分别查看各阶段产物。

## 二、编译单元与“看不见”的问题

每个 `.cpp` 是独立编译单元，编译 `b.cpp` 时**看不到** `a.cpp` 的内容，只能看到头文件里的**声明**。

```cpp
// math.h
int add(int, int);          // 声明：告诉调用方“有这个函数”

// math.cpp
int add(int a, int b) { return a + b; }   // 定义：真正的实现

// main.cpp
#include "math.h"
int main() { return add(1, 2); }
// 编译 main.cpp 只需声明；add 的真实地址在链接期由 math.o 提供
```

这正是**内联函数、模板的定义必须放头文件**的原因——调用方所在的编译单元必须看到完整定义才能展开/实例化（见 [13-语言基础关键字](13-语言基础关键字.md)、[14-模板与泛型编程](14-模板与泛型编程.md)）。

## 三、ODR（One Definition Rule）

- **变量/普通函数**：整个程序里**定义只能一份**。
- **允许多份相同定义**（每个编译单元一份、且内容一致）：`inline` 函数/变量、类类型定义、模板、`constexpr` 函数。这就是为什么类定义能放头文件被多处 `#include`。

```cpp
// ❌ 头文件里放非 inline 的定义 → 被多个 .cpp 包含 → 链接期重复定义
// util.h
int counter = 0;            // 多个 .cpp 包含会重复定义
// ✅ 正确做法
extern int counter;         // 头文件：声明
// util.cpp
int counter = 0;            // 唯一定义
// 或 C++17：
inline int counter = 0;     // inline 变量，允许多编译单元出现
```

## 四、静态库 vs 动态库

| | 静态库 `.a` / `.lib` | 动态库 `.so` / `.dll` / `.dylib` |
| :--- | :--- | :--- |
| 链接时机 | 编译链接期把用到的代码**拷入**可执行文件 | 运行期加载 |
| 体积 | 可执行文件大 | 可执行文件小，库独立 |
| 共享 | 每个程序各一份 | 多程序共享一份内存映射 |
| 更新 | 改库需重新链接 | 替换 `.so` 即可（ABI 兼容前提下） |
| 启动 | 快 | 略慢（要加载、符号重定位） |

音视频里 FFmpeg 常以动态库形式分发（`libavcodec.so` 等），App 体积小、可单独升级编解码库。

## 五、符号可见性（进阶加分）

- C++ 函数符号带 **name mangling**（编码参数类型以支持重载），`extern "C"` 可关闭 mangling 以对接 C / JNI。
- `-fvisibility=hidden` + `__attribute__((visibility("default")))`（或 `__declspec(dllexport)`）控制动态库导出哪些符号——减小符号表、加快加载、隐藏实现。
- `static`（文件作用域）/匿名命名空间：把符号限制在本编译单元，**内部链接**，避免符号冲突。

## 六、两类经典错误怎么排查

1. **`undefined reference to 'foo'`（链接期）**：声明了但**没有定义**，或定义所在的 `.o`/库没参与链接。
   - 查：函数是否只写了声明没实现？库是否加进链接命令（`-lxxx`）？库顺序对不对（被依赖的放后面）？`extern "C"` 是否遗漏导致 mangling 不匹配？
2. **`multiple definition`（链接期）**：违反 ODR，通常是头文件里放了非 inline 的函数/变量定义，被多个 `.cpp` 包含。
   - 改：定义移到唯一 `.cpp`，头文件只留声明；或加 `inline`。
3. **链接成功但运行崩**：动态库版本/ABI 不匹配（`LD_LIBRARY_PATH` 加载到错误版本）。

> 面试一句话：“C++ 编译分预处理、编译、汇编、链接四步，每个 `.cpp` 是独立编译单元，互相只看得到声明，靠链接期连符号。ODR 要求定义唯一，但 inline 函数、模板、类定义允许多单元各放一份——这也是它们要放头文件的原因。静态库链接期拷进程序，动态库运行期共享加载。`undefined reference` 多半是缺定义或没链上库，`multiple definition` 多半是头文件里放了非 inline 定义。”
