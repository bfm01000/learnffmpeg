## 面试速记

- **模板是编译期的“代码生成器”**：编译器按用到的类型**实例化**出具体代码，是**零运行期开销**的抽象（不像虚函数有查表开销）。
- **特化 vs 偏特化**：全特化是给某个**具体类型**定制；偏特化是给**一类类型**（如所有指针 `T*`）定制。**函数模板不能偏特化**，只能全特化或用重载替代。
- **SFINAE**：替换失败不是错误——模板推导时若某个候选的类型替换非法，编译器只是把它从重载集里剔除，不报错。是 C++11/14 时代做“编译期条件选择”的主力，C++20 被 concept 取代。
- **变参模板** `template<typename... Args>`：实现 `make_unique`、`emplace`、`tuple`、日志等的基础。
- **CRTP**（奇异递归模板）：`class Derived : Base<Derived>`，用模板实现**静态多态**，零虚表开销。
- **`type_traits`**：编译期类型查询/变换（`is_integral`、`remove_reference`、`enable_if`…）。

## 一、函数模板与类模板

```cpp
// 函数模板：编译器按调用处的实参类型推导 T
template <typename T>
const T& maxValue(const T& left, const T& right) {
    return left > right ? left : right;
}
maxValue(3, 5);        // T = int
maxValue(2.0, 1.0);    // T = double

// 类模板：用到时显式或推导出模板参数
template <typename T>
class RingBuffer {
    T* data_;
    size_t capacity_;
public:
    explicit RingBuffer(size_t capacity);
    void push(const T& value);
};
RingBuffer<float> audioBuffer(1024);   // T = float
```

- **实例化时机**：模板本身不生成代码，只有**被用到**的特定类型组合才会实例化出真实代码（这也是模板定义通常必须放头文件的原因，和 inline 同理，见 [13-语言基础关键字](13-语言基础关键字.md)）。
- **CTAD（C++17 类模板参数推导）**：`std::vector v{1,2,3};` 可省略 `<int>`。

## 二、模板特化与偏特化

### 1. 全特化：给某个具体类型定制

```cpp
template <typename T>
struct Serializer { static std::string run(const T&) { return "generic"; } };

// 针对 bool 的全特化
template <>
struct Serializer<bool> { static std::string run(const bool& b) { return b ? "true" : "false"; } };
```

### 2. 偏特化：给“一类类型”定制（只有类模板能偏特化）

```cpp
// 主模板
template <typename T>
struct IsPointer { static constexpr bool value = false; };

// 偏特化：所有指针类型 T*
template <typename T>
struct IsPointer<T*> { static constexpr bool value = true; };

IsPointer<int>::value;    // false
IsPointer<int*>::value;   // true
```

> **函数模板不能偏特化**。需要“类似偏特化”的效果时，用**函数重载**或把逻辑放进可偏特化的类模板里。

## 三、变参模板（Variadic Templates）

用 `typename... Args` 接收任意多个类型，配合**包展开** `args...` 和完美转发：

```cpp
template <typename T, typename... Args>
std::unique_ptr<T> makeUnique(Args&&... args) {        // 万能引用 + 变参
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...)); // 完美转发每个参数
}

// C++17 折叠表达式：把一组参数用某运算符“折叠”
template <typename... Args>
auto sum(Args... values) { return (values + ...); }   // (a + (b + (c + ...)))
sum(1, 2, 3, 4);   // 10
```

变参模板是 `std::tuple`、`std::make_shared`、`emplace_back`、类型安全 `printf` 的实现基础。

## 四、SFINAE 与 enable_if（编译期条件选择）

**SFINAE（Substitution Failure Is Not An Error）**：模板推导时，若把推导出的类型代入候选签名导致**非法类型**，编译器不报错，只是把该候选从重载集中**悄悄剔除**。利用这一点可以按类型属性“启用/禁用”某个重载。

```cpp
#include <type_traits>

// 只对整数类型启用
template <typename T,
          typename = std::enable_if_t<std::is_integral_v<T>>>
void process(T value) { /* 整数版本 */ }

// 只对浮点类型启用
template <typename T,
          typename = std::enable_if_t<std::is_floating_point_v<T>>>
void process(T value) { /* 浮点版本，与上面构成不冲突的重载 */ }
```

- **现代替代**：C++17 用 `if constexpr` 把分支写在一个函数里更清爽；C++20 用 **concept** 直接约束，可读性最好（见 [17-C++20与协程](17-C++20与协程.md)）。

```cpp
template <typename T>
void process(T value) {
    if constexpr (std::is_integral_v<T>) { /* 整数分支 */ }
    else                                 { /* 其它分支，编译期裁剪掉不走的分支 */ }
}
```

## 五、type_traits：编译期类型工具箱

`<type_traits>` 提供编译期的**类型查询**与**类型变换**：

```cpp
std::is_integral_v<int>;            // true
std::is_pointer_v<int*>;            // true
std::is_same_v<int, int32_t>;       // 平台相关
std::remove_reference_t<int&>;      // int
std::decay_t<const int&>;           // int（去引用、去 const、数组退化为指针）
std::conditional_t<cond, A, B>;     // 按 cond 选类型
```

它们是写泛型库的基础，也是 `std::forward`/`std::move` 内部实现的依赖。

## 六、CRTP：用模板实现静态多态（零开销）

**CRTP（Curiously Recurring Template Pattern）**：派生类把**自己**作为模板参数传给基类，基类就能在编译期调到派生类的实现——实现多态却**没有虚表、可内联**。

```cpp
template <typename Derived>
class Shape {
public:
    double area() const {
        // 编译期向下转换到真实子类，静态绑定、可内联
        return static_cast<const Derived*>(this)->areaImpl();
    }
};

class Circle : public Shape<Circle> {
    double radius_;
public:
    explicit Circle(double r) : radius_(r) {}
    double areaImpl() const { return 3.14159 * radius_ * radius_; } // 给基类调
};
```

**CRTP vs 虚函数**：

| | 虚函数多态 | CRTP 静态多态 |
| :--- | :--- | :--- |
| 绑定时机 | 运行期查 vtable | 编译期 |
| 开销 | 间接寻址、难内联 | 零开销、可内联 |
| 灵活性 | 可存异质容器、运行期决定类型 | 类型编译期固定 |
| 场景 | 真正的运行期多态 | 已知类型、极致性能（音视频热路径、数学库） |

> 音视频热路径里，若类型在编译期已知（如固定的像素格式转换器），用 CRTP 或模板比虚函数更快。

## 七、常见坑与面试加分

- **模板代码膨胀**：每种类型实例化一份代码，过度模板化会让二进制变大、拖慢编译。
- **报错冗长**：模板错误信息深而长，C++20 concept 能大幅改善（约束不满足时直接给出可读原因）。
- **定义必须可见**：模板的定义要放头文件，否则其它编译单元实例化时找不到实现（同 inline 的 ODR 道理，见 [13-语言基础关键字](13-语言基础关键字.md)）。
- **`typename` / `template` 消歧**：依赖类型里取嵌套类型要加 `typename`（`typename T::value_type`）。

> 面试一句话：“模板是编译期的代码生成器，给我们零开销的泛型抽象。全特化定制具体类型、偏特化定制一类类型（函数模板只能全特化）；变参模板 + 完美转发是 `make_unique`/`emplace` 的基础；SFINAE/`enable_if` 做编译期条件选择，C++20 用 concept 取代它更清晰；需要多态又不想要虚表开销时用 CRTP 做静态多态。”
