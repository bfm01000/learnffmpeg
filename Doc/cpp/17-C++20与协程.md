# C++20 核心特性与协程

> 越来越多高级岗会问 C++20。本篇覆盖 concepts、ranges、`std::jthread`、`std::span` 等高频特性，并重点讲**协程（coroutine）**——它对音视频的异步流水线、拉流/解码任务调度尤其相关。
>
> 相关：concept 取代的 SFINAE 见 [[14-模板与泛型编程]]；`jthread` 与线程见 [[01-多线程与锁]]；协程与无锁队列配合见 [[03-无锁队列]]。

---

## 📌 面试速记

- **concepts**：给模板参数加**可读的约束**，取代晦涩的 SFINAE/`enable_if`，约束不满足时报错清晰。
- **ranges**：可组合的算法管道（`views::filter | views::transform`），惰性求值、不产生中间容器。
- **`std::jthread`**：自动 `join` 的线程（析构即 join）+ 内置**协作式取消**（`stop_token`），比 `std::thread` 更安全。
- **`std::span`**：对连续内存的**非拥有视图**（指针 + 长度），传数组/缓冲不丢长度、不拷贝——音视频处理裸缓冲很顺手。
- **协程**：能**暂停/恢复**的函数，用 `co_await`/`co_yield`/`co_return`。把“回调地狱”的异步代码写成顺序风格；无栈协程，开销低。

## 一、concepts：给模板加约束

C++20 之前用 SFINAE/`enable_if` 限制模板类型（见 [[14-模板与泛型编程]]），既难写又报错冗长。concept 让约束**显式、可读**：

```cpp
#include <concepts>

template <typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

template <Numeric T>                       // 只接受数值类型
T addUp(T left, T right) { return left + right; }

addUp(1, 2);        // ✅
// addUp("a", "b"); // ❌ 编译期直接报错：约束 Numeric 不满足，信息清晰
```

也可用 `requires` 子句表达更复杂的约束（要求某表达式合法）：

```cpp
template <typename T>
concept Drawable = requires(T obj) {
    obj.draw();                  // 要求 T 有 draw() 成员
    { obj.area() } -> std::convertible_to<double>; // 且 area() 返回可转 double
};
```

## 二、ranges：可组合的惰性算法管道

```cpp
#include <ranges>
#include <vector>

std::vector<int> nums{1, 2, 3, 4, 5, 6};

// 取偶数 → 各自平方，惰性求值，不生成中间容器
auto pipeline = nums
    | std::views::filter([](int n) { return n % 2 == 0; })
    | std::views::transform([](int n) { return n * n; });

for (int value : pipeline) { /* 4, 16, 36 */ }
```

- **优点**：声明式、可组合、惰性（用到才算），避免传统 `<algorithm>` 写一堆临时容器。
- `ranges::sort(vec)` 这类**直接接收容器**的版本也比传 `begin/end` 更简洁。

## 三、并发与内存：jthread / span / 其它

### std::jthread —— 更安全的线程

```cpp
#include <thread>
void worker(std::stop_token token) {
    while (!token.stop_requested()) { /* 协作式检查取消 */ }
}
int main() {
    std::jthread t(worker);   // 析构时自动 request_stop() + join()，不会像 std::thread 那样忘 join 就 terminate
}                             // 离开作用域：自动请求停止并汇合
```

相比 `std::thread`（忘记 `join`/`detach` 会在析构时 `terminate`），`jthread` 析构自动 join，并内置 `stop_token` 协作取消机制（见 [[01-多线程与锁]]）。

### std::span —— 非拥有的连续内存视图

```cpp
#include <span>
// 不再退化成裸指针、不丢长度；不拷贝
void applyGain(std::span<int16_t> samples, float gain) {
    for (auto& sample : samples) sample = static_cast<int16_t>(sample * gain);
}
std::vector<int16_t> pcm(1024);
applyGain(pcm, 0.5f);                       // 传 vector
applyGain({rawPtr, frameCount}, 0.5f);      // 传裸缓冲 + 长度
```

音视频里处理 PCM/像素裸缓冲非常合适——既安全（带长度）又零拷贝（见 [[11-类型转换]] 的裸字节流处理）。

### 其它常用

- `consteval`：强制编译期求值的函数；`constinit`：保证静态变量编译期初始化。
- 指定初始化：`Config c{.bitrate = 8000, .fps = 30};`。
- `<bit>`：`std::bit_cast`、`std::endian`（字节序，音视频协议解析有用）。

## 四、协程（Coroutine）—— 重点

### 1. 是什么

协程是**可以在中途暂停、稍后从暂停点恢复**的函数。C++20 用三个关键字驱动，函数体里出现任一个，它就是协程：

- `co_await expr`：暂停协程，等 `expr` 就绪后恢复。
- `co_yield value`：产出一个值并暂停（生成器）。
- `co_return value`：结束协程并返回。

C++20 的协程是**无栈协程**：不为每个协程保留独立调用栈，只把必要状态存进一个堆上的“协程帧”，**挂起/恢复开销很低**。

### 2. 解决什么问题：异步代码顺序化

传统异步靠回调嵌套（回调地狱），协程能把它写成**看起来同步**的顺序代码：

```cpp
// 伪代码示意：拉流 → 解码 → 渲染 的异步流程，用协程写成顺序风格
Task<void> playStream(Url url) {
    auto packet = co_await readPacket(url);   // 暂停，等 IO，不阻塞线程
    auto frame  = co_await decode(packet);    // 暂停，等解码
    co_await render(frame);                    // 暂停，等渲染
    // 没有层层回调，控制流清晰
}
```

线程在 `co_await` 处不被阻塞，可以去干别的活，等结果就绪再恢复——非常契合音视频的 IO 密集 + 多阶段流水线。

### 3. 机制（面试讲到这一层即可）

- 协程返回类型需满足“**promise_type** 协议”：编译器把协程体改写成状态机，`promise_type` 控制返回值、挂起点行为、异常处理。
- `awaiter`（被 `co_await` 的对象）实现 `await_ready / await_suspend / await_resume` 三个方法，决定“是否真的挂起、挂起时做什么、恢复时返回什么”。
- 标准库目前只给了**底层设施**（`std::coroutine_handle`、`std::suspend_always` 等），`Task`/`Generator` 等高层类型要自己写或用第三方库（如 cppcoro、folly::coro、Asio 的协程支持）。

### 4. 生成器示例（co_yield）

```cpp
Generator<int> fibonacci() {           // Generator 为自定义协程返回类型
    int a = 0, b = 1;
    while (true) {
        co_yield a;                    // 产出一个值后暂停
        auto next = a + b; a = b; b = next;
    }
}
// for (int v : fibonacci()) { ... }   // 惰性按需产出
```

> 协程帧通常在堆上分配（编译器可能优化掉）；在极热路径要留意分配开销与帧大小。

## 五、面试总结

> “C++20 我重点关注几块：**concept** 让模板约束可读、取代 SFINAE；**ranges** 提供可组合的惰性算法管道；**`jthread`** 自动 join 还带协作取消；**`span`** 是带长度的非拥有内存视图，处理音视频裸缓冲很合适。最重要的是**协程**——无栈、低开销，能把异步的拉流/解码/渲染流水线用 `co_await` 写成顺序代码，避免回调地狱；它的机制是编译器把协程体改写成状态机，靠 `promise_type` 和 `awaiter` 协议驱动挂起恢复。标准库只给底层设施，高层 `Task`/`Generator` 一般用第三方库。”
