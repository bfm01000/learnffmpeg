### S1. 虚函数怎么实现多态？vtable / vptr 讲一下 —— [[08-继承、多态、虚函数与对象模型]]

<details><summary>▶ 标准回答</summary>

> “虚函数靠**虚函数表 vtable + 虚表指针 vptr** 实现动态绑定。编译器给每个有虚函数的**类**生成一张 vtable，是函数指针数组，存着该类各虚函数的真实地址，放在只读数据段，**编译期**就建好。每个**对象**内存最前面有个隐藏的 vptr，指向所属类的 vtable，由**构造函数**初始化。调用 `p->func()` 时：取对象里的 vptr → 找到 vtable → 按 func 的固定偏移取出真实地址 → 跳转。所以多态的代价就是一次间接寻址，也因此虚函数一般难以内联。非虚函数没有表，地址编译期就定死，直接 call。”

**追问**：为什么基类析构要 virtual？→ 否则 `delete 基类指针` 只静态绑定调基类析构，子类析构不执行，资源泄漏。
</details>

### S2. 三种智能指针的区别？循环引用怎么解决？ —— [[06-智能指针与资源管理]]

<details><summary>▶ 标准回答</summary>

> “`unique_ptr` 独占所有权、不可拷贝只可移动，零开销，是默认首选；`shared_ptr` 共享所有权，靠**原子引用计数**管理生命周期，计数归零才释放；`weak_ptr` 是不增加计数的弱观察者，用来打破循环引用，用前 `lock()` 提升成 `shared_ptr` 看对象是否还在。
>
> **循环引用**：两个对象用 `shared_ptr` 互相持有，计数永远不归零，内存泄漏。解决办法是把其中一方（如父→子是强引用，子→父）改成 `weak_ptr`。另外优先用 `make_shared`，一次分配把控制块和对象放一起，更快也更安全。”

**追问**：`shared_ptr` 线程安全吗？→ 引用计数本身原子、线程安全；但它**指向的对象**不是，多线程改对象仍要加锁。
</details>

### S3. 什么是移动语义？移动构造为什么要 noexcept？ —— [[07-移动语义与右值引用]]

<details><summary>▶ 标准回答</summary>

> “移动语义是把临时对象（右值）的**资源所有权转移**给新对象，而不是深拷贝。比如一个管理堆内存的对象，移动构造只是把指针接管过来、再把源指针置空，避免重新分配和复制。`std::move` 本身不移动任何东西，只是把左值**转成右值引用**，真正的搬运发生在移动构造/移动赋值里。
>
> **为什么要 noexcept**：`std::vector` 扩容时要把旧元素搬到新内存，只有元素的移动构造标了 `noexcept`，它才敢用移动；否则为了保证扩容的强异常安全（搬一半抛异常无法回滚），会**退回用拷贝**。所以资源类的移动操作一定要 `noexcept`。”
</details>

### S4. mutex / lock_guard / unique_lock / 条件变量 怎么配合？ —— [[01-多线程与锁]]

<details><summary>▶ 标准回答</summary>

> “`mutex` 是锁本体管互斥；`lock_guard`/`unique_lock` 是 RAII 包装，构造加锁、析构解锁，避免手写 lock/unlock 漏解锁。简单作用域用 `lock_guard`；要配条件变量、要中途解锁、要超时就用 `unique_lock`；锁多把用 `scoped_lock` 防死锁。
>
> **条件变量**解决‘等某个业务条件成立’：用 `unique_lock` 锁住，`wait(lock, 谓词)` 会**释放锁并睡眠**，被唤醒后重新拿锁再检查谓词。必须带谓词（while 循环）防**虚假唤醒**。修改条件的一方先在锁内改状态再 notify。记住：notify 只是提示，条件真假看 mutex 保护的状态。”
</details>

### S5. atomic 和锁的区别？讲讲内存序 / happens-before —— [[02-原子操作与内存序]]

<details><summary>▶ 标准回答</summary>

> “`atomic` 保证**单个变量**的读-改-写原子，适合停止标记、计数器；多个变量有一致性约束就得用 mutex。多线程正确性要解决原子性、可见性、有序性三件事——atomic 用原子指令解决原子性，用 `memory_order` 解决可见性和有序性。
>
> 最常用的是 **release-acquire 配对**：写线程 `store(release)` 发布，读线程 `load(acquire)` 验收，一旦读到了 release 的值，就建立 **happens-before**——release 之前的所有写入对 acquire 之后都可见。`relaxed` 只保证原子性不保证顺序，适合纯计数；`seq_cst` 是默认、最强、全局单一顺序但最贵。拿不准就用默认的 seq_cst，先正确再优化。”

**追问**：CAS？→ `compare_exchange`，无锁结构核心，注意 ABA 问题。
</details>

### S6. C++ 内存分几个区？new/delete 和 malloc/free 区别？ —— [[05-内存管理与对象生命周期]]

<details><summary>▶ 标准回答</summary>

> “五大区：**栈**（局部变量，编译器自动管，快但小）、**堆**（new/malloc 手动管，大但有碎片）、**全局/静态区**（.data 已初始化 / .bss 未初始化清零）、**常量区 .rodata**（只读）、**代码区 .text**（指令，只读共享）。
>
> `new/delete` 是**运算符**，`new = operator new 分配内存 + 构造函数`，`delete = 析构函数 + operator delete 释放`；类型安全，失败抛 `bad_alloc`。`malloc/free` 只是 C 库函数，只分配/释放裸内存、不调构造析构，失败返回 NULL。所以面向对象必须用 new 才能正确初始化对象。”

**追问**：RAII？→ 把资源绑定到栈对象生命周期，析构自动释放，异常也安全。
</details>

### S7. 三/五/零法则？RVO 是什么？ —— [[15-拷贝消除与三五零法则]]

<details><summary>▶ 标准回答</summary>

> “**三法则**：要手写析构、拷贝构造、拷贝赋值三者之一，通常三个都要写（说明管理了裸资源，否则默认浅拷贝会双重释放）。**五法则**：C++11 加移动后再加移动构造、移动赋值，且移动要 noexcept。**零法则**（现代首选）：成员都用 vector/unique_ptr 这类 RAII 类型，一个特殊函数都不写，编译器生成的全对。
>
> **RVO/NRVO** 是返回值优化：编译器把返回的对象**直接构造在调用方**，省掉拷贝/移动。C++17 起返回纯右值的 RVO 是**强制**的。关键陷阱：别写 `return std::move(local)`，那会**关闭 NRVO** 反而多一次移动，直接 `return local` 就好。”

**追问**：声明了析构会怎样？→ 会抑制移动操作自动生成，对象退化成只能拷贝。
</details>

## 🄰 档 · 高频

### A1. 重写、重载、隐藏的区别？ —— [[08-继承、多态、虚函数与对象模型]]

<details><summary>▶ 标准回答</summary>

> “**重载**是同一作用域内同名不同参，编译期静态决议；**重写**是子类覆盖父类的虚函数，同名同参，运行期动态决议；如果子类和父类同名但没有 virtual、或参数不同，那是**隐藏**——子类作用域屏蔽了父类同名函数，连父类的重载版本一起看不见。一句话：同类同名不同参是重载，子类盖虚函数是重写，没 virtual 却同名是隐藏。写重写一定加 `override` 让编译器查错。”
</details>

### A2. vector 怎么扩容？什么时候迭代器失效？ —— [[12-STL容器底层]]

<details><summary>▶ 标准回答</summary>

> “vector 是连续数组，`push_back` 满了就扩容：申请更大内存（gcc 2 倍、MSVC 1.5 倍）、把旧元素搬过去、释放旧内存。所以单次最坏 O(n)，但倍增让 n 次插入**均摊 O(1)**。**扩容会让所有迭代器、指针、引用失效**；没扩容时尾部 push 只失效 end，中间 erase/insert 失效操作点之后的。已知规模先 `reserve` 避免多次扩容；元素移动构造要 noexcept 才能让扩容走移动。”

**追问**：map vs unordered_map？→ 红黑树有序 O(log n) vs 哈希表无序均摊 O(1)、rehash 失效迭代器。
</details>

### A3. Lambda 的本质是什么？和 std::function 怎么选？ —— [[10-可调用对象-Lambda与std-function]]

<details><summary>▶ 标准回答</summary>

> “Lambda 本质是编译器生成的一个**匿名类**，重载了 `operator()`，捕获的变量就是它的成员变量，默认 `operator()` 是 const、要改捕获值得加 `mutable`。它类型在编译期确定、能内联、零开销。
>
> `std::function` 是**类型擦除**的包装器，底层靠继承+虚函数+可能的堆分配，能统一存各种可调用对象，但有调用开销、无法内联。**黄金法则：能用 auto 接 Lambda 就别用 std::function**，只有要把可调用对象当成员、放容器、做跨边界接口这种需要统一类型时才用 function。延后执行的 Lambda 一律按值或按智能指针捕获，杜绝悬垂引用。”
</details>

### A4. 四种类型转换分别什么场景？为什么不用 C 风格强转？ —— [[11-类型转换]]

<details><summary>▶ 标准回答</summary>

> “`static_cast` 做编译期合理转换——数值互转、void* 还原、上行转换；`dynamic_cast` 做多态类型的安全下行转换，运行期查 RTTI，失败指针返回 nullptr、引用抛 bad_cast；`const_cast` 增删 const（去 const 改真正 const 对象是 UB）；`reinterpret_cast` 做比特层面重新解释，处理裸字节流、指针整数互转。
>
> 不用 C 风格 `(T)x` 是因为它会在这四者里盲目挑一个，意图不明确、可能悄悄退化成危险的 reinterpret，还无法 grep 审查。C++ 拆成四个关键字就是要让意图显式、风险可见。”
</details>

### A5. 什么是异常安全？三种保证？析构能抛异常吗？ —— [[16-异常与异常安全]]

<details><summary>▶ 标准回答</summary>

> “异常安全的核心是 **RAII + 栈展开**：异常抛出后，从抛出点到 catch 之间所有栈对象按逆序自动析构，资源不漏。三种保证：**基本保证**（不泄漏、对象仍有效）、**强保证**（要么成功要么回滚，常用 copy-and-swap 实现）、**不抛保证**（noexcept）。
>
> **析构函数绝不能抛异常**：如果异常正在栈展开期间析构再抛第二个异常，运行时无法处理两个异常会直接 `terminate`。所以析构默认 noexcept，里面可能失败的操作要就地 try-catch 吞掉。性能热路径（逐帧解码）我倾向用返回值/错误码而非异常。”
</details>

### A6. 模板特化和偏特化？SFINAE 是什么？ —— [[14-模板与泛型编程]]

<details><summary>▶ 标准回答</summary>

> “模板是编译期代码生成器，给零开销的泛型抽象。**全特化**给某个具体类型定制，**偏特化**给一类类型（比如所有指针 `T*`）定制——注意**函数模板不能偏特化**，只能全特化或用重载。
>
> **SFINAE**（替换失败不是错误）：模板推导时如果把类型代入某个候选导致非法类型，编译器不报错，只是把它从重载集剔除，借此做编译期条件选择，常配 `enable_if`。C++17 用 `if constexpr` 更清爽，C++20 用 **concept** 直接约束、报错可读，已基本取代 SFINAE。需要多态又不想要虚表开销时用 **CRTP** 做静态多态。”
</details>

### A7. volatile 能用于多线程同步吗？ —— [[13-语言基础关键字]]

<details><summary>▶ 标准回答</summary>

> “不能。C++ 的 `volatile` 只是告诉编译器‘这个变量每次访问都要真读真写、不要优化掉’，典型场景是硬件寄存器、内存映射 I/O。它**不保证原子性**（`volatile int++` 多线程仍丢更新），也**不提供 happens-before**。很多人和 Java 的 volatile 搞混了——Java 那个能保证可见性，C++ 这个不行。多线程同步该用 `std::atomic` 或 `mutex`。双重检查锁定也不能用 volatile 指针，要用 atomic + 内存序，或直接用函数内静态局部变量（C++11 保证线程安全初始化）。”
</details>

### A8. inline 的作用？加了 inline 就一定内联吗？和宏的区别？ —— [[13-语言基础关键字]]

<details><summary>▶ 标准回答</summary>

> “`inline` 建议编译器在调用点把函数体展开，省掉调用开销，是空间换时间。但它只是**建议不是命令**——函数体大、有复杂循环或递归时编译器会忽略它。和宏相比：宏是预处理纯文本替换、不检查类型、参数可能多次求值（`MAX(i++,j++)` 会出错）、无作用域；inline 是真正的函数，类型安全、参数只求值一次、遵守作用域，是用来取代宏函数的。另外它的定义要放头文件（ODR + 各编译单元都要看到才能展开）。”
</details>

## 🄱 档 · 高级 / 加分

### B1. C++20 协程是什么？解决什么问题？ —— [[17-C++20与协程]]

<details><summary>▶ 标准回答</summary>

> “协程是能在中途**暂停、稍后从暂停点恢复**的函数，用 `co_await`/`co_yield`/`co_return` 驱动。C++20 是无栈协程，状态存在堆上的协程帧里，挂起恢复开销低。它最大的价值是把异步代码写成**顺序风格**——比如拉流→解码→渲染，每步 `co_await` 等结果，线程不阻塞可以去干别的，避免回调地狱。机制上编译器把协程体改写成状态机，靠 `promise_type` 和 `awaiter`（await_ready/suspend/resume）协议工作。标准库只给底层设施，高层 Task/Generator 一般用第三方库。”
</details>

### B2. CRTP 是什么？和虚函数比有什么优势？ —— [[14-模板与泛型编程]]

<details><summary>▶ 标准回答</summary>

> “CRTP 是奇异递归模板模式：派生类把自己作为模板参数传给基类 `class Derived : Base<Derived>`，基类就能在编译期 `static_cast` 到真实子类调用其实现，实现**静态多态**。和虚函数比：虚函数运行期查表、难内联、能存异质容器、运行期才定类型；CRTP 编译期绑定、**零开销可内联**，但类型编译期固定。所以音视频热路径里类型已知时（如固定像素格式转换），用 CRTP 比虚函数更快。”
</details>

### B3. const 和 constexpr 区别？consteval / constinit？ —— [[20-const正确性与编译期计算]]

<details><summary>▶ 标准回答</summary>

> “`const` 是运行期只读；`constexpr` 更强，是**编译期可求值**，能用于数组大小、模板参数、case 标签这些需要编译期常量的地方。所有 constexpr 都是 const，反之不然。C++14 起 constexpr 函数能写循环，可以编译期生成查找表。C++20 的 `consteval` 强制必须编译期求值（杜绝意外运行期调用），`constinit` 保证变量编译期完成初始化，规避静态初始化顺序问题。另外 const 成员函数表示不改对象逻辑状态、能被 const 对象调用，`mutable` 给互斥量、缓存这类成员开后门。”
</details>

### B4. undefined reference 和 multiple definition 怎么排查？ —— [[18-编译链接与构建]]

<details><summary>▶ 标准回答</summary>

> “`undefined reference` 是链接期找不到定义：可能函数只声明没实现、或定义所在的库没参与链接（漏了 `-lxxx`、库顺序不对）、或 `extern \"C\"` 漏了导致 name mangling 对不上。`multiple definition` 是违反 ODR，通常是头文件里放了非 inline 的函数/变量定义被多个 cpp 包含——把定义移到唯一的 cpp、头文件只留声明，或加 inline。根因是每个 cpp 是独立编译单元、互相只看得到声明，靠链接期连符号；ODR 要求定义唯一，但 inline/模板/类定义允许多单元各一份。”
</details>
