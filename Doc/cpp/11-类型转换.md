# C++ 类型转换：四件套与 RTTI

> 面试高频：“C++ 有几种类型转换？分别什么场景？为什么不推荐 C 风格强转？”本篇系统对比 `static_cast` / `dynamic_cast` / `const_cast` / `reinterpret_cast`，并讲音视频里处理裸字节流的实战。
>
> 相关：`dynamic_cast` 依赖的虚表与 RTTI 见 [[08-继承、多态、虚函数与对象模型]]；对象内存布局见 [[05-内存管理与对象生命周期]]。

---

## 📌 面试速记

| 转换 | 用途 | 检查时机 | 典型场景 |
| :--- | :--- | :--- | :--- |
| `static_cast` | 编译期“合理”转换 | 编译期 | 数值类型互转、`void*` 还原、上行转换、显式调用单参构造 |
| `dynamic_cast` | 多态类型的安全下行转换 | **运行期**（查 RTTI） | 基类指针/引用转子类，失败返回 `nullptr`/抛异常 |
| `const_cast` | 增删 `const`/`volatile` | 编译期 | 去掉 const 调用老 C API；**改实际 const 对象是 UB** |
| `reinterpret_cast` | 比特层面重新解释 | 编译期（不做任何检查） | 指针↔整数、裸字节流解析、与硬件/协议打交道 |

一句话：**优先 `static_cast`；要安全下行用 `dynamic_cast`；不得已去 const 用 `const_cast`；玩比特用 `reinterpret_cast`。绝不用 C 风格 `(T)x`——它会在四者里盲目挑一个，隐藏风险。**

---

## 一、static_cast：最常用的“合理”转换

编译期完成，做基本的类型相容性检查（比 C 强转安全）。

```cpp
double ratio = 3.14;
int truncated = static_cast<int>(ratio);          // 数值转换，截断为 3

void* raw = operator new(16);
int* typed = static_cast<int*>(raw);              // void* 还原为具体类型

class Base {}; class Derived : public Base {};
Derived d;
Base* base = static_cast<Base*>(&d);              // 上行转换（安全，子类一定是基类）
Derived* back = static_cast<Derived*>(base);      // 下行转换：编译通过，但不做运行期检查！
```

**关键警告**：`static_cast` 做**下行转换**（基类→子类）时**不检查** `base` 是否真的指向 `Derived`。若指向的其实是别的子类，后续访问就是未定义行为。需要安全检查时用 `dynamic_cast`。

---

## 二、dynamic_cast：多态类型的安全下行转换

运行期借助 **RTTI（Run-Time Type Information）** 检查真实类型，**要求类至少有一个虚函数**（即有虚表，见 [[08-继承、多态、虚函数与对象模型]]）。

```cpp
class Codec { public: virtual ~Codec() = default; };
class H264Codec : public Codec { public: void specific(); };
class AACCodec  : public Codec {};

void handle(Codec* codec) {
    // 指针版：失败返回 nullptr
    if (auto* h264 = dynamic_cast<H264Codec*>(codec)) {
        h264->specific();          // 确实是 H264Codec 才进来
    }
    // 引用版：失败抛 std::bad_cast（引用无法表示“空”）
    try {
        H264Codec& ref = dynamic_cast<H264Codec&>(*codec);
    } catch (const std::bad_cast&) { /* 不是 H264Codec */ }
}
```

- **代价**：运行期查 RTTI 有开销，热路径慎用。
- **设计味道**：满地 `dynamic_cast` 往往说明该用虚函数多态替代手动类型判断。面试可提：“能用虚函数表达的行为差异，就不要用 dynamic_cast 做类型分支。”

---

## 三、const_cast：增删 const / volatile

唯一能去掉（或加上）`const`/`volatile` 限定的转换。

```cpp
void legacyApi(char* buffer);          // 老 C API 没写 const，但其实只读

void wrapper(const std::string& text) {
    legacyApi(const_cast<char*>(text.data())); // 已知 API 不会改，去 const 适配
}
```

**致命红线**：用 `const_cast` 去掉 const 后**真的去修改一个本来就是 const 的对象**，是**未定义行为**（该对象可能被编译器放进只读段）。`const_cast` 只应用于“对象本身非 const，只是手上的引用/指针带了 const”这种情形。

---

## 四、reinterpret_cast：比特层面重新解释

不做任何转换计算，只是“把这块内存按另一种类型看待”。最危险、也最贴近底层。

```cpp
std::uintptr_t address = reinterpret_cast<std::uintptr_t>(ptr); // 指针↔整数
auto* regs = reinterpret_cast<volatile uint32_t*>(0x40001000);  // 映射硬件寄存器
```

- 不能用它在无继承关系的类型间安全转换并访问（违反严格别名规则，可能 UB）。
- 跨平台时要小心字节序、对齐（见 [[05-内存管理与对象生命周期]]）。

## 五、音视频实战：裸字节流的解析

音视频里经常拿到 `uint8_t*` 裸缓冲（解封装后的码流、网络收到的 RTP 包、PCM 音频帧），需要按结构解释：

```cpp
// 解析一个自定义包头（注意：生产代码要处理对齐与字节序）
struct PacketHeader { uint32_t magic; uint32_t payloadSize; uint16_t codecId; };

void parse(const uint8_t* data, size_t length) {
    // 用 reinterpret_cast 把字节流头部当作结构体读取
    const auto* header = reinterpret_cast<const PacketHeader*>(data);
    uint32_t payloadSize = header->payloadSize; // 大端协议需再做字节序转换
    const uint8_t* payload = data + sizeof(PacketHeader);
    // ... 处理 payload
}

// 把 16-bit PCM 样本缓冲按 int16_t 解释做音量处理
void applyGain(uint8_t* pcm, size_t bytes, float gain) {
    auto* samples = reinterpret_cast<int16_t*>(pcm); // 假定缓冲对齐到 2 字节
    size_t sampleCount = bytes / sizeof(int16_t);
    for (size_t sampleIndex = 0; sampleIndex < sampleCount; ++sampleIndex) {
        samples[sampleIndex] = static_cast<int16_t>(samples[sampleIndex] * gain);
    }
}
```

实战注意点：

1. **对齐**：把 `uint8_t*` 直接 `reinterpret_cast` 成 `PacketHeader*` 要求缓冲满足该结构对齐；不确定时改用 `memcpy` 逐字段拷出来，既安全又规避严格别名问题。
2. **字节序**：网络/容器协议多为大端，读出后按需 `ntohl` / 手动翻转。
3. **生命周期**：解析出的指针指向原缓冲，缓冲释放后即悬垂。

## 六、为什么不用 C 风格强转 `(T)x`？

C 风格强转会**按顺序尝试** `const_cast` / `static_cast` / `reinterpret_cast` 的组合，编译器替你“盲选”：

- 意图不明确：读代码的人看不出你想做安全数值转换还是危险的比特重解释。
- 隐藏风险：可能在你以为是 `static_cast` 时，悄悄退化成 `reinterpret_cast`。
- 不可搜索：四个 C++ 转换关键字可被 grep 审查，`(T)x` 散落各处难审计。

> 面试一句话：“C++ 把转换拆成四个关键字，就是要让**意图显式、风险可见、可被检索审查**。`static_cast` 管合理转换，`dynamic_cast` 管多态安全下行，`const_cast` 管 const 限定，`reinterpret_cast` 管比特重解释；C 风格强转把这些混在一起，所以现代 C++ 一律不用。”
