# C++ 拷贝消除（RVO/NRVO）与三/五/零法则

## 0. 本篇定位

- 面试复习：先掌握 RVO/NRVO、不要 `return std::move(local)`、Rule of Three/Five/Zero 和特殊成员函数生成规则。

- 音视频落点：封装大帧 buffer 或 FFmpeg 句柄时，首选 Rule of Zero；需要独占资源时再显式定义移动、禁止拷贝。

## 面试速记

- **特殊成员函数**有 6 个：默认构造、析构、拷贝构造、拷贝赋值、移动构造、移动赋值。
- **三法则**：若你需要手写**析构/拷贝构造/拷贝赋值**三者之一，通常三者都要写（说明类管理了裸资源）。
- **五法则**：C++11 加入移动语义后，扩成五个——再加**移动构造/移动赋值**。
- **零法则**（首选）：让成员都是 RAII 类型（`vector`/`string`/`unique_ptr`/`shared_ptr`），**一个都别手写**，全靠编译器默认生成。这是现代 C++ 最推荐的写法。
- **RVO/NRVO**：编译器把“返回临时对象”这件事**直接在调用方就地构造**，省掉拷贝/移动。C++17 起（返回纯右值）RVO 是**强制**的——连移动都不会发生。
- **`return std::move(local)` 是反优化**：会**关闭 NRVO**，多此一举，别写。

## 一、拷贝消除：RVO 与 NRVO

“拷贝消除（Copy Elision）”指编译器**省略本应发生的拷贝/移动构造**，让对象**直接构造在最终位置**。

```cpp
struct Heavy {
    Heavy()             { std::cout << "ctor\n"; }
    Heavy(const Heavy&) { std::cout << "copy\n"; }
    Heavy(Heavy&&)      { std::cout << "move\n"; }
    ~Heavy()            { std::cout << "dtor\n"; }
};

Heavy makeRvo()  { return Heavy{}; }      // RVO：返回纯右值
Heavy makeNrvo() { Heavy local; return local; } // NRVO：返回具名局部变量

int main() {
    Heavy a = makeRvo();   // 仅打印 ctor / dtor —— 没有 copy / move
    Heavy b = makeNrvo();  // 通常也只 ctor / dtor（NRVO）
}
```

- **RVO（Return Value Optimization）**：返回的是**临时对象（纯右值）**。C++17 起这是**语言强制保证**的——标准规定纯右值不再产生临时对象，直接初始化目标，**哪怕拷贝/移动构造被 `delete` 也合法**。
- **NRVO（Named RVO）**：返回的是**具名局部变量**。C++17 也**不强制**，是编译器“可以但不保证”的优化（绝大多数编译器在 `-O1` 以上都会做）。

### 关键反模式：别写 `return std::move(local)`

```cpp
Heavy bad() { Heavy local; return std::move(local); } // ❌ 反优化
```

`std::move` 把返回表达式变成右值引用，**使 NRVO 失效**，编译器只能退而求其次做一次移动构造——你本想优化，结果反而多了一次移动。**直接 `return local;`** 即可：能 NRVO 就零开销，不能也会自动当右值触发移动。

## 二、三法则（Rule of Three）

C++98 时代：如果一个类需要自定义**析构函数**，往往是因为它**管理了裸资源**（裸指针、文件句柄、socket）。那么编译器默认生成的**拷贝构造/拷贝赋值**只会做“浅拷贝”（逐成员复制指针值），导致两个对象指向同一资源、**双重释放**。所以这三个要么都不写，要么都写：

```cpp
class Buffer {
    int* data_;
    size_t size_;
public:
    explicit Buffer(size_t n) : data_(new int[n]), size_(n) {}
    ~Buffer() { delete[] data_; }                         // ① 析构

    Buffer(const Buffer& other)                            // ② 拷贝构造（深拷贝）
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }
    Buffer& operator=(const Buffer& other) {               // ③ 拷贝赋值（深拷贝 + 自赋值保护）
        if (this != &other) {
            int* fresh = new int[other.size_];             // 先分配，分配失败也不破坏 this（强异常安全）
            std::copy(other.data_, other.data_ + other.size_, fresh);
            delete[] data_;
            data_ = fresh; size_ = other.size_;
        }
        return *this;
    }
};
```

> 拷贝赋值用 **copy-and-swap** 惯用法可以更优雅地同时获得自赋值安全和强异常安全，见 [16-异常与异常安全](16-异常与异常安全.md)。

## 三、五法则（Rule of Five）

C++11 引入移动语义后，资源管理类还应提供**移动构造**和**移动赋值**，避免在移动场景退化成深拷贝：

```cpp
    Buffer(Buffer&& other) noexcept                        // ④ 移动构造
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr; other.size_ = 0;            // 置空源，防双重释放
    }
    Buffer& operator=(Buffer&& other) noexcept {           // ⑤ 移动赋值
        if (this != &other) {
            delete[] data_;
            data_ = other.data_; size_ = other.size_;
            other.data_ = nullptr; other.size_ = 0;
        }
        return *this;
    }
```

- **移动操作要写 `noexcept`**：否则 `vector` 扩容等场景为异常安全会退回拷贝（见 [07-移动语义与右值引用](07-移动语义与右值引用.md) / [12-STL容器底层](12-STL容器底层.md)）。

### 编译器自动生成的微妙规则（高频追问）

- 一旦你**声明了**任何拷贝操作、移动操作或析构函数，编译器对**移动操作的自动生成会被抑制**。
- 例如：只写了析构函数 → 移动构造/移动赋值**不会**自动生成，对象就只能拷贝（性能隐患）。
- 所以“五法则”的实践是：**要么五个都不碰（零法则），要么需要哪个就把相关的都显式 `= default` 或手写清楚**，避免“写了一个就悄悄禁用了另一个”的陷阱。

```cpp
class Widget {
public:
    ~Widget();                       // 一旦声明析构……
    Widget(Widget&&) = default;      // ……移动操作就需要显式 = default 找回来
    Widget& operator=(Widget&&) = default;
    Widget(const Widget&) = default;
    Widget& operator=(const Widget&) = default;
};
```

## 四、零法则（Rule of Zero）—— 现代首选

**最佳实践：不要自己管理裸资源。** 让每个成员都是已经正确实现了拷贝/移动/析构的 RAII 类型，那么你的类**一个特殊成员函数都不用写**，编译器生成的全部正确：

```cpp
class Decoder {
    std::vector<uint8_t> buffer_;          // 自带深拷贝 + 移动
    std::unique_ptr<AVCodecContext, CtxDeleter> ctx_; // 自带移动、禁拷贝
    std::string name_;
public:
    // 不写析构、不写拷贝/移动——编译器全部正确生成
};
```

- 想禁止拷贝？让成员含 `unique_ptr` 即可天然禁拷贝，或显式 `= delete`。
- 这样代码最短、最不易错，也最符合现代 C++ 风格。智能指针见 [06-智能指针与资源管理](06-智能指针与资源管理.md)。

> 面试一句话：“三法则是 C++98 时代——管理裸资源就要同时写析构、拷贝构造、拷贝赋值；C++11 加移动语义扩成五法则，再加移动构造和移动赋值，且移动要 `noexcept`。但现代 C++ 首选**零法则**：用 `vector`/`unique_ptr` 这类 RAII 成员，一个特殊函数都不写，编译器生成的全对。另外返回值直接 `return local`，靠 RVO/NRVO 零开销，千万别写 `return std::move(local)`，那会关掉 NRVO。”
