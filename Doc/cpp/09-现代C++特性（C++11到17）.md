# C++11 ~ C++17 面试高频新特性

## 0. 本篇定位

- 面试复习：这是 C++11 到 C++17 的总览，不作为每个特性的唯一深讲；先抓 `auto`、lambda、智能指针、线程库、`optional/variant/string_view`。
- 深入学习：遇到移动语义、智能指针、线程、模板等内容，要回到对应专题文档继续深挖。
- 音视频落点：现代特性最终要服务更清晰的所有权、更少的拷贝、更稳定的异步任务和更可维护的模块接口。
## C++11

### 1. `auto` 与 `decltype`

- `auto`：让编译器根据初始化表达式自动推导变量类型。
- `decltype(expr)`：获取表达式的类型，常用于模板和泛型代码。

```cpp
auto x = 10;            // int
auto s = std::string("hello");

int a = 1;
decltype(a) b = 2;      // int
```

**面试追问**：`auto` 会不会保留引用和 const？

一般情况下，`auto` 会丢掉顶层 `const` 和引用：

```cpp
const int x = 10;
auto a = x;      // int，不是 const int

int y = 20;
int& ref = y;
auto b = ref;    // int，不是 int&

auto& c = ref;   // int&
```

---

### 2. `nullptr`

C++11 引入 `nullptr` 替代 `NULL`。

```cpp
void f(int);
void f(char*);

f(NULL);      // 可能调用 f(int)，因为 NULL 本质上可能是 0
f(nullptr);   // 调用 f(char*)
```

**核心价值**：避免空指针和整数 `0` 之间的二义性。

---

### 3. 范围 `for`

```cpp
std::vector<int> nums{1, 2, 3};

for (auto& n : nums) {
    n += 1;
}
```

**注意点**：

- 只读遍历用 `const auto&`，避免拷贝。
- 需要修改元素用 `auto&`。
- 简单值类型可以用 `auto`。

---

### 4. Lambda 表达式

```cpp
int base = 10;
auto add = [base](int x) {
    return x + base;
};
```

常见捕获方式：

```cpp
[=]   // 值捕获外部变量
[&]   // 引用捕获外部变量
[x]   // 值捕获 x
[&x]  // 引用捕获 x
```

**面试追问**：值捕获和引用捕获有什么区别？

- 值捕获：lambda 内部保存一份副本，安全，但默认不能修改副本。
- 引用捕获：不拷贝，能看到外部变量变化，但要注意生命周期，异步场景容易悬空引用。

异步任务中更推荐值捕获必要对象：

```cpp
auto task = [ptr = sharedPtr]() {
    ptr->run();
};
```

> 深入：Lambda 的匿名类本质、`mutable`、与 `std::function` 的选型详见 [10-可调用对象-Lambda与std-function](10-可调用对象-Lambda与std-function.md)。

### 5. 右值引用、移动语义、完美转发

#### 右值引用

```cpp
std::string&& r = std::string("hello");
```

右值引用主要用于接管临时对象资源，避免深拷贝。

#### 移动语义

```cpp
std::vector<int> a{1, 2, 3};
std::vector<int> b = std::move(a);
```

`std::move` 本身不移动，只是把对象强制转换成右值引用，真正移动发生在移动构造或移动赋值里。

#### 完美转发

```cpp
template <typename T>
void wrapper(T&& arg) {
    func(std::forward<T>(arg));
}
```

**核心价值**：保持参数原来的左值/右值属性。

**面试高频总结**：

- `T&&` 在模板中可能是万能引用。
- `std::move` 无条件转右值。
- `std::forward<T>` 有条件转发，保留值类别。

> 深入：移动构造/移动赋值、`noexcept`、万能引用与完美转发详见 [07-移动语义与右值引用](07-移动语义与右值引用.md)。

### 6. 智能指针

#### `std::unique_ptr`

独占所有权，不能拷贝，只能移动。

```cpp
std::unique_ptr<int> p = std::make_unique<int>(10); // C++14
```

#### `std::shared_ptr`

共享所有权，通过引用计数管理生命周期。

```cpp
auto p1 = std::make_shared<int>(10);
auto p2 = p1;
```

#### `std::weak_ptr`

弱引用，不增加引用计数，常用于解决循环引用。

```cpp
std::weak_ptr<int> wp = p1;
if (auto sp = wp.lock()) {
    // 对象仍然存在
}
```

**面试追问**：`shared_ptr` 有什么坑？

- 循环引用导致内存泄漏，需要 `weak_ptr`。
- 不要用同一个裸指针构造多个 `shared_ptr`。
- `shared_ptr` 引用计数线程安全，但被管理对象本身不一定线程安全。

> 深入：`make_shared`、循环引用、`enable_shared_from_this`、自定义 deleter 管理 FFmpeg/C 资源详见 [06-智能指针与资源管理](06-智能指针与资源管理.md)。

### 7. `override`、`final`、`= default`、`= delete`

```cpp
class Base {
public:
    virtual void run();
};

class Derived : public Base {
public:
    void run() override;
};
```

- `override`：显式声明重写基类虚函数，防止签名写错。
- `final`：禁止类被继承或虚函数被继续重写。
- `= default`：要求编译器生成默认函数。
- `= delete`：禁止某个函数被调用。

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
```

#### 编译器默认生成的构造函数（Rule of Three / Five / Zero）

这是面试极高频考点。理解"编译器在什么条件下生成什么"是正确设计类的基础。

**核心问题**：当你写一个类时，不写任何构造/析构/赋值函数，编译器到底帮你生成了什么？

```cpp
class Foo {};  // 看起来是空的，编译器实际上生成了 6 个函数
```

**六大特殊成员函数（Special Member Functions）**：

| # | 函数 | 签名 | 生成条件 |
|---|------|------|----------|
| 1 | **默认构造** | `T()` | 没有**任何**用户声明的构造函数 |
| 2 | **析构** | `~T()` | 没有用户声明的析构函数 |
| 3 | **拷贝构造** | `T(const T&)` | 没有用户声明的移动操作（C++11），且没被 `= delete` |
| 4 | **拷贝赋值** | `T& operator=(const T&)` | 同上 |
| 5 | **移动构造** | `T(T&&)` | 没有用户声明的拷贝/移动/析构 |
| 6 | **移动赋值** | `T& operator=(T&&)` | 同上 |

**条件逐条展开**：

**① 默认构造函数 `T()`**

```cpp
struct A { int x = 0; };     // ✅ 生成 T()，x 初始化为 0
struct B { int x; };          // ✅ 生成 T()，但 x 不被初始化（垃圾值）
struct C { C(int) {} };       // ❌ 不生成 T()——用户声明了其他构造函数
```

一旦声明了**任意**构造函数（哪怕只是 `C(int)`），编译器就**不再生成默认构造函数**。这就是为什么 `C c;` 会编译失败。

**② 析构函数 `~T()`**

```cpp
struct A { };                 // ✅ 生成 ~T()，非虚
struct B : public A { };      // ✅ 如果 A 有虚析构，B 的生成析构也是虚的
struct C { ~C() {} };         // ❌ 不生成——用户已声明
```

编译器生成的析构函数**默认不是 `virtual`**。所以多态基类**必须手写 `virtual ~Base() = default;`**，否则 `delete` 基类指针时子类析构不会被调用（UB + 内存泄漏）。

**③④ 拷贝构造 & 拷贝赋值**

```cpp
struct A { };                 // ✅ 两个都生成，逐成员拷贝
struct B { B(B&&); };         // ❌ 不生成——用户声明了移动构造
struct C { ~C() {} };         // ⚠️ C++11 起已弃用：仍然生成，但不应依赖
```

- 默认行为：**逐成员拷贝**（对内置类型逐字节复制，对类类型调用其拷贝构造/赋值）。
- 一旦声明了移动操作，拷贝操作就被抑制（编译器认为你关心资源管理，不想擅自决定拷贝行为）。
- C++11 之前：声明析构也会抑制拷贝；C++11 起保留生成但标记为 deprecated。

**⑤⑥ 移动构造 & 移动赋值（C++11 新增）**

```cpp
struct A { };                 // ✅ 两个都生成，逐成员移动
struct B { B(const B&); };    // ❌ 不生成——用户声明了拷贝构造
struct C { ~C() {} };         // ❌ 不生成——用户声明了析构函数
```

- 生成条件最苛刻：**不能有任何用户声明的拷贝操作、移动操作、或析构函数**。
- 默认行为：**逐成员移动**（对内置类型逐字节复制——移动对 int/指针无意义；对类类型调用其移动构造/赋值）。
- 如果某个成员不可移动，该移动操作会被隐式 `= delete`。

**一句话判断生成与否**：

```text
编译器给不给，取决于你有没有"碰过"五大件（构造/析构/拷贝/拷贝赋值/移动）中的任何一个。
你碰了一个，编译器就认为你"清楚自己在管理什么"，不再擅自生成。
```

**三大规则（面试背诵）**：

| 规则 | 含义 | 适用年代 |
|------|------|----------|
| **Rule of Three** | 如果你需要自定义**析构 / 拷贝构造 / 拷贝赋值**中的任意一个，通常三者都需要 | C++98/03 |
| **Rule of Five** | Rule of Three + 如果涉及资源所有权，应同时定义**移动构造 / 移动赋值** | C++11+ |
| **Rule of Zero** | 如果类的所有成员都正确管理自己的资源（用 `unique_ptr`/`shared_ptr`/`vector` 而非裸指针），**不要写任何特殊成员函数**——全交给编译器 | C++11+ 最佳实践 |

**Rule of Zero 是工程上的目标状态**：用 RAII 成员替代手写资源管理，让编译器自动生成所有六大函数，代码最安全、最干净。

```cpp
// ❌ Rule of Three / Five: 手写资源管理，必须自己写全套
class Manual {
    int* data;
public:
    Manual() : data(new int[100]) {}
    ~Manual() { delete[] data; }
    Manual(const Manual& o) : data(new int[100]) { std::copy(...); }
    Manual& operator=(const Manual& o) { /* copy + swap */ return *this; }
    Manual(Manual&& o) noexcept : data(std::exchange(o.data, nullptr)) {}
    Manual& operator=(Manual&& o) noexcept { /* swap */ return *this; }
};

// ✅ Rule of Zero: 用 vector 管资源，所有六大函数全交给编译器
class Automatic {
    std::vector<int> data{100};
    // 不需要写任何 special member function
};
```

**易错点（面试陷阱）**：

1. **写了析构但没写拷贝/移动**：拷贝默认生成（deprecated），移动被抑制。代码"能跑"但每次"拷贝"实际内部有裸指针时是浅拷贝，double-free 崩溃。
2. **基类析构不是虚的**：`Base* p = new Derived; delete p;` 派生类析构不会被调用，资源泄漏。
3. **`= default` vs 不写**：`= default` 明确表达"我需要编译器生成的默认行为"，同时让编译器在可能时生成 `noexcept`/`constexpr`/`trivial` 等额外属性，而纯粹不写只有"碰巧生成"的语义。
4. **移动操作不是自动 `noexcept`**：`vector` 在扩容时如果移动构造没标记 `noexcept`，会退化成拷贝（以保异常安全），性能骤降。自定义移动操作应加 `noexcept`。

### 8. `constexpr`

`constexpr` 表示可以在编译期求值。

```cpp
constexpr int square(int x) {
    return x * x;
}

int arr[square(3)];
```

**面试重点**：

- `const` 强调只读。
- `constexpr` 强调编译期常量表达式。
- `constexpr` 函数在参数是编译期常量时可编译期计算，否则也可以运行期计算。

---

### 9. 线程库

C++11 标准化了线程、锁、条件变量。

```cpp
std::thread t([] {
    // do something
});
t.join();
```

常见组件：

- `std::thread`
- `std::mutex`
- `std::lock_guard`
- `std::unique_lock`
- `std::condition_variable`
- `std::atomic`

**面试追问**：`lock_guard` 和 `unique_lock` 区别？

- `lock_guard` 简单轻量，构造加锁，析构解锁。
- `unique_lock` 更灵活，支持延迟加锁、手动解锁、移动，常和条件变量配合。

> 深入：锁家族选型、条件变量与死锁见 [01-多线程与锁](01-多线程与锁.md)；`std::atomic` 与内存序见 [02-原子操作与内存序](02-原子操作与内存序.md)。

### 10. 统一初始化与 `initializer_list`

```cpp
std::vector<int> v{1, 2, 3};
int x{10};
```

优点：

- 初始化形式统一。
- 可以防止部分窄化转换。

```cpp
int a = 3.14;  // 允许，截断
int b{3.14};   // 编译错误
```

## C++14

### 1. 泛型 Lambda

```cpp
auto add = [](auto a, auto b) {
    return a + b;
};
```

C++11 lambda 参数必须写具体类型，C++14 支持 `auto` 参数，更适合泛型代码。

---

### 2. `std::make_unique`

C++11 有 `make_shared`，但没有 `make_unique`，C++14 补上。

```cpp
auto p = std::make_unique<int>(10);
```

优点：

- 避免手写 `new`。
- 异常安全。
- 表达所有权更清晰。

---

### 3. 函数返回类型自动推导

```cpp
auto add(int a, int b) {
    return a + b;
}
```

适合返回类型明显、模板返回类型复杂的场景。

---

### 4. 增强版 `constexpr`

C++14 放宽了 `constexpr` 函数限制，可以写局部变量、循环、分支。

```cpp
constexpr int sum(int n) {
    int ret = 0;
    for (int i = 1; i <= n; ++i) {
        ret += i;
    }
    return ret;
}
```

# C++17

### 1. 结构化绑定

```cpp
std::pair<int, std::string> p{1, "Tom"};
auto [id, name] = p;
```

常用于 `pair`、`tuple`、结构体、map 遍历。

```cpp
std::map<std::string, int> scores;
for (const auto& [name, score] : scores) {
    // ...
}
```

---

### 2. `if` / `switch` 初始化语句

```cpp
if (auto it = mp.find("key"); it != mp.end()) {
    // 使用 it
}
```

优点：限制变量作用域，让代码更紧凑。

---

### 3. `if constexpr`

编译期分支，常用于模板。

```cpp
template <typename T>
void print(T value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "int-like: " << value << std::endl;
    } else {
        std::cout << "other: " << value << std::endl;
    }
}
```

**面试重点**：普通 `if` 的两个分支都要语义合法；`if constexpr` 未命中的分支不会参与实例化。

---

### 4. 内联变量 `inline variable`

解决头文件中定义全局变量的多重定义问题。

```cpp
// config.h
inline int globalConfig = 10;
```

常用于 header-only 库或全局常量。

---

### 5. `std::optional`

表示“可能有值，也可能没有值”。

```cpp
std::optional<int> findValue(bool ok) {
    if (ok) return 10;
    return std::nullopt;
}
```

比用特殊值 `-1`、空字符串更清晰。

---

### 6. `std::variant`

类型安全的联合体。

```cpp
std::variant<int, std::string> v;
v = 10;
v = std::string("hello");
```

访问：

```cpp
std::visit([](auto&& value) {
    std::cout << value << std::endl;
}, v);
```

---

### 7. `std::any`

可以保存任意类型的值。

```cpp
std::any value = 10;
value = std::string("hello");
```

取值需要指定真实类型：

```cpp
auto s = std::any_cast<std::string>(value);
```

**对比**：

- `optional<T>`：有没有一个 `T`。
- `variant<A, B, C>`：值是有限类型集合中的一种。
- `any`：值可以是任意类型，但类型安全更多依赖运行期检查。

---

### 8. `std::string_view`

字符串只读视图，不拥有内存。

```cpp
void print(std::string_view s) {
    std::cout << s << std::endl;
}
```

优点：避免不必要的字符串拷贝。

**面试追问**：`string_view` 有什么坑？

它不管理生命周期，不能引用已经销毁的字符串。

```cpp
std::string_view bad() {
    std::string s = "hello";
    return s; // 错误：返回悬空 string_view
}
```

---

### 9. 文件系统库 `std::filesystem`

```cpp
#include <filesystem>

namespace fs = std::filesystem;

for (const auto& entry : fs::directory_iterator(".")) {
    std::cout << entry.path() << std::endl;
}
```

常用能力：

- 判断文件是否存在。
- 遍历目录。
- 拼接路径。
- 获取文件大小。
- 创建/删除目录。

---

### 10. 折叠表达式

用于可变参数模板。

```cpp
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);
}
```

等价于把所有参数用 `+` 折叠起来。

---

### 11. 类模板参数推导 CTAD

```cpp
std::pair p(1, 2.0);        // 推导为 std::pair<int, double>
std::vector v{1, 2, 3};     // 推导为 std::vector<int>
```

减少模板类型书写。

---

### 12. 并行算法

C++17 给部分标准算法增加执行策略。

```cpp
std::sort(std::execution::par, v.begin(), v.end());
```

常见策略：

- `std::execution::seq`：顺序执行。
- `std::execution::par`：并行执行。
- `std::execution::par_unseq`：并行且允许向量化。

实际是否加速取决于标准库实现、数据规模和任务类型。

## 面试高频总结

### C++11 最常问

- 右值引用、移动语义、完美转发。
- 智能指针和循环引用。
- Lambda 捕获方式。
- `nullptr` 和 `NULL` 区别。
- `const` 和 `constexpr` 区别。
- `thread`、`mutex`、`condition_variable`。

### C++14 最常问

- 泛型 Lambda。
- `make_unique`。
- 返回类型自动推导。
- 增强 `constexpr`。

### C++17 最常问

- 结构化绑定。
- `if constexpr`。
- `optional` / `variant` / `any` 的区别。
- `string_view` 生命周期问题。
- `filesystem`。
- 折叠表达式。

### 一句话背诵版

> C++11 主要是现代 C++ 的基础，包括自动类型推导、lambda、右值引用、移动语义、智能指针和线程库；C++14 是对 C++11 的补强，比如泛型 lambda、`make_unique` 和增强 `constexpr`；C++17 则进一步提升工程表达能力和泛型编程能力，引入了结构化绑定、`if constexpr`、`optional/variant/any`、`string_view`、`filesystem`、折叠表达式和类模板参数推导等特性。
