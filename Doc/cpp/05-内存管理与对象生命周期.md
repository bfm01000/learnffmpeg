# C++ 内存管理：内存布局、底层机制与面试高频题

> **💡 面试速记（可直接背诵的话术模板）**
>
> 1. **C++ 程序的内存分为哪几个区？** 经典五大区：
>
> **栈区**（存放局部变量、函数参数，由编译器自动分配释放，速度快但空间小）；
>
> **堆区**（由程序员手动 `new/malloc` 分配释放，空间大但容易产生碎片和泄漏）；
>
> **（全局/静态） 变量**（存放全局变量和静态变量，分初始化 `.data` 和未初始化 `.bss`）；
>
> **常量区**（存放字符串字面量等只读数据）；
>
> **代码区**（存放二进制机器指令）。
>
> 1. `**new`/`delete` 和 `malloc`/`free` 的本质区别？** `malloc/free` 只是 C 语言的库函数，只负责分配/释放裸内存；而 `new/delete` 是 C++ 的**运算符**，它除了分配内存，还会**自动调用对象的构造函数和析构函数**。此外，`new` 是类型安全的，失败抛出 `bad_alloc` 异常，而 `malloc` 返回 `void`*，失败返回 `NULL`。
> 2. **什么是 RAII？** RAII（资源获取即初始化）是 C++ 内存管理的最核心思想。它利用局部对象在离开作用域时会自动调用析构函数的特性，把动态分配的资源（内存、锁、文件句柄等）绑定到一个局部对象的生命周期上。智能指针就是 RAII 的典型应用。
> 3. `**delete p` 和 `delete[] p` 的区别？如果用混了会怎样？** `delete p` 只调用一次析构函数，释放一块内存；`delete[] p` 会读取数组首地址前面的一个隐藏字（记录了数组长度），然后**对数组中的每个元素挨个调用析构函数**，最后释放整块内存。如果对象是基本数据类型（如 `int`），混用不会崩溃（只漏调析构，但基本类型没析构）；但如果对象是自定义类且有复杂的析构逻辑，用 `delete` 释放数组会导致**除第一个元素外的所有对象都没执行析构**，极易引发内存泄漏甚至崩溃。
> 4. **如何定位内存泄漏？** 在开发阶段，严格使用**智能指针**和 **RAII** 预防；在排查阶段，Linux 下常用 **Valgrind** 或者编译时加上 GCC/Clang 的 **AddressSanitizer (ASan, `-fsanitize=address`)**，它们能精准报告哪里 `new` 了但没有 `delete`，以及越界访问等问题。

## 一、 C++ 内存布局深度剖析

当一个 C++ 程序运行起来后，它在内存中的排布是有严格划分的（从高地址到低地址通常如下）：

### 1. 栈区（Stack）

- **存储内容**：函数内的局部变量、函数传参的值、函数的返回地址等。
- **管理方式**：由编译器**自动**分配和释放。函数一结束，里面的栈变量就全被弹出了。
- **特性**：**速度极快**（底层只是移动一下栈顶指针 `rsp`），因为它是连续的内存。但**容量很小**（Linux 默认一般是 8MB），如果在栈上开超大数组，或者发生无限递归，就会导致 **Stack Overflow（栈溢出）**。

### 2. 堆区（Heap）

- **存储内容**：程序运行期间动态请求的内存（用 `new`、`malloc` 申请的）。
- **管理方式**：由程序员**手动**控制（必须手动 `delete/free`，否则就是内存泄漏）。
- **特性**：**容量极大**（受限于虚拟内存），但不连续。频繁地分配和释放会产生**内存碎片**（Memory Fragmentation）。速度比栈慢，因为底层需要调用系统的分配算法（如 `brk/mmap`）去空闲链表里找一块合适的内存。

### 3. （全局 / 静态）变量存储区

分为两个相邻的段：

- `**.data` 段（初始化数据段）**：存放**已经明确初始化且值不为 0** 的全局变量和静态变量。
- `**.bss` 段（未初始化数据段）**：存放**未初始化**或**明确初始化为 0** 的全局/静态变量。
  - **🔥 面试常考细节：为什么未初始化的全局变量默认是 0？**
  - **答：** 因为它们被放在了 `.bss` 段。`.bss` 段在可执行文件中其实是不占物理磁盘空间的（只记录需要多大空间）。当操作系统把程序加载到内存运行时，会统一把 `.bss` 段分配的内存全部清零。所以，未初始化的全局变量和静态变量，在程序运行之初，天然就被操作系统“免费”初始化成了 0。

### 4. 常量区（`.rodata`）

- **存储内容**：存放常量字符串（如 `"hello world"`）、`const` 修饰的**全局变量**等。
- **特性**：**只读**。如果你用裸指针强行试图修改常量区的字符串，程序会直接段错误崩溃（Segmentation Fault）。
- **🔥 面试常考细节：全局变量加不加 `const`，存储位置有什么区别？**
  - **答：区别在于是否具有操作系统级别的“只读”保护。**
    1. **没有被 `const` 修饰的全局变量**：存在**全局/静态存储区**（根据是否初始化，分在 `.data` 或 `.bss` 段）。它们是**可读可写**的，程序运行期间随时可以修改。
    2. **被 `const` 修饰的全局变量**：存在**常量区（`.rodata` 段）**。编译器和操作系统会共同保护这块内存，它是**绝对只读**的。任何试图通过指针强转修改它的行为，都会触发操作系统的内存保护机制，导致程序直接崩溃（段错误）。
- **🔥 面试常考细节：`const` 修饰的变量一定在常量区吗？**
  - **答：绝对不是！** `const` 只是一个编译期的语法约束，告诉编译器“不准修改它”。它存在哪，取决于它定义的位置：
    1. **全局/静态作用域的 `const`**（如 `const int a = 10;` 写在函数外，或者 `static const int b = 20;`）：存在**常量区（.rodata）**，受到操作系统级别的内存写保护。
    2. **局部作用域的 `const`**（如函数里写的 `const int c = 30;`）：存在**栈区**。它只是编译器不让你改，如果你通过指针强转骗过编译器（`int* p = (int*)&c; *p = 40;`），在栈上是可以修改成功的（虽然属于未定义行为，但不会报段错误）。
    3. **类的 `const` 成员变量**：存在**堆区或栈区**（取决于对象在哪 new 出来的）。它占用对象的内存空间，每个对象都有一份。

### 5. 代码区（`.text`）

- **存储内容**：存放程序编译后的机器指令和汇编代码。
- **特性**：**只读**、**共享**。
  - **只读**：防止程序意外修改自己的指令（如果被修改，就是典型的缓冲区溢出攻击/代码注入）。如果你用指针强行指向代码区的地址并试图修改它，和常量区一样，操作系统会立刻抛出段错误（Segmentation Fault）导致程序崩溃。
  - **共享**：如果同一个程序运行了多个实例（比如开了两个同样的软件），它们在内存中共享同一份代码区，极大地节省了物理内存。

## 二、 `new` / `delete` 底层运作机制

面试官最爱问：“执行 `Foo* p = new Foo();` 时，底层到底发生了什么？”

`**new` 的两步走机制：**

1. **分配内存**：编译器在底层会**自动**帮你调用一个名为 `operator new` 的全局函数。这个函数内部其实就是调用了 `malloc`，在堆上申请正好能装下一个 `Foo` 对象的裸内存。
2. **调用构造函数**：编译器在刚申请的这块内存上，调用 `Foo` 的构造函数对对象进行初始化。

**🔥 极限深挖拷问：为什么我代码里写的是 `new`，底层却调用了 `operator new`？它们有什么区别？能重载吗？**

> 面试绝杀回答：“这是两个完全不同的概念，也是 C++ 编译器在底层做的‘语法转换’魔法。
> 简单来说一个公式：`**new` 关键字 = `operator new` 函数 + 构造函数**。
>
> 1. `**new` 关键字（new expression）**：它是 C++ 语言级别的操作符，**绝对不能被重载**。当你写下 `new Foo()` 时，编译器会把这句代码翻译成两步：第一步调用 `operator new` 函数去要内存，第二步调用 `Foo::Foo()` 构造函数去初始化。
> 2. `**operator new` 函数**：它是一个标准的全局库函数（声明为 `void* operator new(size_t size)`）。它的唯一职责就是**单纯地分配裸内存**，不负责初始化。底层通常是对 C 语言 `malloc` 的封装。如果分配失败，它会抛出 `std::bad_alloc` 异常，而不是像 `malloc` 那样返回 `NULL`。
>
> **（高频追问：如果是 `new int` 或 `new int[10]` 这种基本数据类型呢？）**
> 🗣️ **口语化回答**：“基本数据类型没有构造函数，所以流程会有所精简。
>
> - 如果是 `new int`：编译器只会调用 `operator new(4)` 分配 4 个字节的裸内存，**跳过**调用构造函数这一步（除非你写了 `new int(5)`，编译器会帮你把这块内存的值设为 5）。
> - 如果是 `new int[10]`：编译器会调用另一个专门分配数组的全局函数 **`operator new[]`**，一次性分配 40 个字节的内存。同样，如果是对象数组（如 `new Foo[10]`），编译器会在分配完内存后，**循环调用 10 次** `Foo` 的构造函数。”
>
> **（高阶加分项：重载与内存池）** 最关键的是，`operator new` 函数是**可以被重载**的！我们可以全局重载它，也可以在某个特定类内部重载它。在游戏引擎或高并发服务器中，为了避免频繁调用系统 `malloc` 导致内存碎片和性能下降，我们通常会重载类的 `operator new`，让它从我们自己预先分配好的**内存池（Memory Pool）**中去取内存，从而实现极速的内存分配。
>
> **🔥 极限深挖拷问：除了 `operator new`，C++ 还能重载 `operator()` 吗？有什么用？**
> 🗣️ **口语化回答**：“当然可以！重载 `operator()`（函数调用操作符）是 C++中非常核心的一个特性。
> 当我们在一个类里重载了 `operator()` 之后，这个类的实例化对象就可以像普通函数一样被调用，这种对象被称为**仿函数（Functor）或函数对象**。
> 比如 `class Adder { public: int operator()(int a, int b) { return a + b; } };`，我们可以直接用 `Adder add; int sum = add(1, 2);`。
> **仿函数比普通函数强大的地方在于它有‘状态’。** 因为它本质是个类，内部可以存成员变量。在 C++11 引入 Lambda 表达式之前，STL 算法（如 `std::sort` 的自定义排序规则）大量依赖仿函数。实际上，**C++ 中的 Lambda 表达式，底层原理就是一个由编译器自动生成的、重载了 `operator()` 的匿名仿函数类！**”

`**delete` 的两步走机制：**

1. **调用析构函数**：编译器先调用 `p` 指向对象的 `~Foo()` 析构函数，清理对象内部可能占用的资源。
2. **释放内存**：底层调用全局函数 `operator delete`，它内部其实就是调用了 `free`，把这块裸内存还给操作系统。

## 三、 高频面试题与踩坑点

### 1. 既然有了 `malloc/free`，为什么 C++ 还要引入 `new/delete`？

**答：** 核心原因是 C++ 是面向对象的。`malloc` 不懂对象，它只管分几百个字节的哑内存（Dumb Memory）。如果我们要创建一个复杂的类（比如内部包含动态数组、打开了文件等），只分配内存是没用的，**必须要调用构造函数来初始化内部状态**。`new` 就是“分配内存 + 调用构造”的结合体，是为面向对象量身定制的。

### 2. 什么是 Placement new（定位 new）？

**问：** 我已经有一块分配好的内存了，怎么在这块内存上构造对象？
**答：** 使用 Placement new。语法是 `new (指针) 类型()`。

- **作用**：它**不分配内存**，仅仅是在指定的内存地址上“原地”调用一下构造函数。
- **场景**：在开发**内存池（Memory Pool）**或者要求极低延迟的场景（如音视频底层缓存复用）。为了避免频繁的 `malloc/free` 开销，我们会预先分配一大块裸内存池，然后用 Placement new 在这块内存上反复构造对象。对象用完后，我们只显式调用析构函数（`p->~Foo()`），但不 `delete` 内存，留着下次继续 Placement new。

### 3. 栈和堆哪个分配速度快？为什么？

**答：栈远远快于堆。**

- **栈**分配内存仅仅是将 CPU 的栈指针寄存器（如 ESP/RSP）往下移动几个字节，是单条汇编指令的事；释放也是加回去。而且栈的内存非常集中，CPU Cache 命中率极高。
- **堆**分配需要进入操作系统内核态或者调用 C 库复杂的分配算法（要在空闲链表里搜寻合适的块，可能还要拆分或合并块，甚至触发页表映射），操作复杂，多线程下还可能涉及到锁的竞争。

### 4. 什么是内存碎片？怎么解决？

- **内部碎片**：因为系统分配内存时通常按块对齐（比如以 8 字节或 4K 页对齐），你申请 5 字节，系统给你 8 字节，浪费的 3 字节就是内部碎片。
- **外部碎片**：堆内存经过频繁的申请和释放，变成了“瑞士奶酪”，到处都是零散的小空闲块。导致你想申请一块 1MB 的大内存时，虽然空闲总和有 10MB，但没有一块连续的 1MB，导致分配失败。
- **解决办法**：
  1. **使用内存池（Memory Pool）**：一次性向系统申请大块连续内存，然后在业务层自己切割管理，统一回收。
  2. **对象复用（Object Pool）**：像我们音视频里的 `FramePool`，解码出的对象用完不销毁，塞回队列下次覆盖复用。
  3. **TCMalloc / Jemalloc**：替换掉系统默认的 glibc `malloc`，使用 Google 等大厂优化的内存分配器，能有效减少多线程下的碎片和锁竞争。

### 5. 野指针（Wild Pointer）和悬空指针（Dangling Pointer）的区别？

- **野指针**：指针变量在声明时**没有被初始化**。它指向一个随机的垃圾地址。
  - *规避*：声明指针时立刻置为 `nullptr`。
- **悬空指针**：指针原本指向一块合法的内存，但**那块内存已经被 `delete` 释放了**，可是这个指针的值（那个地址）没有被清空。如果你再去访问它，就是踩雷。
  - *规避*：`delete p;` 之后立刻补一句 `p = nullptr;`。更现代的做法是直接抛弃裸指针，使用**智能指针（`shared_ptr` / `unique_ptr`）**，让编译器帮你管生管死。

## 四、RAII：C++ 资源管理的核心范式

**RAII（Resource Acquisition Is Initialization，资源获取即初始化）** 是 C++ 区别于 C / Java 内存管理哲学的核心：把资源的生命周期**绑定到一个栈对象的生命周期**上——构造时获取资源，析构时释放资源。由于 C++ 保证**对象离开作用域时一定调用析构函数**（哪怕中途 `return`、抛异常），资源就一定被释放。

```cpp
// 不用 RAII：任何一条 return / 异常都会漏掉 unlock / fclose / delete
void bad() {
    mtx.lock();
    FILE* fp = fopen("a.dat", "rb");
    if (!fp) return;             // ❌ 锁没释放
    // ... 中途 throw 同样泄漏
    fclose(fp);
    mtx.unlock();
}

// 用 RAII：作用域结束自动释放，异常安全
void good() {
    std::lock_guard<std::mutex> lock(mtx);          // 析构自动 unlock（见 [[01-多线程与锁]]）
    std::unique_ptr<FILE, decltype(&fclose)> fp(fopen("a.dat", "rb"), &fclose); // 析构自动 fclose
    if (!fp) return;             // ✅ 锁和文件都自动释放
}
```

**RAII 的典型载体**：智能指针（见 [[06-智能指针与资源管理]]）、`lock_guard`/`unique_lock`（见 [[01-多线程与锁]]）、`std::fstream`、自定义的 FFmpeg 资源包装。

**面试一句话**：“RAII 就是用对象的构造/析构来管理资源的获取与释放，利用栈对象离开作用域必然析构这一点，保证哪怕中途异常或提前 return，资源也不会泄漏。智能指针和 `lock_guard` 都是 RAII 的应用。”

## 五、内存对齐（Memory Alignment）

### 1. 为什么需要对齐？

CPU 访问内存通常按字长成块读取。如果一个 4 字节 `int` 跨越了对齐边界，CPU 可能要读两次再拼接，某些架构（ARM）甚至直接硬件异常。因此编译器会让每个类型的地址是其**对齐值（alignment）**的整数倍——通常等于类型大小（`int` 对齐到 4、`double` 对齐到 8）。

### 2. 结构体填充（padding）

```cpp
struct Bad {     // sizeof == 24（有填充）
    char  a;     // 1 字节 + 7 填充
    double b;    // 8 字节
    int   c;     // 4 字节 + 4 尾部填充（让整体对齐到 8）
};
struct Good {    // sizeof == 16：按从大到小排列成员可减少填充
    double b;    // 8
    int   c;     // 4
    char  a;     // 1 + 3 填充
};
```

> 面试题“以下结构体 sizeof 是多少”，关键是：① 每个成员按自身对齐值放置，前面不够就填充；② 整体大小补齐到**最大成员对齐值**的整数倍。**把大成员排前面能省内存**。

### 3. 查询与指定对齐

```cpp
alignof(double);                 // 查询对齐值：8
struct alignas(64) CacheLine {   // 指定对齐到 64 字节（一个缓存行）
    std::atomic<int> counter;
};
```

`alignas(64)` 常用于**避免伪共享**（false sharing）：把不同线程频繁写的变量各自对齐到独立缓存行，防止它们落在同一行被反复失效（见 [[03-无锁队列]]）。

### 4. 音视频里的对齐

- **SIMD（SSE/NEON）** 要求数据按 16/32 字节对齐才能用对齐加载指令；FFmpeg 的 `av_malloc` 就按 32 字节对齐分配。
- **DMA / 硬件解码器** 常要求缓冲按特定边界对齐，否则拒绝或降速。
- 解析裸字节流时不能假设对齐（见 [[11-类型转换]]），跨边界读取要用 `memcpy`。

## 六、对象生命周期与构造/析构顺序

面试高频：“成员变量、基类、局部对象的构造析构顺序是怎样的？”

1. **成员变量按声明顺序构造**，与初始化列表里写的顺序**无关**；析构按声明的**逆序**。
2. **基类先于派生类构造**，派生类先于基类析构（见 [[08-继承、多态、虚函数与对象模型]]）。
3. **同一作用域的局部对象按定义顺序构造、逆序析构**（栈式后进先出）。
4. **函数内 static 局部变量**在首次执行到定义处时构造，程序退出时析构；C++11 起其初始化是**线程安全**的（常用于单例，见 [[13-语言基础关键字]]）。

```cpp
class Demo {
    A a;   // 先构造（先声明）
    B b;   // 后构造
public:
    Demo() : b(), a() {}   // ⚠️ 即使这里写 b 在前，实际仍是 a 先构造（按声明顺序）
    // 析构顺序：先 ~b 再 ~a（逆序）
};
```

> 这条规则的实战意义：若成员 `b` 的初始化依赖 `a`，必须让 `a` 声明在前，否则用到未构造的 `a` 是未定义行为——编译器还可能因初始化列表顺序与声明顺序不一致而告警。
