# C++ 虚函数：底层原理、实战与面试避坑指南

> **💡 面试速记（可直接背诵的话术模板）**
>
> 1. **什么是虚函数？** 虚函数是 C++ 实现**动态多态**（运行时多态）的核心机制。通过在基类函数前加 `virtual` 关键字，可以让基类指针或引用在运行时根据实际指向的子类对象，调用对应的子类重写版本。
> 2. **底层实现原理是什么？** 编译器为每个包含虚函数的类生成一个**虚函数表（vtable）**，表里存着虚函数的函数指针。同时在类的对象内存布局的最前面，偷偷塞入一个**虚表指针（vptr）**，指向这个类的 vtable。运行时，通过 `对象 -> vptr -> vtable -> 真实的函数地址` 来完成动态绑定。
> 3. **非虚函数（普通函数）有表吗？它是怎么被调用的？** **绝对没有表。** 虚函数是为了“运行期”找对象才建表的，而非虚函数的地址在**编译期**就已经确定了。编译器会直接把非虚函数的真实内存地址硬编码进汇编的 `CALL` 指令里，这叫**静态绑定**。非虚函数的代码只在代码区（`.text`）保存一份，调用时编译器会偷偷把当前对象的地址作为第一个参数（隐藏的 `this` 指针）传给这个函数。
> 4. **为什么基类的析构函数必须是虚函数？** 如果基类析构函数不是虚函数，当我们用 `delete 基类指针` 来释放一个子类对象时，编译器只会静态绑定调用基类的析构函数，**子类的析构函数永远不会被执行**，这会导致子类特有的资源（比如 new 出来的内存）发生严重的**内存泄漏**。
> 5. **构造函数能是虚函数吗？** **绝对不能。** 从逻辑上讲，虚函数的作用是根据现有的对象类型调用不同行为，而构造对象时对象还没完全生成；从底层原理讲，vptr 是在构造函数的执行过程中才被初始化的，调用构造函数时连 vptr 都还没有准备好，根本无法查表。
> 6. **构造/析构函数里能调虚函数吗？** 语法上能调，但**绝达不到你想要的多态效果**。在基类构造时，对象的身份还只是个基类，vptr 指向基类的虚表，调用的只会是基类的版本；析构时同理，子类部分已经被剥离，调用的也是基类版本。

## 一、 虚函数的核心概念与作用

**一句话总结：虚函数让“相同的调用”产生“不同的行为”。**

在面向对象编程中，我们经常把子类对象赋值给基类的指针或引用。如果不加 `virtual`，C++ 默认是**静态绑定（早绑定）**，即根据指针的类型来决定调用哪个函数。加了 `virtual` 后，变成**动态绑定（晚绑定）**，根据指针实际指向的内存到底是什么对象来决定调用哪个函数。

```cpp
class Animal {
public:
    void sleep() { cout << "Animal sleep (非虚函数)" << endl; }
    virtual void speak() { cout << "Animal speak (虚函数)" << endl; }
};

class Dog : public Animal {
public:
    void sleep() { cout << "Dog sleep" << endl; }
    void speak() override { cout << "Dog speak" << endl; }
};

int main() {
    Dog myDog;
    Animal* ptr = &myDog; // 基类指针指向子类对象

    ptr->sleep(); // 输出 "Animal sleep" -> 静态绑定，看指针类型 (Animal*)
    ptr->speak(); // 输出 "Dog speak"    -> 动态绑定，看实际对象类型 (Dog)
}
```

## 二、 面试必考：虚函数的底层原理解析 (vtable & vptr)

如果面试官问：“虚函数是怎么实现多态的？”，你**必须**画出（或描述出）这幅图。

### 1. 虚函数表（vtable）

- **归属**：vtable 是**属于类（Class）**的，同一个类的所有对象共享同一张虚表。
- **内容**：它本质上是一个**函数指针数组**。里面记录了这个类所有虚函数的真实内存地址。
- **创建时机**：在**编译期**就已经确定并生成好了，通常存放在可执行文件的只读数据段（`.rodata`）。

### 2. 虚表指针（vptr）

- **归属**：vptr 是**属于对象（Object）**的。当一个类有虚函数时，编译器会在这个类的每个实例化对象的内存布局的最前端（通常是 offset 0 的位置）悄悄安插一个隐藏的指针 `vptr`。
- **内容**：它指向该类对应的 vtable 的首地址。
- **初始化时机**：在**运行期**，由类的**构造函数**悄悄帮你完成初始化。

### 3. 查表过程（动态绑定的代价）

当我们执行 `ptr->speak()` 时，底层的汇编指令实际上做了以下几步（这也是虚函数的性能开销所在）：

1. 取出 `ptr` 指向的对象的首地址，拿到里面的 `vptr`。
2. 通过 `vptr` 找到对应的虚函数表 `vtable`。
3. 根据 `speak` 函数在表中的固定偏移量（索引），在表里取出真正的函数地址。
4. 跳转执行。

## 三、 面试高频问题与陷阱

### 1. 纯虚函数与抽象类

**问：什么是纯虚函数？有什么作用？**
答：在虚函数后面加上 `= 0` 就是纯虚函数（如 `virtual void draw() = 0;`）。它没有函数体（不需要实现）。
包含至少一个纯虚函数的类叫**抽象类**。抽象类**不能实例化**创建对象，只能被继承。它本质上是在定义一个**接口规范（Interface）**，强制要求子类必须实现这些方法。

### 2. 虚析构函数（极其重要！）

**问：为什么基类的析构函数通常要声明为虚函数？**
答：为了防止内存泄漏。

```cpp
class Base { public: ~Base() { cout << "Base Dtor"; } };
class Derived : public Base { 
    int* data;
public: 
    Derived() { data = new int[100]; }
    ~Derived() { delete[] data; cout << "Derived Dtor"; } 
};

Base* p = new Derived();
delete p; // 💣 灾难发生！
```

如果 `~Base()` 不是虚函数，`delete p` 时编译器只看到 `p` 是 `Base*` 类型，只会静态绑定调用 `Base` 的析构函数。子类 `Derived` 的析构函数永远不会被执行，`data` 数组直接泄漏！
如果加上 `virtual ~Base()`，析构时就会动态查表，先调用子类的析构函数释放资源，再自动调用基类的析构函数，安全下车。

### 3. 可以把析构函数设为纯虚函数吗？

**问：纯虚析构函数可以吗？有什么坑？**
答：可以写 `virtual ~Base() = 0;`。这样可以把一个没有其他纯虚函数的基类强制变成抽象类。
**致命坑点**：虽然是纯虚的，但**你必须在类外为它提供一个空实现**（`Base::~Base() {}`）。因为子类析构完之后，编译器会强制调用基类的析构函数，如果你没写实现，链接器（Linker）会直接报错说找不到符号。

### 4. 内联函数（inline）可以是虚函数吗？

**答：语法上可以，但大多数时候起不到内联的效果。**
`inline` 是编译期的建议（把代码直接展开），而 `virtual` 多态是运行期的行为（查虚表找地址）。
当你用基类指针/引用发生动态绑定时，编译器在编译期根本不知道最终会调哪个函数，所以**绝对无法内联展开**。
只有当你直接用**对象本身**（而不是指针/引用）调用该虚函数时，编译器确定类型了，这时候才能成功内联。

### 5. 虚函数参数的默认值陷阱

**问：以下代码输出什么？**

```cpp
class Base {
public:
    virtual void func(int x = 10) { cout << "Base: " << x << endl; }
};
class Derived : public Base {
public:
    void func(int x = 20) override { cout << "Derived: " << x << endl; }
};

Base* p = new Derived();
p->func();
```

**绝杀陷阱：输出 `Derived: 10`！**
答：这是 C++ 一个非常反直觉的设计。**虚函数是动态绑定的（看实际对象），但默认参数是静态绑定的（看指针类型）！**
编译 `p->func()` 时，编译器看到 `p` 是 `Base*`，于是把 `Base` 的默认值 `10` 塞进了汇编指令里。运行时查表调用了 `Derived::func`，所以打出 Derived，但传进去的参数是 10。
**最佳实践**：规范要求，如果重写带有默认参数的虚函数，**子类的默认参数必须和基类保持一模一样**，或者干脆不在虚函数里用默认参数，改用 NVI（Non-Virtual Interface）手法。

### 6. 哪些函数不能是虚函数？

1. **构造函数**（前面已解释：对象还没生成，vptr 还没初始化）。
2. **静态成员函数（static）**（静态函数属于类本身，没有 `this` 指针，根本没法通过 `this->vptr` 去查表）。
3. **普通全局函数**（非成员函数，没意义）。
4. **友元函数**（友元不是成员函数）。

### 7. 非虚函数（普通函数）有表吗？

**问：虚函数有 vtable，那普通的非虚函数有表吗？它是怎么存的？**
**绝杀回答：** **绝对没有表**。

1. **静态绑定**：虚函数建表是为了“运行期”找地址，而非虚函数的地址在**编译期**就已经确定了。编译器会直接把它的真实地址（位于代码段 `.text`）硬编码到汇编的 `CALL` 指令里，直接跳转，没有任何查表的性能开销。
2. **不占对象内存**：非虚函数的代码只在代码区保留一份，不管类里写了多少个普通函数，实例化出来的对象大小都不会增加。
3. **隐藏的 `this` 指针**：既然代码只有一份，它怎么区分操作的是哪个对象的成员变量？因为编译器在底层会悄悄把当前对象的地址，作为第一个参数（也就是隐藏的 `this` 指针）传递给这个位于代码段的全局函数。

### 8. C++11 的 `override` 和 `final` 关键字

**问：重写虚函数时为什么要加 `override`？`final` 有什么用？**
**答：为了让编译器帮你防呆，并在设计上明确意图。**

- `**override`**：
  - 在 C++11 之前，如果子类想重写（Overwrite）基类的虚函数，但一不小心把参数类型、名字或者 `const` 属性写错了（比如基类是 `func(int)`，子类写成了 `func(float)`），编译器**不会报错**，而是会认为你在子类里定义了一个全新的**隐藏（Hide）**函数。这会导致多态完全失效。
  - 加了 `override` 后，编译器会强制去基类里检查：“有没有一个一模一样的虚函数可以给我重写？”如果没有，直接**编译报错**。这是现代 C++ 极为推荐的安全规范。
- `**final`**：
  - **修饰类**：`class Derived final : public Base {};` 表示这个类是“断子绝孙”的，任何类都不能再继承它。
  - **修饰虚函数**：`virtual void func() final;` 表示这个虚函数到我这里就结束了，后面的任何子类都**不允许再重写它**。如果在性能极度敏感的代码里，编译器确信某个虚函数是 `final` 的，它就有可能将原本的查表调用优化为直接调用（内联优化），从而提升性能。
