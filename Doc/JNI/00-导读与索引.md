## 一、为什么这样排序

音视频 SDK 开发的 JNI 面试，考察的不只是"知不知道 API"，而是**线程安全**、**内存生命周期**和**大数据零拷贝**三个深水区。因此本库把**线程模型（01）**放在最前（没搞清楚 `JNIEnv` 不能跨线程，后面全是错的），然后是**引用与内存管理（02）**（GlobalRef 泄漏是线上事故第一杀手），接着是**TLS 回调架构（03）**（把 01+02 串成工程方案），最后是**零拷贝（04）**（承接 03 的回调通道，解决音视频帧这类大数据 payload 的传递问题）。

> 这几个主题之间有强依赖：不理解 01 的 Attach 机制就不可能写对 03 的 TLS 回调；不掌握 02 的 GlobalRef 生命周期就不可能安全地在 03 中传递 Java 回调对象；没有 03 的回调通道，04 的 DirectByteBuffer 也只是单点 API，难以落成音视频 SDK 的完整方案。

## 四、推荐学习路线

1. **打底**：01，先搞清 `JNIEnv` 为什么不能跨线程，以及 `AttachCurrentThread` 的正确姿势。
2. **深入注册机制**：05，彻底搞懂静态注册和动态注册的底层原理、方法签名写法、工程选型。
3. **稳住生命周期**：02，掌握三种引用类型、RAII 封装、`shared_ptr` 多线程释放。
4. **串成工程方案**：03，把 01 的 Attach + 02 的 GlobalRef 串成完整的 C++→Java 回调架构。
5. **落到音视频数据**：04，把 03 的回调通道和大块二进制 payload 结合起来，重点处理 DirectByteBuffer 的所有权。
6. **检验**：99 ——自测，查漏补缺。
