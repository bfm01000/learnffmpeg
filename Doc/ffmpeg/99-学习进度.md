### 优先级 1：动手写最简播放器（核心，Pending）

按导读第 13 节、README"下一步建议"：

```
demux MP4 → decode H.264 → swscale 转 RGB → SDL 显示
```

**为什么是这个**：把 AVPacket / AVFrame / time_base / 引用计数 / Planar/Packed 从"读过"推进到"骨头里的"。比读十遍 MP4 box 协议管用十倍。

**预计产出**：

- `project/<新目录>/simplest_player/` C++ 工程
- CMakeLists.txt 接 ffmpeg + SDL2（参考 [[01-数据结构与生命周期]] 第 8.3 节）
- main.cpp 完整跑通 1080p MP4 播放
- 在 99-学习进度.md 记录踩坑笔记

**验收标准**：

- 能播完整段 1080p MP4，画面正常、不花屏、不绿屏
- 能解释自己代码里每一行的目的（特别是引用计数 / linesize / time_base 几处）
- 能讲清"为什么解码出来不是直接 RGB"

### 优先级 2：补一个最简转码器（写完播放器后再做）

```
读 MP4 → decode → encode 成另一种码率 / 分辨率 → 写新 MP4
```

会用到 [[06-编码参数与码控]] 里的 CRF/Profile/Preset 实战。

### 优先级 3：把音频接进来

播放器只有视频是"瘸的"。加音频后才会真正撞上：

- 音视频同步（音频时钟作为主时钟）
- Planar→Packed 重采样
- SDL audio callback 的实时约束

详见 [[04-音频PCM-采样-重采样]] 第 11、16 节。

### 优先级 4（可选）：硬件加速

在 macOS 上意味着 VideoToolbox。参考 [[07-硬件编解码]] 阶段 2。仅在前三个都做完且确实需要时再来。移动端（Android MediaCodec / iOS VideoToolbox 实时编码）见 [10-移动端硬件编解码.md](./10-移动端硬件编解码.md)——这块和 WebRTC 项目直接相关，做手机或 RTC 时优先级会前移。

## 跨机器同步规则

**核心约定**：本文件是 ffmpeg 学习的 single source of truth。每次推进**任何一项**学习活动后立即更新它。

**典型推进动作（任一发生都要更新）**：

- 读完 / 重读完某一份文档
- 写了 / 改了 / 调通了任何代码
- 撞坑 + 解决坑（必须记录踩坑笔记）
- 完成自检题（哪几道答上了、哪几道还不熟）
- 跨了一个学习阶段（阶段 1 → 阶段 2 → 阶段 3）
- 新增 / 改写文档

**更新内容**（每次至少改动）：

1. "最近完成的动作"区块末尾加新条目（带日期）
2. "下一步待办"里把已完成项打 ✅，或调整优先级
3. 如果有新文档 / 新代码产出，更新"已完成成果清单"

**同步流程**：

```bash
# 推进完任何一项后:
git add Doc/ffmpeg/99-学习进度.md  # (以及新增/修改的文档/代码)
git commit -m "ffmpeg: <描述这次推进>"
git push

# 切到别的电脑:
git pull
# 然后用顶部的"一句话恢复指令"启动新会话
```
