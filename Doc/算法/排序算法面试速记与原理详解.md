## 📌 第一部分：面试速记（考前 15 分钟扫一遍）

### 一句话核心

> 排序面试考三件事：**手撕代码不出 Bug**（边界 + 越界 + 空数组）、**会讲清复杂度和稳定性**、**知道工业级实现用什么以及为什么**（不是 std::sort 等于快排）。

### 先看懂复杂度：时间复杂度 vs 空间复杂度

- **时间复杂度**：衡量算法执行时间随着数据规模 `n` 增长的变化趋势。它不关心具体跑了多少毫秒，而是关心 `n` 变大时操作次数怎么增长。例如 `O(n)` 表示大致扫一遍，`O(n log n)` 表示排序算法里常见的分治级别，`O(n²)` 表示双重循环级别，数据一大就会明显变慢。
- **空间复杂度**：衡量算法执行过程中额外占用的内存随着 `n` 增长的变化趋势。这里通常不把输入数组本身算进去，只看额外空间。例如 `O(1)` 表示只用少量变量，`O(log n)` 常见于递归栈，`O(n)` 表示需要额外开一个和输入规模差不多大的数组。
- **平均时间 / 最坏时间**：平均时间看一般输入下的表现，最坏时间看极端输入下的兜底能力。比如快排平均 `O(n log n)`，但如果 pivot 每次都选得很差，最坏会退化到 `O(n²)`。

#### 考点 1：手撕快速排序（最高频，必考）

**考察意图：** 看你能不能徒手写出无 Bug 快排，并清楚 partition 的两种主流写法。

**底层原理：**
分治。选 pivot → partition 把数组分成"小于 pivot"和"大于 pivot"两段 → 递归两段。partition 决定 90% 的 Bug 风险。

**🗣️ 面试标准回答（含代码模板，必背）：**

> "快排核心是 partition + 递归。我用 **Lomuto 分区法**写，思路是用一个慢指针记录小于 pivot 的边界，快指针扫一遍。"

```cpp
// Lomuto 分区（更易记，但常数稍大）
void quickSort(vector<int>& nums, int left, int right) {
    if (left >= right) return;
    int pivot = nums[right];         // 选末尾为 pivot
    int i = left - 1;                // 小于 pivot 的右边界
    for (int j = left; j < right; j++) {
        if (nums[j] < pivot) {
            swap(nums[++i], nums[j]);
        }
    }
    swap(nums[++i], nums[right]);    // pivot 归位
    quickSort(nums, left, i - 1);
    quickSort(nums, i + 1, right);
}
```

**或者用 Hoare 分区（双指针对撞，性能更好）：**

```cpp
int partition(vector<int>& nums, int left, int right) {
    int pivot = nums[left + (right - left) / 2];
    int i = left - 1, j = right + 1;
    while (true) {
        do i++; while (nums[i] < pivot);
        do j--; while (nums[j] > pivot);
        if (i >= j) return j;
        swap(nums[i], nums[j]);
    }
}
void quickSort(vector<int>& nums, int left, int right) {
    if (left >= right) return;
    int partitionIndex = partition(nums, left, right);
    quickSort(nums, left, partitionIndex);       // 注意 Hoare 是 [left, partitionIndex] 不是 [left, partitionIndex-1]
    quickSort(nums, partitionIndex + 1, right);
}
```

**💡 实战案例补充（来自[[核心-自动剪辑性能优化]]）：**

> "我做 Smart Seek 时，要在 `AVStream->index_entries` 数组里二分查找目标 PTS。这个数组本身已经按 PTS 排序（FFmpeg 在 demux 阶段保证的），所以我直接 `std::upper_bound`。但如果是多流合并（多视频源剪辑），我需要把多个流的关键帧时间戳合并排序，这时我用 `std::sort`——底层是 introsort（快排 + 堆排 + 插入排序混合）。"

**👨‍💻 面试官追问：**

> Q1: 快排最坏 O(n²) 怎么避免？
> A: 三种 pivot 优化：**随机选**、**三数取中**（取首/中/尾的中位数）、**introsort**（递归深度超 `2*log(n)` 切换堆排）。
> Q2: 为什么快排不稳定？
> A: 因为 partition 中的 swap 会跨越相等元素的相对位置。例：`[3a, 3b, 1]`，pivot=1，swap 后变 `[1, 3b, 3a]`。
> Q3: 快排空间复杂度为什么是 O(log n)？
> A: 是递归栈深度。可以用尾递归优化把空间降到 O(log n)（先递归小区间，大区间尾递归）。

#### 考点 2：手撕归并排序（次高频）

**考察意图：** 看你懂"分治 + 合并"思想，以及链表归并和数组归并的区别。

**底层原理：**
分治。递归排序左右两半 → 合并两个有序段。**稳定**，因为合并时左半元素优先（`<=` 而非 `<`）。

**🗣️ 面试标准回答（代码必背）：**

```cpp
void merge(vector<int>& nums, int left, int mid, int right, vector<int>& tmp) {
    int i = left, j = mid + 1, k = left;
    while (i <= mid && j <= right) {
        // 关键：用 <= 保证稳定性（相等时取左半）
        if (nums[i] <= nums[j]) tmp[k++] = nums[i++];
        else                     tmp[k++] = nums[j++];
    }
    while (i <= mid) tmp[k++] = nums[i++];
    while (j <= right) tmp[k++] = nums[j++];
    for (int x = left; x <= right; x++) nums[x] = tmp[x];
}
void mergeSort(vector<int>& nums, int left, int right, vector<int>& tmp) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;    // 防溢出
    mergeSort(nums, left, mid, tmp);
    mergeSort(nums, mid + 1, right, tmp);
    merge(nums, left, mid, right, tmp);
}
```

**💡 实战案例补充：**

> "归并最大的工业价值是**外部排序**——数据量超过内存时，分块读入排序后归并写回。FFmpeg 在做 MP4 fragment 重排时本质就是 K 路归并；播放器做多音轨混音也是按 PTS 时间戳的 K 路归并。"

**👨‍💻 面试官追问：**

> Q1: 归并和快排怎么选？
> A: **链表用归并**（O(1) 空间，因为不需要额外数组），**数组用快排**（缓存友好 + 原地）；**需要稳定用归并**；**外部排序用归并**。
> Q2: 链表归并怎么做到 O(1) 空间？
> A: 链表的 merge 不需要拷贝，只需改 next 指针。分治用快慢指针找中点。
> Q3: 归并的 O(n) 额外空间能去掉吗？
> A: 理论上有"原地归并"算法（如 in-place merge sort），但实现复杂且常数大，工业实现不用。

#### 考点 3：堆排序 + Top-K 问题（与优先队列的关系）

**考察意图：** 看你懂堆的本质（完全二叉树 + 数组实现），以及为什么 Top-K 用最小堆。

**底层原理：**

- **大顶堆**：父节点 ≥ 子节点（用于升序排序）
- **建堆 O(n)** 不是 O(n log n)，因为叶子节点占一半（数学证明：累加每层操作数收敛）
- 堆排序 = 建堆 + n 次"取堆顶 + 重新 heapify"

**🗣️ 面试标准回答（代码必背）：**

```cpp
void heapify(vector<int>& nums, int n, int i) {
    int largest = i, l = 2*i + 1, r = 2*i + 2;
    if (l < n && nums[l] > nums[largest]) largest = l;
    if (r < n && nums[r] > nums[largest]) largest = r;
    if (largest != i) {
        swap(nums[i], nums[largest]);
        heapify(nums, n, largest);
    }
}
void heapSort(vector<int>& nums) {
    int n = nums.size();
    // 1. 建堆：从最后一个非叶子节点开始 heapify
    for (int i = n/2 - 1; i >= 0; i--) heapify(nums, n, i);
    // 2. 逐个取堆顶放末尾
    for (int i = n - 1; i > 0; i--) {
        swap(nums[0], nums[i]);
        heapify(nums, i, 0);
    }
}
```

**💡 实战案例补充（来自[[核心-预览延时优化]]）：**

> "AJB 算法里我做过类似的 Top-K 应用：实时跟踪最近 N 帧里**抖动最大的 K 帧**（用于判断是否触发紧急降级）。
> 用最小堆 + 容量 K：维护一个大小为 K 的最小堆，每来一帧抖动值，如果堆顶（最小值）比它小就替换并 heapify。这样堆里始终是 Top-K 大。
> C++ 直接用 `std::priority_queue`，底层就是堆。这比每次全排序快得多——找 Top-K 是 O(n log K) 不是 O(n log n)。"

**👨‍💻 面试官追问：**

> Q1: 为什么 Top-K 大用最小堆，Top-K 小用最大堆？
> A: 最小堆的堆顶是 K 个里最小的，新来一个比它大才有资格替换。反之亦然。
> Q2: 建堆为什么是 O(n)？
> A: 从下往上 heapify，叶子节点 n/2 个无需操作，倒数第二层 n/4 个每个最多下沉 1 层…累加起来是 O(n)。如果从上往下建（每个新元素上浮）就是 O(n log n)。
> Q3: 堆排序在工业中用得多吗？
> A: 单独用得少，主要作为 introsort 的兜底（防止快排退化）。优先队列用得很多（任务调度、Dijkstra、A* 搜索）。

#### 考点 4：排序的稳定性是什么？哪些算法稳定？

**考察意图：** 看你能不能精确定义稳定性，并讲清每个算法为什么稳定/不稳定。

**底层原理：**
稳定性 = **相等元素排序后的相对位置不变**。例：`[(3,'a'), (1,'x'), (3,'b')]` 排完是 `[(1,'x'), (3,'a'), (3,'b')]` 而不是 `[(1,'x'), (3,'b'), (3,'a')]`。

**🗣️ 面试标准回答：**

> "稳定排序的核心定义是 **'相等元素的相对位置不变'**。
> **稳定的**：冒泡、插入、归并、计数、桶、基数。
> **不稳定的**：选择、希尔、快排、堆排。
> 记忆方法：**'选希快堆' 不稳定，其他都稳定。**
> 不稳定的本质都是**'远距离交换'**——选择排序找最小值交换可能跨越相等元素，快排 partition 同理，堆排堆顶下沉同理。"

**为什么稳定性重要？**

- **多字段排序**：先按部门排，再按薪资排，要保证同部门内薪资排完不破坏部门顺序
- **数据库 ORDER BY 多列**：要求稳定
- **音视频时间戳**：相同 PTS 的多个 packet 要保持原顺序（如交错的音视频帧）

**👨‍💻 面试官追问：**

> Q: 怎么把不稳定的排序"变"稳定？
> A: 给每个元素加一个原始下标 idx，相等时按 idx 比较。本质是把"稳定性"问题转成"完全严格序"问题。

#### 考点 5：非比较排序：计数/桶/基数

**考察意图：** 看你知不知道 O(n) 排序的存在条件——**不依赖比较**。

**底层原理：**
比较排序的理论下界是 O(n log n)（决策树高度证明）。要突破必须不比较 → 用数据本身的特性（如整数范围、字符位数）。

**🗣️ 面试标准回答：**

> "三种非比较排序：
>
> 1. **计数排序**：开一个大小为 max-min+1 的数组统计频次，再依次写回。要求**整数 + 范围 k 不大**（k 是 max-min）。时空都是 O(n+k)。
> 2. **桶排序**：把数据划分到若干桶里，桶内排序后合并。要求**数据均匀分布**（不均匀退化到 O(n²)）。
> 3. **基数排序**：按位排序（个位→十位→百位...），每位用计数排序。要求**定长整数或定长字符串**。复杂度 O(n·d)，d 是位数。
>
> 注意：这三个都不是真的 O(n)，是 O(n + 别的)。当 k 或 d 很大时反而比 O(n log n) 慢。"

**经典适用场景：**

- 计数排序：成绩排序（0-100 分）、年龄排序、字符频次
- 桶排序：浮点数 [0,1) 排序、统计直方图
- 基数排序：手机号排序、IP 地址排序、有限位数整数

**👨‍💻 面试官追问：**

> Q: LSD（低位优先）和 MSD（高位优先）基数排序的区别？
> A: LSD 从最低位开始排，需要稳定子排序；MSD 从最高位开始排，类似分桶递归。LSD 实现简单，MSD 适合处理变长字符串。

#### 考点 6：工业级实现：std::sort / qsort / Java sort 到底是什么？

**考察意图：** 看你有没有真的读过标准库实现，区分新手和有工程经验的人。

**🗣️ 面试标准回答：**

> "工业实现都不是单一算法，而是**混合排序**：
>
> 1. **C++std::sort（GCC libstdc++）**：**Introsort**（内省排序）
>   - 主体快排（三数取中选 pivot）
>   - 递归深度超过 `2*log2(N)` 切换堆排序（防止 O(n²) 退化）
>   - 子区间小于 16 切换插入排序（小数据插入更快）
> 2. **C qsort**：标准没规定，glibc 用归并，BSD/Mac 用快排。**不保证稳定**，慎用。
> 3. **Java Arrays.sort**：基本类型用 **DualPivotQuickSort**（双轴快排，Vladimir Yaroslavskiy 2009），对象类型用 **Timsort**（归并+插入混合，稳定）。
> 4. **Python sorted / list.sort**：**Timsort**（Tim Peters 2002），针对真实数据中常见的"部分有序"做了大量优化，识别 run（已经有序的段）直接合并。
> 5. **C++ std::stable_sort**：归并（要求稳定），但用 in-place merge 减少空间。"

**👨‍💻 面试官追问：**

> Q1: 为什么小数组用插入排序而不是冒泡？
> A: 插入排序对于小数据**常数极小**（连续内存、缓存友好、比较次数少）。冒泡每轮都要走到底，比较和交换次数都多。
> Q2: 双轴快排比单轴快多少？
> A: 实测约 10-20% 性能提升。原理是把数据分成三段（< p1、p1~p2、> p2），减少递归深度。
> Q3: Timsort 为什么对"部分有序"快？
> A: 它先识别已有序的 run（如 `[1,2,3,7,8,2,4]` 中前 5 个是 run），然后只对 run 之间归并，复杂度从 O(n log n) 接近 O(n)。

> 看到'三种值分类'（如 0/1/2、红白蓝）想三路 partition。
> 看到'分组排序'、'部分有序'想计数排序或桶排序。"

### ⛳ 项目实战话术（STAR 法则版）

> 面试官追问"你项目里哪里用过排序？"

**话术 A（自动剪辑 - 多关键帧索引归并排序）：**

> **S**：自动剪辑要支持多视频源拼接，每个源都有自己的关键帧索引数组（`AVStream->index_entries`，按 PTS 升序）。我需要把 N 个源的所有关键帧时间戳合并成一个全局有序数组，用于 Smart Seek 决策。
>
> **T**：N 通常 3-8 个，每个数组几百到几千个元素。
>
> **A**：用 **K 路归并 + 最小堆**：把每个数组的首元素入堆（带源 ID），每次取堆顶（最小 PTS）写入结果，然后该源的下一个元素入堆。本质就是 `priority_queue<pair<int64_t, int>>`（PTS, source_id）。
>
> **R**：时间复杂度 O(M log K)，M 是总元素数。直接 `std::sort` 全合并是 O(M log M)，K 路归并利用了"每个子数组已有序"的特性，K=4 时性能差约 2 倍。

**话术 B（车载预览 - 抖动滑窗 Top-K）：**

> 见考点 3 实战补充。AJB 里维护最近 100 帧抖动的 Top-10，触发降级阈值。`priority_queue` 容量限制 10，O(n log 10) ≈ O(n)。

### 🚧 雷区与加分项

**❌ 雷区（千万别犯）：**

- `mid = (left + right) / 2` → **整数溢出！** 应写 `mid = left + (right - left) / 2`
- 快排 partition 写错边界（i j 越界）—— 字节最爱卡这个
- 说"std::sort 就是快排" → 错，是 introsort
- 说"堆排序建堆 O(n log n)" → 错，是 O(n)
- 说快排稳定 → 错
- 写完不验证空数组 `[]`、单元素 `[1]`、全相同 `[2,2,2]`、已有序 `[1,2,3]`、逆序 `[3,2,1]` 五种边界

**✅ 加分项（说出来加分）：**

- 主动提"我用 `left + (right-left)/2` 防溢出"
- 主动提 introsort 的递归深度切换条件 `2*log2(N)`
- 主动提 Timsort 的 run 识别优化
- 用快慢指针实现链表归并（不需要额外数组）
- 提到 **稳定性是排序算法的"政治正确"，工业实现 99% 是稳定的**（Timsort、stable_sort）
- 提到 **缓存友好性**：数组归并比链表归并快 5-10 倍，纯粹因为 cache locality
- 主动写测试用例覆盖 5 种边界

## 📚 第二部分：原理深讲（吃透底层）

### 1. 基础概念与分类

#### 1.1 排序算法的五个维度


| 维度           | 含义                   | 例子                       |
| ------------ | -------------------- | ------------------------ |
| **稳定性**      | 相等元素相对位置不变           | 归并稳定，快排不稳定               |
| **原地性**      | 额外空间 O(1) 或 O(log n) | 快排原地，归并非原地               |
| **比较性**      | 是否依赖元素比较             | 比较排序下界 O(n log n)，非比较可突破 |
| **内部 vs 外部** | 全部数据是否能放入内存          | 内部用快排，外部用归并              |
| **自适应性**     | 部分有序时性能是否提升          | Timsort 自适应，普通归并不自适应     |


#### 1.2 比较排序的理论下界证明

**结论**：基于比较的排序最坏情况至少 O(n log n)。

**证明（决策树模型）**：

- n 个元素有 n! 种排列
- 每次比较产生 1 bit 信息（< 或 >）
- 需要至少 `⌈log₂(n!)⌉` 次比较才能区分所有排列
- 由 Stirling 公式：`log₂(n!) ≈ n log₂ n - n log₂ e ≈ O(n log n)`

**这就是为什么计数/桶/基数能突破 O(n log n) ——它们不做比较，用数据本身的范围信息直接定位。**

### 2. 各算法原理深讲

#### 2.1 冒泡排序：被低估的"已有序检测"

```cpp
void bubbleSort(vector<int>& nums) {
    int n = nums.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (nums[j] > nums[j+1]) {
                swap(nums[j], nums[j+1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // 已有序，提前退出
    }
}
```

**亮点**：加 `swapped` 标志后，**最好情况 O(n)**（已有序）。
**为什么实际不用**：常数大，比较次数多。

#### 2.2 选择排序：交换次数最少

每轮选最小值放到前面。比较次数 O(n²)，但**交换次数仅 O(n)**。
**应用**：当 swap 成本极高时（比如要交换大对象且没有 move 语义），选择排序反而合适。

#### 2.3 插入排序：小数组之王

```cpp
void insertionSort(vector<int>& nums) {
    for (int i = 1; i < nums.size(); i++) {
        int cur = nums[i];
        int j = i - 1;
        while (j >= 0 && nums[j] > cur) {
            nums[j+1] = nums[j];   // 用赋值而不是 swap（少 2/3 写）
            j--;
        }
        nums[j+1] = cur;
    }
}
```

**为什么小数组快**：

- 内存连续访问，缓存命中率高
- 比较+赋值都极轻
- 已有序时 O(n)（自适应）
- introsort 和 Timsort 在子区间 < 16 时都切到插入排序

#### 2.4 快速排序：introsort 实现剖析

```cpp
// 简化版 introsort
void introsort(vector<int>& nums, int left, int right, int depthLimit) {
    while (right - left > 16) {                 // 小区间退化到插入排序
        if (depthLimit == 0) {                  // 深度过大切堆排
            heapSortRange(nums, left, right);
            return;
        }
        depthLimit--;
        int partitionIndex = partition(nums, left, right);
        introsort(nums, partitionIndex + 1, right, depthLimit); // 递归大的一边
        right = partitionIndex;                 // 尾递归处理小的一边（省栈）
    }
    insertionSortRange(nums, left, right);
}
void sort(vector<int>& nums) {
    int depthLimit = 2 * log2(nums.size());
    introsort(nums, 0, nums.size() - 1, depthLimit);
}
```

**三大优化**：

1. **三数取中选 pivot**：取 `nums[left]`、`nums[mid]`、`nums[right]` 的中位数，避开已有序最坏情况
2. **深度兜底切堆排**：保证最坏 O(n log n)
3. **小区间切插入**：常数优化

#### 2.5 归并排序：链表版的精妙

```cpp
// LeetCode 148: 链表归并排序
ListNode* mergeSort(ListNode* head) {
    if (!head || !head->next) return head;
    // 快慢指针找中点
    ListNode *slow = head, *fast = head->next;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    ListNode* mid = slow->next;
    slow->next = nullptr;        // 切断
    return merge(mergeSort(head), mergeSort(mid));
}
ListNode* merge(ListNode* l1, ListNode* l2) {
    ListNode dummy(0), *tail = &dummy;
    while (l1 && l2) {
        if (l1->val <= l2->val) { tail->next = l1; l1 = l1->next; }
        else                     { tail->next = l2; l2 = l2->next; }
        tail = tail->next;
    }
    tail->next = l1 ? l1 : l2;
    return dummy.next;
}
```

**亮点**：

- **空间 O(1)**：不需要拷贝数据，只改指针
- 唯一的额外空间是**递归栈 O(log n)**

#### 2.6 堆排序：建堆的数学魔法

**建堆 O(n) 证明**：

从最后一个非叶子节点开始向下 heapify，第 i 层节点最多下沉 `h-i` 次（h 是树高）。

```
总操作数 = Σ (该层节点数 × 该层最大下沉距离)
        = Σ (n/2^(i+1)) × i     (i 从 0 到 h)
```

这个级数收敛到 O(n)（用错位相减或求导证明）。

**直观理解**：底层节点最多，但下沉距离短；顶层节点下沉距离长，但只有 1 个。两者乘积是常数级。

#### 2.7 计数 / 桶 / 基数：突破 O(n log n) 的代价

**计数排序伪代码**：

```cpp
void countingSort(vector<int>& nums) {
    int mx = *max_element(nums.begin(), nums.end());
    int mn = *min_element(nums.begin(), nums.end());
    vector<int> cnt(mx - mn + 1, 0);
    for (int x : nums) cnt[x - mn]++;
    int idx = 0;
    for (int i = 0; i < cnt.size(); i++)
        while (cnt[i]--) nums[idx++] = i + mn;
}
```

**代价分析**：

- 空间 O(k)：当 k=10⁹ 时，1GB 内存才能装下，完全不可行
- 整数限制：浮点数无法做 cnt 数组
- 所以工业上很少单独用，常作为基数排序的子步骤

### 3. 工业级排序实现源码剖析

#### 3.1 GCC libstdc++ std::sort

```cpp
// libstdc++ 简化伪代码
template <class It, class Compare>
void __sort(It first, It last, Compare comp) {
    if (first != last) {
        __introsort_loop(first, last, __lg(last - first) * 2, comp);
        __final_insertion_sort(first, last, comp);
    }
}
// __lg 是 log2 的近似实现（用 __builtin_clz 加速）
```

关键点：

- `__introsort_loop` 处理 > 16 的区间
- 退出后整体走一次插入排序（因为前面留下了"接近有序"的小段）
- 这一次最终插入排序是 introsort 的灵魂——不分别处理每个小段，而是一次扫完

#### 3.2 Python Timsort 核心思想

```python
# 简化伪代码
def timsort(arr):
    runs = identify_runs(arr)      # 找出已有序的段（升序或降序）
    stack = []
    for run in runs:
        stack.append(run)
        while should_merge(stack):  # 满足某些大小不变量时合并
            merge_top_two(stack)
    while len(stack) > 1:
        merge_top_two(stack)
```

**为什么对真实数据快**：日志、数据库记录、监控数据等真实数据中 70%+ 是部分有序的，Timsort 能直接识别 run 跳过排序。

### 4. 性能与典型陷阱

#### 4.1 性能 Benchmark（10⁶ 随机整数，单线程）


| 算法                       | 时间 (ms) | 备注                                |
| ------------------------ | ------- | --------------------------------- |
| std::sort (introsort)    | ~80     | 通用最快                              |
| std::stable_sort (merge) | ~130    | 稳定，慢 60%                          |
| Python sorted (Timsort)  | ~180    | 算上解释器开销                           |
| 手写快排                     | ~120    | 比 std::sort 慢，因为没有完整 introsort 优化 |
| 手写归并                     | ~150    | 慢于 std::sort，因为有额外内存分配            |
| 手写堆排                     | ~250    | 缓存不友好（堆操作随机跳跃）                    |
| qsort (libc)             | ~200    | 慢，因为通过函数指针调用比较函数                  |


**关键启示**：

- **缓存友好性 > 复杂度优化**：堆排和快排都是 O(n log n)，但快排快 2 倍，纯粹因为内存访问模式
- **函数指针 vs 模板**：qsort 用函数指针无法内联，比 std::sort 慢 2-3 倍

### 5. 实战代码：手撕 Top-K（字节真题）

LeetCode 215：数组中的第 K 个最大元素。要求 O(n) 平均。

**方法 1：最小堆 O(n log K)**

```cpp
int findKthLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> minHeap;
    for (int x : nums) {
        minHeap.push(x);
        if (minHeap.size() > k) minHeap.pop();
    }
    return minHeap.top();
}
```

**方法 2：quickselect O(n) 平均**

```cpp
int quickselect(vector<int>& nums, int left, int right, int k) {
    if (left == right) return nums[left];
    int pivot = nums[left + rand() % (right - left + 1)];  // 随机化 pivot
    int i = left - 1, j = right + 1;
    while (i < j) {
        do i++; while (nums[i] < pivot);
        do j--; while (nums[j] > pivot);
        if (i < j) swap(nums[i], nums[j]);
    }
    if (k <= j) return quickselect(nums, left, j, k);
    else        return quickselect(nums, j + 1, right, k);
}
int findKthLargest(vector<int>& nums, int k) {
    return quickselect(nums, 0, nums.size() - 1, nums.size() - k);
}
```

**为什么 quickselect 是 O(n)？**

- 期望情况下每次 partition 后只递归一边，T(n) = T(n/2) + O(n) = O(n)
- 最坏 O(n²)，但随机化 pivot 后概率极低

### 6. 进阶问题与延伸

#### 6.1 外部排序

**场景**：100GB 文件，内存只有 8GB，如何排序？

**方案**：

1. **分块**：每次读 1GB 进内存，快排后写回磁盘（共 100 个有序块）
2. **K 路归并**：用最小堆同时打开 100 个文件，逐个取最小写出
3. **优化**：归并时用 buffer 减少 IO（每个文件读 10MB 缓冲）

**MapReduce 本质**就是分布式外排序：Map 阶段分块排序，Reduce 阶段 K 路归并。

#### 6.2 并行排序

- **并行快排**：左右子区间用线程池并行处理。但负载不均衡（左右大小不一）
- **样本排序 Sample Sort**：先采样选 K-1 个 pivot 切成 K 段，K 线程并行排各段
- **GPU 排序**：bitonic sort（O(n log²n) 但完全并行）、radix sort on GPU

**音视频应用**：FFmpeg 的 `-threads N` 在多帧并行编码时，每个线程独立处理一个 GOP，最后按 PTS 排序输出——本质是 K 路归并。

#### 6.3 字节专项延伸

- **桶排序应用**：Top-K URL 频次统计（先 hash 分桶，桶内排序）
- **数据流中位数**（LC 295）：两个堆（大顶 + 小顶）维护
- **滑动窗口最大值**（LC 239）：单调队列（不是排序但常考）
- **数组中第 K 大**多种解法对比：快选 / 堆 / 计数（值范围小时）
