# 二分查找：从基础到进阶（面试速记与原理详解）

> **适用方向**：算法面试必考、C++ 基础、日常业务逻辑优化
> **难度**：⭐⭐⭐⭐
> **核心心法**：二分的本质不是“单调性”，而是“边界的划分”。

---

## 第一部分：二分查找的本质与基础模板

### 1. 什么是二分查找？
二分查找（Binary Search）就像是经典的“猜数字”游戏。假设我知道一个 1 到 100 之间的数字，你每次猜一个数，我只告诉你“猜大了”还是“猜小了”。如果你每次都猜中间的数，最多只需要 7 次就能猜中。

**适用条件**：
1. **目标具有单调性**（或者可以说存在一个明确的分界线）。
2. **支持随机访问**（通常是数组，链表不适合二分）。

**复杂度**：
- 时间复杂度：$O(\log N)$。
- 空间复杂度：$O(1)$。

### 2. 基础模板：寻找精确值
这是最基础的二分查找，用于在一个**严格递增**的数组中寻找某个特定的值。

```cpp
int binarySearch(const vector<int>& nums, int target) {
    int left = 0;
    int right = nums.size() - 1; // 注意：这里是 size - 1

    while (left <= right) { // 注意：这里是 <=
        // 防溢出写法，等同于 (left + right) / 2
        int mid = left + (right - left) / 2; 

        if (nums[mid] == target) {
            return mid; // 找到了，直接返回
        } else if (nums[mid] < target) {
            left = mid + 1; // 目标在右半边
        } else {
            right = mid - 1; // 目标在左半边
        }
    }
    return -1; // 没找到
}
```

#### 🚨 面试常考坑点：
1. **为什么是 `left <= right` 而不是 `<`？**
   因为 `right` 的初始值是 `nums.size() - 1`，即最后一个元素的索引。当 `left == right` 时，这个区间内还有一个元素没有被检查。如果用 `<`，就会漏掉这最后一个元素。
2. **为什么是 `mid = left + (right - left) / 2`？**
   如果写成 `(left + right) / 2`，当 `left` 和 `right` 都非常大（接近 `INT_MAX`）时，两数相加会导致整型溢出，变成负数。

## 第二部分：进阶模板（寻找边界）

在实际面试中，数组里往往有**重复元素**，面试官通常会让你找：
- 第一个 `>= target` 的元素（C++ 中的 `std::lower_bound`）
- 第一个 `> target` 的元素（C++ 中的 `std::upper_bound`）
- 最后一个 `<= target` 的元素

这时候基础模板就不管用了，我们需要**边界二分模板**。

### 1. 寻找左边界（第一个 >= target 的位置）
**核心思想**：当 `nums[mid] == target` 时，不要立即返回，而是**收缩右边界**（`right = mid`），继续向左逼近。

```cpp
int lowerBound(const vector<int>& nums, int target) {
    int left = 0;
    int right = nums.size(); // 注意：这里是 size，不是 size - 1

    while (left < right) { // 注意：这里是 <
        int mid = left + (right - left) / 2;
        
        if (nums[mid] >= target) {
            right = mid; // 目标在左半边或就是 mid，所以 right = mid
        } else {
            left = mid + 1; // 目标在右半边，mid 肯定不是，所以 left = mid + 1
        }
    }
    // 循环结束时 left == right
    return left; 
}
```
*注：如果返回值等于 `nums.size()`，说明数组中所有元素都小于 `target`。*

### 2. 寻找右边界（第一个 > target 的位置）
**核心思想**：当 `nums[mid] == target` 时，说明大于 `target` 的值还在右边，所以要**收缩左边界**（`left = mid + 1`）。

```cpp
int upperBound(const vector<int>& nums, int target) {
    int left = 0;
    int right = nums.size();

    while (left < right) {
        int mid = left + (right - left) / 2;
        
        if (nums[mid] > target) {
            right = mid; // 目标在左半边或就是 mid
        } else {
            left = mid + 1; // nums[mid] <= target，目标在右半边
        }
    }
    return left;
}
```

> **💡 巧记口诀**：
> - 找左边界（`>=`）：条件写 `>=`，满足时 `right = mid`。
> - 找右边界（`>`）：条件写 `>`，满足时 `right = mid`。
> - 只要写了 `right = mid`，循环条件就必须是 `left < right`，且 `right` 初始值为 `size`。

## 第三部分：高阶应用（局部有序与峰值）

二分的本质不是“单调性”，而是**“能否找到一个条件，将数组一分为二，并且确定目标在哪一半”**。

### 1. 搜索旋转排序数组（LeetCode 33）
**题目**：一个有序数组在某个点被旋转了（例如 `[0,1,2,4,5,6,7]` 变成了 `[4,5,6,7,0,1,2]`），在其中找 `target`。
**思路**：虽然整体无序，但从中间切开，**必定有一半是严格有序的**。

```cpp
int searchRotated(vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;

        // 判断哪一半是有序的
        if (nums[left] <= nums[mid]) { 
            // 左半边有序
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1; // target 在左半边范围内
            } else {
                left = mid + 1;  // 否则去右半边找
            }
        } else { 
            // 右半边有序
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1;  // target 在右半边范围内
            } else {
                right = mid - 1; // 否则去左半边找
            }
        }
    }
    return -1;
}
```

### 2. 寻找峰值（LeetCode 162）
**题目**：数组中任意相邻元素不相等，找到任意一个峰值（大于左右相邻元素的值）。
**思路**：比较 `nums[mid]` 和 `nums[mid+1]`。
- 如果 `nums[mid] < nums[mid+1]`，说明处于上坡，峰值一定在右边（`left = mid + 1`）。
- 如果 `nums[mid] > nums[mid+1]`，说明处于下坡，峰值一定在左边或就是 mid（`right = mid`）。

```cpp
int findPeakElement(vector<int>& nums) {
    int left = 0, right = nums.size() - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < nums[mid + 1]) {
            left = mid + 1; // 上坡，峰在右
        } else {
            right = mid;    // 下坡，峰在左（含当前）
        }
    }
    return left; // 最终 left == right，指向峰值
}
```

## 第四部分：终极杀器 —— 二分答案（Binary Search on Answer）

在很多困难级别的算法题中，题目并没有给你一个明确的数组去查找，而是让你求**“最大值中的最小值”**或**“最小值中的最大值”**。

**核心特征**：
1. 答案存在一个明确的上下界 `[left, right]`。
2. 答案具有单调性：如果 `x` 满足条件，那么 `>x`（或 `<x`）也一定满足条件。

**解题套路**：
把求最优解的问题，转化为**“判定问题”**（写一个 `check(mid)` 函数）。

### 经典例题：爱吃香蕉的珂珂（LeetCode 875）
**题目**：有 N 堆香蕉，珂珂要在 H 小时内吃完。求她吃香蕉的最小速度 K（根/小时）。
**思路**：
- 速度 K 的范围是 `[1, 数组中的最大值]`。
- 如果速度为 `mid` 时能在 H 小时内吃完，说明 `mid` 是一个合法解，但我们想找更小的（求左边界），所以 `right = mid`。
- 如果吃不完，说明速度太慢，`left = mid + 1`。

```cpp
// 判定函数：以 speed 的速度，能否在 h 小时内吃完？
bool check(const vector<int>& piles, int speed, int h) {
    int time = 0;
    for (int pile : piles) {
        // 向上取整：(pile + speed - 1) / speed
        time += (pile + speed - 1) / speed; 
    }
    return time <= h;
}

int minEatingSpeed(vector<int>& piles, int h) {
    int left = 1;
    int right = *max_element(piles.begin(), piles.end());

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (check(piles, mid, h)) {
            right = mid; // 能吃完，尝试更小的速度
        } else {
            left = mid + 1; // 吃不完，必须加快速度
        }
    }
    return left;
}
```

## 总结与避坑指南

1. **死循环问题**：如果你写了 `left = mid`，那么计算 mid 时必须向上取整 `mid = left + (right - left + 1) / 2`，否则在 `left` 和 `right` 相邻时会陷入死循环。推荐尽量使用 `right = mid` 和 `left = mid + 1` 的组合，这样默认向下取整即可。
2. **溢出问题**：永远使用 `left + (right - left) / 2` 计算中点。
3. **C++ STL 捷径**：
   - `std::lower_bound(begin, end, target)`：返回第一个 `>= target` 的迭代器。
   - `std::upper_bound(begin, end, target)`：返回第一个 `> target` 的迭代器。
   - 如果要找最后一个 `<= target` 的元素，可以用 `upper_bound` 找到后，将迭代器往前退一格（`--it`）。
