# 归并排序（Merge Sort）原理深度图解与面试速记

归并排序是面试中极其重要的高频考点。它不仅是**分治思想（Divide and Conquer）**的完美体现，更是解决“逆序对”等经典算法题的唯一解法。同时，它常被面试官拿来与快速排序（Quick Sort）进行全方位对比。

---

## 💡 面试高频问题与标准口语化回答（可直接背诵）

### Q1：简单介绍一下归并排序的核心思想？（附详细原理拆解）

🗣️ **口语化回答**：“归并排序的核心思想就是**分治法（Divide and Conquer）**。
它的过程分为两步：‘分（Divide）’和‘治（Merge）’。

**1. 怎么‘分’？（自顶向下劈开）**
假设我们有一个无序的数组 `[8, 4, 5, 7, 1, 3, 6, 2]`。

- 第一次劈开：变成左边 `[8, 4, 5, 7]` 和右边 `[1, 3, 6, 2]`。
- 第二次劈开：左边继续劈成 `[8, 4]` 和 `[5, 7]`，右边劈成 `[1, 3]` 和 `[6, 2]`。
- 第三次劈开：一直劈到每个小数组里**只剩下一个元素**（比如 `[8]`, `[4]`, `[5]`...）。
**为什么要劈到只剩一个元素？** 因为在算法的逻辑里，一个元素的数组，天然就是**有序**的！这就是我们递归的终止条件。

**2. 怎么‘治’（归并）？（自底向上合并）**
现在我们手里全是只有 1 个元素的有序小数组了，接下来开始两两合并。

- 第一次合并：`[8]` 和 `[4]` 合并成有序的 `[4, 8]`；`[5]` 和 `[7]` 合并成有序的 `[5, 7]`。
- 第二次合并：把刚才合并好的 `[4, 8]` 和 `[5, 7]` 再次合并。我们准备一个临时数组，用两个指针分别指着两个数组的开头，谁小就把谁拿出来放进临时数组。这样就得到了有序的 `[4, 5, 7, 8]`。
- 最后一次合并：左半边 `[4, 5, 7, 8]` 和右半边 `[1, 2, 3, 6]` 进行终极合并，得到最终完全有序的 `[1, 2, 3, 4, 5, 6, 7, 8]`。

一句话总结：**一直往下劈，直到只剩一个元素；然后再两两往上合并，合并的过程中顺手排好序。**”

### Q2：归并排序的时间、空间复杂度是多少？它是稳定的吗？

🗣️ **口语化回答**：“归并排序的时间复杂度非常稳定，不管是最好、最坏还是平均情况，都是 **$O(N \log N)$**。因为劈分数组的深度是 $\log N$，每一层合并的开销是 $O(N)$。
它的空间复杂度是 **$O(N)$**，因为在合并的时候，我们需要开辟一个和原数组一样大的临时数组来存放排序好的数据。
它是**稳定排序**。因为在合并两个有序数组时，如果遇到相等的元素，我们总是优先把左边数组的元素放进去，这就保证了相等元素的相对顺序不会改变。”

### Q3：归并排序和快速排序（Quick Sort）有什么区别？实际工程中怎么选？

🗣️ **口语化回答**：“它们俩都是分治法，时间复杂度都是 $O(N \log N)$，但有三个核心区别：

1. **稳定性**：归并是稳定的，快排是不稳定的。
2. **空间开销**：归并需要 $O(N)$ 的额外空间，快排是原地排序，空间复杂度是 $O(\log N)$（递归栈）。
3. **缓存命中率（常数项）**：快排在原数组上用双指针交换，对 CPU 缓存（Cache）极其友好；而归并需要在原数组和临时数组之间来回拷贝数据，常数项比快排大。

**工程选择**：在内存充足且要求稳定的场景（比如 Java/Python 对对象数组的排序），通常用归并（或 Timsort）；在基本数据类型排序、追求极致速度且不在乎稳定性的场景（比如 C++ 的 `std::sort`），通常用快排。”

## 💻 代码实战与细节避坑

归并排序的代码非常经典，面试时经常要求手写。核心在于 `merge` 合并逻辑。

```cpp
#include <iostream>
#include <vector>

using namespace std;

// 合并两个有序区间的核心函数
void merge(vector<int>& arr, int left, int mid, int right, vector<int>& temp) {
    int i = left;      // 左半边数组的起始指针
    int j = mid + 1;   // 右半边数组的起始指针
    int t = 0;         // 临时数组的指针

    // 1. 两个指针比较，谁小就把谁放进临时数组
    while (i <= mid && j <= right) {
        // ⚠️ 极其重要的避坑点：这里必须是 <=，不能是 < 
        // 只有加上 =，才能保证左边相等的元素先放进去，从而保证排序的【稳定性】！
        if (arr[i] <= arr[j]) {
            temp[t++] = arr[i++];
        } else {
            temp[t++] = arr[j++];
        }
    }

    // 2. 如果左边还有剩余，全部直接塞进临时数组
    while (i <= mid) {
        temp[t++] = arr[i++];
    }

    // 3. 如果右边还有剩余，全部直接塞进临时数组
    while (j <= right) {
        temp[t++] = arr[j++];
    }

    // 4. 把临时数组排好序的数据，拷贝回原数组对应的区间
    t = 0;
    while (left <= right) {
        arr[left++] = temp[t++];
    }
}

// 递归分治函数
void mergeSort(vector<int>& arr, int left, int right, vector<int>& temp) {
    if (left >= right) return; // 递归终止条件：区间里只有一个元素或为空

    int mid = left + (right - left) / 2; // 防溢出的写法

    // 1. 分：递归劈分左半边
    mergeSort(arr, left, mid, temp);
    // 2. 分：递归劈分右半边
    mergeSort(arr, mid + 1, right, temp);
    
    // 3. 治：合并两个有序的半边
    merge(arr, left, mid, right, temp);
}

// 提供给外部调用的接口
void sortArray(vector<int>& arr) {
    if (arr.empty()) return;
    // ⚠️ 优化点：临时数组 temp 在最外层一次性开辟好，传引用进去。
    // 千万不要在 merge 函数里面每次都 new 一个新数组，那样会导致频繁的内存分配，极度拖慢性能！
    vector<int> temp(arr.size()); 
    mergeSort(arr, 0, arr.size() - 1, temp);
}
```

## 🔥 极限深挖拷问（区分度极高的进阶题）

### 深挖 1：如果在 `merge` 函数里每次都 `new` 一个临时数组，会有什么后果？

> 面试绝杀回答：“这是新手最容易犯的致命错误！归并排序的递归深度是 $\log N$，总共会发生 $O(N)$ 次合并操作。如果在每次 `merge` 时都去 `new` 一个局部数组，会导致极其频繁的堆内存分配和释放。
> 内存分配（`malloc/new`）是一个非常耗时的系统调用，这会把归并排序的常数项拉得无限大，导致实际运行速度比 $O(N^2)$ 的插入排序还要慢！
> **标准做法**：在最外层一次性开辟一个大小为 $N$ 的临时数组，然后把引用（或指针）一路传进递归函数里复用。”

### 深挖 2：什么是“外部排序”？为什么处理海量数据（如 100GB 数据，只有 1GB 内存）必须用归并排序？

> 面试绝杀回答：“当数据量远大于内存容量时，数据只能存在硬盘上，无法一次性读入内存用快排，这时候就必须用**外部排序（External Sorting）**，而外部排序的核心就是归并。
> **具体流程**：
>
> 1. 先把 100GB 的大文件，切分成 100 个 1GB 的小文件。
> 2. 把每个 1GB 的小文件读入内存，用快速排序排好序，再写回硬盘。现在我们有了 100 个内部有序的小文件。
> 3. 利用**多路归并**的思想。在内存里开辟 100 个输入缓冲区和 1 个输出缓冲区。从 100 个文件里各读入第一块数据，用**小根堆（优先队列）**找出最小的元素，写到输出缓冲区。
> 4. 哪个文件的元素被挑走了，就从硬盘继续读那个文件的下一个元素。直到所有文件都被合并完。
>
> 归并排序天然适合这种**顺序读取**的磁盘 I/O 场景。”

### 深挖 3：经典算法题——如何用归并排序求“逆序对”？（剑指 Offer 51）

> 面试绝杀回答：“逆序对问题（即前面的数字大于后面的数字）是归并排序最经典的变种应用。
> 核心逻辑在 `merge` 合并阶段：当我们比较左半边数组的 `arr[i]` 和右半边数组的 `arr[j]` 时。
> 如果 `arr[i] <= arr[j]`，正常放入临时数组，不产生逆序对。
> **关键点来了**：如果 `arr[i] > arr[j]`，说明左边当前的元素，比右边当前的元素大。因为左半边数组**已经是有序的**，这意味着左半边从 `i` 开始，一直到 `mid` 的所有元素，**都大于** `arr[j]`！
> 所以，此时产生逆序对的数量不是 1 个，而是 `mid - i + 1` 个！我们只需要在把 `arr[j]` 放入临时数组的同时，累加 `count += (mid - i + 1)` 即可。
> 这样在一次完整的归并排序后，就能以 $O(N \log N)$ 的时间复杂度求出所有的逆序对。”
