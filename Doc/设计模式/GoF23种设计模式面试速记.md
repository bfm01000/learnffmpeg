# GoF 23 种经典设计模式：面试速记与常问问题

GoF 23 种设计模式来自《Design Patterns: Elements of Reusable Object-Oriented Software》，主要解决面向对象设计中的三类问题：**对象怎么创建、对象之间怎么组合、对象之间怎么通信与协作**。

面试里不要求你把 23 个都背成八股，更重要的是：**能说清楚每个模式解决什么问题、适合什么场景、和相似模式有什么区别、在项目里怎么用过**。

---

## 一、 面试速记：三大类

GoF 23 种设计模式分成三类：

| 分类 | 关注点 | 包含模式 |
| :--- | :--- | :--- |
| **创建型模式** | 对象怎么创建 | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型模式** | 类/对象怎么组合 | 适配器、桥接、组合、装饰器、外观、享元、代理 |
| **行为型模式** | 对象之间怎么协作 | 责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 |

一句话记忆：

> **创建型管“怎么 new”，结构型管“怎么组装”，行为型管“怎么协作”。**

---

## 二、 创建型模式（5 个）

### 1. 单例模式 Singleton（高频）

**核心作用：** 保证一个类全局只有一个实例，并提供统一访问点。

**常见场景：**
*   日志系统
*   全局配置
*   设备能力缓存
*   线程池管理器

**面试常问：**
*   **C++ 如何实现线程安全单例？**  
    C++11 后优先用 Meyers Singleton，也就是函数内局部静态变量：`static Singleton instance;`，标准保证初始化线程安全。
*   **Meyers Singleton 是什么？**  
    用函数内 `static` 局部变量实现的懒加载单例，第一次调用时创建，后续返回同一个对象。
*   **Java DCL 为什么要加 `volatile`？**  
    防止 `new` 对象时发生“引用先赋值、构造还没完成”的指令重排序，同时保证线程间可见性。
*   **单例模式有什么缺点？**  
    容易隐藏依赖、影响测试、造成全局状态污染；不适合带业务状态、可能多实例的对象。

**一句话回答：**
> “单例适合进程级唯一资源，比如日志、配置、能力缓存。C++11 后推荐函数内局部静态变量，线程安全且简单。但单例容易隐藏依赖，不适合滥用到业务对象上。”

---

### 2. 工厂方法模式 Factory Method（高频）

**核心作用：** 定义创建对象的接口，让子类决定创建哪一个具体类。

**常见场景：**
*   根据平台创建不同渲染器
*   根据编码格式创建不同编码器
*   根据协议创建不同推流器

**面试常问：**
*   **简单工厂、工厂方法、抽象工厂有什么区别？**  
    简单工厂用一个 `switch/if` 创建产品；工厂方法让子类工厂创建单个产品；抽象工厂创建一整族相关产品。
*   **工厂模式和策略模式有什么关系？**  
    工厂负责创建策略对象，策略负责封装可替换算法。一个管“创建谁”，一个管“怎么做”。
*   **工厂模式是否违反开闭原则？**  
    简单工厂新增产品通常要改 `switch`，不完全符合；工厂方法和抽象工厂更符合扩展开放，但类数量更多。

**一句话回答：**
> “工厂方法把具体对象创建延迟到子类工厂中，业务代码只依赖抽象接口。它比简单工厂更符合开闭原则，但类数量会增加。”

---

### 3. 抽象工厂模式 Abstract Factory（中高频）

**核心作用：** 创建一整族相关对象，保证它们属于同一产品族。

**常见场景：**
*   Android 硬件后端：硬编 + 硬解 + OpenGL 渲染
*   FFmpeg 软件后端：软编 + 软解 + CPU 渲染
*   不同平台 UI 组件族

**面试常问：**
*   **抽象工厂和工厂方法区别？**  
    工厂方法创建一个产品，抽象工厂创建一族产品，比如同一后端的编码器、解码器、渲染器。
*   **什么是产品族？**  
    一组相互关联、通常要一起使用的对象，比如 Android 硬件 Pipeline 的硬编、硬解、OpenGL 渲染器。
*   **抽象工厂有什么缺点？**  
    新增产品族方便，但新增产品种类麻烦，因为所有具体工厂都要加新创建方法。

**一句话回答：**
> “工厂方法创建一个产品，抽象工厂创建一族产品。比如音视频里一套硬件 Pipeline 可能同时创建编码器、解码器和渲染器，这就适合抽象工厂。”

---

### 4. 建造者模式 Builder（高频）

**核心作用：** 分步骤构建复杂对象，避免超长构造函数，并在 `build()` 阶段统一校验。

**常见场景：**
*   播放器配置
*   推流配置
*   SDK 初始化参数
*   网络请求参数

**面试常问：**
*   **Builder 和构造函数有什么区别？**  
    构造函数适合参数少的对象；Builder 适合参数多、可选项多、需要集中校验的复杂对象。
*   **Builder 和 setter 有什么区别？**  
    setter 会让对象先创建再慢慢修改，容易半初始化；Builder 是先收集参数，`build()` 后生成合法对象。
*   **Builder 和工厂模式区别？**  
    工厂解决“创建哪个类”，Builder 解决“这个类参数太多，怎么配置”。
*   **C++ 里直接写 `struct` 不行吗？**  
    简单内部参数包可以直接 `struct`；如果是对外复杂配置、有必填项和组合约束，Builder 更稳。

**一句话回答：**
> “Builder 适合参数很多、可选项很多、参数之间有约束的复杂配置对象。它解决的是‘这个对象怎么优雅配置’，不是‘创建哪个具体类’。”

---

### 5. 原型模式 Prototype（低频）

**核心作用：** 通过拷贝已有对象来创建新对象，而不是重新构造。

**常见场景：**
*   对象创建成本高
*   需要复制一份相似配置
*   游戏对象、图形对象复制

**面试常问：**
*   **原型模式和拷贝构造有什么关系？**  
    原型模式通常通过 `clone()` 或拷贝构造复制已有对象，本质是“基于已有对象创建新对象”。
*   **深拷贝和浅拷贝区别？**  
    浅拷贝只复制指针值，多个对象可能共享同一资源；深拷贝会复制资源本身，避免悬空和重复释放问题。

**一句话回答：**
> “原型模式适合创建成本高、但已有对象可复用的场景。核心难点不在 clone 本身，而在深拷贝和资源所有权。”

---

## 三、 结构型模式（7 个）

### 1. 适配器模式 Adapter（高频）

**核心作用：** 把一个已有接口转换成调用方期望的接口。

**常见场景：**
*   封装第三方 SDK
*   C 接口包装成 C++ 接口
*   FFmpeg 数据结构适配到业务帧结构

**面试常问：**
*   **适配器和外观模式区别？**  
    适配器解决接口不兼容；外观隐藏复杂子系统，提供简单入口。
*   **类适配器和对象适配器区别？**  
    类适配器靠继承适配，对象适配器靠组合持有被适配对象；工程里对象适配器更灵活。

**一句话回答：**
> “适配器解决接口不兼容问题。比如底层 FFmpeg 返回 `AVFrame`，业务层想要统一的 `VideoFrame`，中间可以用 Adapter 转换。”

---

### 2. 桥接模式 Bridge（中频）

**核心作用：** 把抽象和实现分离，让两边可以独立变化。

**常见场景：**
*   播放器抽象 vs 平台实现
*   渲染接口 vs OpenGL/Vulkan/Metal 实现
*   日志接口 vs 文件/控制台/远端实现

**面试常问：**
*   **桥接和适配器区别？**  
    桥接是设计前期主动拆分两个变化维度；适配器多是已有接口不兼容后的补救。
*   **桥接模式解决什么维度变化？**  
    解决抽象和实现两个维度独立变化，比如播放器抽象和 OpenGL/Vulkan/Metal 渲染后端。

**一句话回答：**
> “桥接模式适合两个维度都可能变化的场景，比如播放器类型会变，底层渲染后端也会变。它通过组合而不是继承，让抽象层和实现层独立演进。”

---

### 3. 组合模式 Composite（中频）

**核心作用：** 用树形结构表示“整体-部分”，让客户端用统一方式处理单个对象和组合对象。

**常见场景：**
*   UI 组件树
*   文件系统目录树
*   滤镜节点树
*   场景图

**面试常问：**
*   **组合模式适合什么结构？**  
    适合树形结构，比如 UI 组件树、目录树、滤镜节点树。
*   **透明式组合和安全式组合区别？**  
    透明式让叶子和组合节点接口完全一致；安全式只让组合节点暴露添加/删除子节点接口，更类型安全。

**一句话回答：**
> “组合模式适合树形结构。它让调用方不用区分叶子节点和组合节点，都通过同一套接口处理。”

---

### 4. 装饰器模式 Decorator（中高频）

**核心作用：** 在不修改原类的情况下，动态给对象增加功能。

**常见场景：**
*   输入流加缓冲、加加密、加压缩
*   视频帧处理链增加水印、滤镜、统计
*   网络请求增加日志、重试、鉴权

**面试常问：**
*   **装饰器和继承有什么区别？**  
    继承是静态扩展，类容易爆炸；装饰器通过组合动态叠加功能，更灵活。
*   **装饰器和代理模式区别？**  
    装饰器重点是增强功能；代理重点是控制访问，比如权限、远程、懒加载。

**一句话回答：**
> “装饰器强调动态叠加功能，比如原始帧处理器外面包一层水印处理、再包一层统计处理。它比继承更灵活，避免类爆炸。”

---

### 5. 外观模式 Facade（高频）

**核心作用：** 给复杂子系统提供一个简单统一入口。

**常见场景：**
*   SDK 对外暴露简单 API
*   播放器隐藏解封装、解码、渲染细节
*   推流器隐藏采集、编码、封装、发送细节

**面试常问：**
*   **外观模式和适配器模式区别？**  
    外观简化复杂系统入口；适配器转换不兼容接口。
*   **外观模式是否只是简单封装？**  
    不只是包一层函数，而是把复杂子系统的依赖、调用顺序、错误处理收敛到统一入口。

**一句话回答：**
> “外观模式不是改接口兼容，而是把复杂子系统收敛成一个简单入口。比如 `LiveEngine.start()` 背后包含采集、编码、封装、推流，但调用方只看到一个简单 API。”

---

### 6. 享元模式 Flyweight（低频）

**核心作用：** 复用大量相同或相似对象，减少内存占用。

**常见场景：**
*   字符对象复用
*   纹理/字体/样式缓存
*   大量小对象共享内部状态

**面试常问：**
*   **内部状态和外部状态是什么？**  
    内部状态可共享，放在享元对象里；外部状态随上下文变化，由调用方传入。
*   **享元和对象池区别？**  
    享元强调共享相同状态减少对象数量；对象池强调复用对象生命周期，减少频繁创建销毁。

**一句话回答：**
> “享元模式通过共享可复用的内部状态减少对象数量。它更偏内存优化，面试频率不如工厂、观察者、策略高。”

---

### 7. 代理模式 Proxy（中高频）

**核心作用：** 用代理对象控制对真实对象的访问。

**常见场景：**
*   远程代理
*   延迟加载
*   权限控制
*   日志统计
*   缓存代理

**面试常问：**
*   **代理和装饰器区别？**  
    代理控制访问，装饰器增强功能；结构相似，但设计意图不同。
*   **静态代理和动态代理区别？**  
    静态代理手写代理类，编译期确定；动态代理运行期生成代理逻辑，常见于 Java 反射/AOP。

**一句话回答：**
> “代理模式重点是控制访问，比如远程调用、权限、懒加载；装饰器重点是增强功能。二者结构像，但意图不同。”

---

## 四、 行为型模式（11 个）

### 1. 责任链模式 Chain of Responsibility（中高频）

**核心作用：** 多个处理器按链式顺序处理请求，当前处理不了就交给下一个。

**常见场景：**
*   日志等级处理
*   网络拦截器
*   参数校验链
*   音视频数据处理链

**面试常问：**
*   **责任链和管线 Pipeline 有什么关系？**  
    都是链式处理；责任链可以中途处理并终止，Pipeline 更强调每个阶段顺序加工数据。
*   **责任链有什么缺点？**  
    链路过长时调试困难，请求可能无人处理，也可能因为顺序不当产生隐蔽 Bug。

**一句话回答：**
> “责任链适合多个处理节点按顺序尝试处理请求，调用方不需要知道最终谁处理。缺点是链太长时调试困难，也可能请求无人处理。”

---

### 2. 命令模式 Command（中频）

**核心作用：** 把请求封装成对象，便于排队、撤销、重做、异步执行。

**常见场景：**
*   UI 操作撤销/重做
*   任务队列
*   线程池任务
*   播放控制命令

**面试常问：**
*   **命令模式和回调/lambda 有什么关系？**  
    命令模式把操作封装成对象；现代 C++ 可以用 `std::function` / lambda 作为轻量命令对象。
*   **命令模式适合什么场景？**  
    适合任务排队、撤销重做、异步执行、日志记录。

**一句话回答：**
> “命令模式把一次操作封装成对象，可以排队、记录、撤销或异步执行。现代 C++ 里很多时候会用 `std::function` 或 lambda 实现轻量命令。”

---

### 3. 解释器模式 Interpreter（低频）

**核心作用：** 定义语言文法，并解释执行表达式。

**常见场景：**
*   简单规则引擎
*   表达式解析
*   DSL

**面试常问：**
*   **解释器模式为什么少用？**  
    只适合简单语法，复杂语法用 parser/编译器工具更靠谱。
*   **和编译器/解析器有什么关系？**  
    它是解释执行简单语法规则的一种面向对象实现，复杂编译器通常不会直接手写 GoF 解释器模式。

**一句话回答：**
> “解释器模式适合简单 DSL 或规则表达式，但复杂语法通常会用成熟 parser 工具，实际面试频率很低。”

---

### 4. 迭代器模式 Iterator（中频）

**核心作用：** 不暴露集合内部结构，提供统一遍历方式。

**常见场景：**
*   STL 迭代器
*   自定义容器遍历
*   树/图结构遍历

**面试常问：**
*   **C++ STL 迭代器属于什么模式？**  
    属于迭代器模式，用统一接口遍历容器而不暴露内部结构。
*   **迭代器失效是什么？**  
    容器插入、删除、扩容后，原迭代器可能不再指向有效元素，继续使用会导致未定义行为。

**一句话回答：**
> “迭代器模式把遍历行为从容器内部抽离出来。C++ STL 的 `begin()` / `end()` 就是典型例子。”

---

### 5. 中介者模式 Mediator（低中频）

**核心作用：** 用一个中介对象协调多个对象之间的复杂交互，避免彼此网状依赖。

**常见场景：**
*   UI 控件协作
*   模块调度中心
*   聊天室

**面试常问：**
*   **中介者和观察者区别？**  
    观察者是一对多通知；中介者集中协调多对象交互，避免对象之间网状依赖。
*   **中介者会不会变成上帝对象？**  
    会，这是主要风险。中介者如果承载太多业务规则，会变成难维护的中心大类。

**一句话回答：**
> “中介者减少对象之间的直接依赖，但风险是中介者本身越来越胖，变成上帝类。”

---

### 6. 备忘录模式 Memento（低频）

**核心作用：** 保存对象某一时刻状态，之后可以恢复。

**常见场景：**
*   撤销/恢复
*   编辑器快照
*   游戏存档

**面试常问：**
*   **备忘录和命令模式如何配合撤销？**  
    命令记录操作，备忘录保存状态快照；撤销时可以反向执行命令或恢复快照。
*   **状态快照太大怎么办？**  
    可以做增量快照、差异记录、限制历史深度，或只保存关键状态。

**一句话回答：**
> “备忘录适合状态回滚，核心是保存快照但不破坏封装。实际工程要注意快照内存成本。”

---

### 7. 观察者模式 Observer（高频）

**核心作用：** 一个对象状态变化时，自动通知多个观察者。

**常见场景：**
*   SDK Listener 回调
*   UI 事件监听
*   播放状态通知
*   网络状态通知

**面试常问：**
*   **观察者和发布-订阅区别？**  
    观察者是对象级直接回调；发布-订阅通过 Broker/Topic 解耦，适合系统级事件。
*   **如何避免内存泄漏？**  
    不让长生命周期 Subject 强持有短生命周期 Observer；可用弱引用、生命周期解绑、失效观察者清理。
*   **多线程 add/remove 如何避免 crash？**  
    列表加锁，通知前局部拷贝，锁外回调，避免遍历时修改容器和死锁。

**一句话回答：**
> “观察者模式适合对象级的一对多通知。音视频 SDK 里底层 C++ 引擎通过 Listener 通知 Java/OC 层状态变化，就是典型观察者模式。重点坑是生命周期和多线程安全。”

---

### 8. 状态模式 State（中频）

**核心作用：** 把对象在不同状态下的不同行为封装到不同状态类中。

**常见场景：**
*   播放器状态：Idle / Preparing / Playing / Paused / Error
*   推流状态：Disconnected / Connecting / Pushing / Reconnecting

**面试常问：**
*   **状态模式和策略模式区别？**  
    策略由外部选择算法；状态由对象内部状态迁移驱动行为变化。
*   **状态机怎么设计？**  
    明确定义状态、事件、转移条件和动作，避免散落的大量 `if-else`。

**一句话回答：**
> “状态模式适合状态多、状态切换复杂、每个状态行为不同的对象。它把大段 `if (state)` 拆到状态类里。”

---

### 9. 策略模式 Strategy（高频）

**核心作用：** 把一组算法或策略封装起来，让它们可以互相替换。

**常见场景：**
*   软编/硬编策略
*   不同码率控制策略
*   不同丢帧策略
*   不同 Seek 策略

**面试常问：**
*   **策略模式和状态模式区别？**  
    策略之间通常独立替换；状态之间有生命周期和迁移关系。
*   **策略模式和工厂模式如何配合？**  
    工厂根据配置/能力创建具体策略，业务方通过策略接口调用。
*   **如何避免大量 if-else？**  
    抽象策略接口，把不同算法封装成策略类，通过工厂或配置选择。

**一句话回答：**
> “策略模式解决的是算法可替换问题。比如硬编策略和软编策略都实现同一个 `VideoEncoder` 接口，运行时根据机型能力选择不同策略。”

---

### 10. 模板方法模式 Template Method（中高频）

**核心作用：** 父类定义算法骨架，子类实现某些步骤。

**常见场景：**
*   SDK 初始化流程
*   编解码流程骨架
*   测试框架生命周期

**面试常问：**
*   **模板方法和策略模式区别？**  
    模板方法靠继承复用流程骨架；策略靠组合替换算法。
*   **继承方式有什么缺点？**  
    耦合更强，父类变化影响子类；子类过多时层级复杂，不如组合灵活。

**一句话回答：**
> “模板方法是通过继承复用流程骨架，策略模式是通过组合替换算法。模板方法适合流程稳定、部分步骤变化的场景。”

---

### 11. 访问者模式 Visitor（低频）

**核心作用：** 在不修改对象结构的前提下，给对象结构增加新的操作。

**常见场景：**
*   AST 遍历
*   编译器
*   对复杂对象结构做多种统计/导出

**面试常问：**
*   **访问者模式解决什么问题？**  
    在对象结构稳定时，方便新增操作，比如对 AST 增加打印、类型检查、代码生成。
*   **为什么它比较复杂？**  
    需要双分派，类之间依赖关系更绕；新增元素类型时所有访问者都要改。

**一句话回答：**
> “访问者模式适合对象结构稳定、操作经常新增的场景。它复杂度较高，普通业务面试不常深问。”

---

## 五、 面试常考优先级

### 1. 必须重点准备

这些在移动端 / 音视频 / SDK 面试里最常见：

*   **单例模式**：线程安全、DCL、Meyers Singleton、滥用问题。
*   **工厂模式**：简单工厂、工厂方法、抽象工厂区别。
*   **建造者模式**：复杂配置对象、Builder vs struct / setter。
*   **观察者模式**：Listener 回调、内存泄漏、弱引用、多线程 remove。
*   **策略模式**：软硬编切换、ABR 策略、丢帧策略。
*   **外观模式**：SDK 对外统一入口。
*   **适配器模式**：FFmpeg / MediaCodec / 第三方 SDK 接口适配。

### 2. 建议了解

*   **代理模式**：权限、远程调用、懒加载、动态代理。
*   **装饰器模式**：功能动态增强，如日志、滤镜、水印。
*   **模板方法模式**：固定流程 + 可变步骤。
*   **状态模式**：播放器/推流器状态机。
*   **责任链模式**：拦截器、校验链、处理链。
*   **桥接模式**：平台实现和抽象接口分离。
*   **组合模式**：树形结构。

### 3. 低频扫一眼即可

*   原型模式
*   享元模式
*   命令模式
*   解释器模式
*   迭代器模式
*   中介者模式
*   备忘录模式
*   访问者模式

## 六、 面试常问问题汇总

### Q1：GoF 23 种设计模式分哪几类？

**标准回答：**
> “分成创建型、结构型和行为型。创建型关注对象怎么创建，比如单例、工厂、建造者；结构型关注类和对象怎么组合，比如适配器、装饰器、外观、代理；行为型关注对象之间怎么协作，比如观察者、策略、状态、模板方法、责任链。”

### Q2：你项目里用过哪些设计模式？

**推荐回答方向：**
> “在音视频 SDK 里，我用得最多的是观察者、工厂、策略和建造者。观察者用于底层 C++ 引擎向 Java/OC 层回调状态；工厂用于根据机型能力创建硬编或软编编码器；策略用于软硬编切换、ABR 和丢帧策略；建造者用于 SDK 初始化配置，避免超长构造函数和非法参数组合。”

### Q3：工厂模式和策略模式有什么区别？

**标准回答：**
> “工厂模式关注对象怎么创建，解决的是‘创建哪个具体类’；策略模式关注算法怎么替换，解决的是‘运行时用哪套行为’。实际项目里二者经常配合：工厂负责创建具体策略对象，业务方通过策略接口调用。”

### Q4：观察者模式和发布-订阅模式有什么区别？

**标准回答：**
> “观察者模式通常是对象级直接通知，被观察者维护观察者列表并直接回调；发布-订阅中间有 Broker 或 EventBus，发布者和订阅者互相不知道，只通过 Topic 通信。简单说，观察者更近、更强类型；发布-订阅更远、更解耦、更适合系统级事件。”

### Q5：Builder 和工厂模式有什么区别？

**标准回答：**
> “工厂模式解决创建哪个类，比如创建硬编编码器还是软编编码器。Builder 解决一个复杂对象怎么配置，比如推流配置里的 URL、分辨率、码率、ABR 开关。工厂关注类型选择，Builder 关注参数构建。”

### Q6：策略模式和状态模式有什么区别？

**标准回答：**
> “策略模式是外部选择不同算法，策略之间通常彼此独立；状态模式是对象内部状态变化导致行为变化，状态之间通常有明确迁移关系。比如软硬编选择更像策略，播放器 Idle/Playing/Paused/Error 更像状态。”

### Q7：装饰器、代理、适配器、外观怎么区分？

**标准回答：**
> “适配器解决接口不兼容；外观给复杂子系统提供简单入口；代理控制对真实对象的访问；装饰器在不改原对象的情况下动态增强功能。它们结构可能相似，但设计意图不同。”

### Q8：设计模式是不是用得越多越好？

**标准回答：**
> “不是。设计模式是为了管理变化和复杂度，不是为了炫技。如果场景很简单，直接写清楚就行。比如只有一种实现就没必要上工厂，参数很少就没必要 Builder。面试里我更看重能不能判断什么时候不用模式。”

## 七、 音视频方向项目话术

### 1. 最推荐讲的组合

面试官问“你项目里用过哪些设计模式”，可以这样组织：

> “我不会泛泛地讲所有模式，我在项目里最典型的是四类。第一是观察者模式，底层 C++ 引擎通过 Listener 通知 Java/OC 层网络状态、首帧、错误码，并用 `WeakGlobalRef` 防止页面泄漏。第二是工厂模式，根据机型能力和配置创建硬编或软编编码器。第三是策略模式，ABR、丢帧、软硬编降级都可以抽成不同策略。第四是建造者模式，用于 SDK 初始化配置，集中校验 URL、分辨率、码率、零拷贝开关这些参数。”

### 2. 不建议主讲的模式

不建议一上来讲：

*   “我用单例做全局配置”
*   “我用迭代器遍历数组”
*   “我用原型模式复制对象”

这些不是不能讲，而是不够贴合音视频岗位。更好的策略是：**优先讲能体现 Pipeline、跨语言回调、软硬件调度、弱网策略的模式。**

---

## 八、 一句话总结

**GoF 23 种设计模式不用平均用力。面试真正高频的是单例、工厂、建造者、观察者、策略、适配器、外观、代理、状态、模板方法。**

最后可以这样收束：

> “我理解设计模式不是背名字，而是识别变化点。创建逻辑变化用工厂，参数构建复杂用 Builder，一对多通知用观察者，算法可替换用策略，复杂子系统对外收口用外观。用得对能降低耦合，用过头就会变成过度设计。”
