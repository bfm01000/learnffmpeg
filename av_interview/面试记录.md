## 你在团队中做过哪些基础建设的贡献，形成一整套流程，大家都用你这套流程

### 推荐回答（约 90 秒，以自动剪辑 3.0 为例）

> 我比较有代表性的基础建设，是在**自动剪辑 3.0** 里沉淀下来的一套「**算法接入 + 性能治理**」流程。
>
> 背景是：3.0 算法把送帧频率从 600ms 提到 200ms，整体出片速度直接不达标，产品上不了线。我主导接入时发现，问题不是某一个函数慢，而是**精度、抽帧、调度**三层叠在一起。我没有只修完 3.0 就结束，而是把排查和改造过程抽象成团队后面能复用的方法。
>
> 我沉淀了四块东西：
>
> **第一，算法接入的标准排查流程——「先分段打点，再定瓶颈，最后才改架构」。**  
> 任何新算法进来，先按「解封装 → 抽帧 → 渲染 → 推理 → 合成」做分段耗时统计，和算法侧给的 benchmark 对齐，避免凭感觉优化。3.0 就是用这套流程定位到：Seek 重复解码 + 三阶段串行，而不是算法本身慢。
>
> **第二，帧 ID 作为绝对索引的接入规范。**  
> 2.0 里上层用时间戳、算法用帧 ID，双向浮点转换会抽到不同帧（比如 999ms 和 1001ms）。3.0 我推动改成：**帧 ID 贯穿全链路，上层只做单向换算**。这套规范后面接新算法时，大家默认按这个来，不再重复踩精度坑。
>
> **第三，Smart Seek + 异构并行 Pipeline 的可复用模板。**  
> 抽帧层：同 GOP 内顺解丢帧，跨 GOP 才 Seek，关键帧判断直接读 FFmpeg 的 `index_entries`（MP4 stss 索引），不靠猜。调度层：抽帧走 VPU、渲染走 GPU、推理走 NPU/CPU，用生产者-消费者队列解耦三阶段，让总耗时收敛到「≈ 最慢阶段」。  
> 这套 Pipeline 在 3.0 跑通后，**全景自动剪辑**直接复用——还把「前进方向 + 结构化」两个算法合并成一次抽帧，并统一了 iOS / Android 渲染层，避免双端各写一套。
>
> **第四，内存侧的通用治理策略。**  
> GPU 渲染帧用对象池接收，避免高频 alloc 导致碎片；防抖内存从「一次性加载整段素材」改成**按窗口动态加载**（比如 30 分钟素材不再一次性占 270MB）。
>
> 所以这件事对我来说，价值不只是 3.0 性能提升几倍，而是后面团队接算法、做剪辑类 Feature 时，有了统一的**排查顺序、接入规范和 Pipeline 模板**，不用每次从零摸索。我也把排查过程和决策依据写成了复盘文档，新人接入时会直接参考。

### 口述结构速记（30 秒版）

> 自动剪辑 3.0 我主导接入时，沉淀了一套算法接入流程：**全链路打点定瓶颈 → 帧 ID 绝对索引规范 → Smart Seek 抽帧策略 → VPU/GPU/NPU 三阶段并行 Pipeline → 对象池 + 窗口化内存**。  
> 3.0 跑通后，全景自动剪辑和后续双端渲染都复用了这套模板，团队接新算法基本按这个流程走。

### 「一整套流程」拆成 5 步（被追问时可展开）

| 步骤 | 做什么 | 3.0 里怎么验证的 | 团队怎么复用 |
|---|---|---|---|
| 1. 分段打点 | 解封装 / 抽帧 / 渲染 / 推理 / 合成各段耗时 | 发现抽帧 Seek 重复解码、三阶段串行是主因 | 新算法接入第一步默认做 |
| 2. 精度规范 | 帧 ID 作绝对索引，禁止双向时间戳转换 | 消除 999ms vs 1001ms 抽帧误差 | 后续算法 SDK 接入规范 |
| 3. 抽帧策略 | Smart Seek：同 GOP 顺解丢帧，读 `index_entries` 判 GOP | 高频抽帧耗时稳定 | 所有 FFmpeg 抽帧场景可参考 |
| 4. 并行模板 | 生产者-消费者三队列，VPU / GPU / NPU 流水线 | 总耗时 ≈ 推理耗时 | **全景自动剪辑**直接复用 |
| 5. 内存治理 | 渲染帧对象池 + 防抖窗口化加载 | 长素材内存从 270MB 级降下来 | 剪辑类 Feature 通用 |

### 面试官可能追问

**Q：你说「大家都用」，具体是谁在用、用在哪？**

> 最直接的是**全景自动剪辑**：并行 Pipeline、一次抽帧跑双算法、双端渲染统一，都是基于 3.0 的模板扩展的。  
> 其次是**后续算法接入**：帧 ID 规范和「先打点再优化」的排查顺序，组里接新算法时会默认走这套，不需要每次重新争论用时间戳还是帧 ID。  
> 我不会说所有模块 100% 都照搬，但**剪辑链路的核心骨架**——抽帧策略 + 三阶段并行 + 内存治理——已经是团队共识了。

**Q：这套流程是你一个人定的，还是团队一起讨论的？**

> 架构方向和瓶颈定位是我主导的，但落地时有和算法同学对齐送帧频率和帧 ID 语义，和双端同学对齐渲染层统一，抽帧模块因为不在我们组，我这边是通过**改上层策略**（Smart Seek）绕开底层短期改不了的问题，没有硬推对方重构。  
> 流程能推广，主要是因为**可验证**——每一步都有打点数据支撑，不是拍脑袋定的规范。

**Q：和「做业务需求」有什么区别？**

> 业务需求是「3.0 要上线」；基础建设是「3.0 踩过的坑，后面的人不用再踩」。  
> 比如并行 Pipeline 如果只服务 3.0，那就是一次性优化；抽象成模板后，全景剪辑接入成本明显降低，这就是基建的价值。
