# 音视频编辑算法：时间线区间合并

在视频剪辑软件（如 Premiere、剪映）中，时间线（Timeline）是核心的数据结构。用户会在多条轨道上放置各种视频片段（Clip），这些片段往往会有重叠（例如画中画、转场效果）。

一个常见的业务需求是：**计算出整个时间线上，到底哪些时间段是有画面的？**（比如用于计算最终导出视频的总时长，或者用于在渲染时跳过完全没有画面的空白区域）。

这道题本质上是经典的算法题：**合并区间（LeetCode 56）**，但披上了音视频业务的外衣。

---

## 一、 问题分析

假设时间线上有以下几个视频片段（单位：秒）：
*   Clip 1: `[1, 3]` （从第 1 秒到第 3 秒）
*   Clip 2: `[2, 6]` （从第 2 秒到第 6 秒，与 Clip 1 有重叠）
*   Clip 3: `[8, 10]` （从第 8 秒到第 10 秒）
*   Clip 4: `[15, 18]`

**目标输出**：合并后有画面的连续区间：`[1, 6]`, `[8, 10]`, `[15, 18]`。

### 核心思路：排序 + 贪心

1.  **按起始时间排序**：
    首先，必须把所有的片段按照它们的**起始时间（start）**从小到大进行排序。
    排序后，我们可以保证：如果我们正在处理当前的区间，那么后面所有的区间，它们的起始时间一定不会早于当前区间。
    
2.  **贪心合并**：
    准备一个结果数组 `merged`。
    遍历排序后的片段：
    *   如果 `merged` 为空，或者当前片段的 `start` **大于** `merged` 中最后一个区间的 `end`，说明它们**没有重叠**，直接把当前片段加入 `merged`。
    *   否则，说明它们**有重叠**。此时，我们需要更新 `merged` 中最后一个区间的 `end`，将其延长为它原本的 `end` 和当前片段的 `end` 中的**最大值**。

## 二、 C++ 代码实现

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// 定义视频片段结构体
struct Clip {
    double start;
    double end;
    
    Clip(double s, double e) : start(s), end(e) {}
};

class TimelineAlgorithm {
public:
    // 合并时间线上的视频片段
    static std::vector<Clip> mergeClips(std::vector<Clip>& clips) {
        if (clips.empty()) {
            return {};
        }

        // 1. 按照起始时间从小到大排序
        // 使用 Lambda 表达式定义排序规则
        std::sort(clips.begin(), clips.end(), [](const Clip& a, const Clip& b) {
            return a.start < b.start;
        });

        std::vector<Clip> merged;
        
        // 2. 遍历并合并
        for (const auto& clip : clips) {
            // 如果 merged 为空，或者当前 clip 的起始时间大于 merged 中最后一个区间的结束时间
            // 说明没有重叠，直接加入
            if (merged.empty() || merged.back().end < clip.start) {
                merged.push_back(clip);
            } 
            // 否则，说明有重叠，更新最后一个区间的结束时间
            else {
                merged.back().end = std::max(merged.back().end, clip.end);
            }
        }

        return merged;
    }
};

// ================= 测试代码 =================
int main() {
    // 模拟时间线上的视频片段
    std::vector<Clip> timeline = {
        Clip(2.0, 6.0),
        Clip(1.0, 3.0),
        Clip(15.0, 18.0),
        Clip(8.0, 10.0),
        Clip(2.5, 4.0)
    };

    std::vector<Clip> result = TimelineAlgorithm::mergeClips(timeline);

    std::cout << "合并后的有画面区间：" << std::endl;
    for (const auto& clip : result) {
        std::cout << "[" << clip.start << ", " << clip.end << "] ";
    }
    std::cout << std::endl;
    // 预期输出: [1, 6] [8, 10] [15, 18]

    return 0;
}
```

## 三、 面试官可能的追问与进阶

### 追问 1：这个算法的时间复杂度和空间复杂度是多少？
**回答**：
*   **时间复杂度**：$O(N \log N)$。因为主要的时间消耗在对数组进行排序上（`std::sort` 通常是快速排序或内省排序），遍历合并的过程只需要 $O(N)$。所以总体是 $O(N \log N)$。
*   **空间复杂度**：$O(\log N)$ 或 $O(N)$。如果不算返回的结果数组 `merged`，排序本身需要 $O(\log N)$ 的栈空间。如果算上结果数组，最坏情况下（没有重叠）需要 $O(N)$ 的空间。

### 追问 2（业务进阶）：如果我不仅想知道有画面的时间段，我还想知道在某个特定的时间点（比如第 4 秒），到底有几个视频片段叠在一起（计算合成复杂度）？
**回答思路（扫描线算法 / 差分数组）**：
这就变成了经典的“会议室”问题（LeetCode 253）。
1.  我们可以把每个片段拆分成两个事件：一个**入场事件** `(start, +1)`，一个**出场事件** `(end, -1)`。
2.  把所有事件放到一个数组里，按照时间点进行排序。
3.  遍历这个事件数组，维护一个计数器 `current_clips`。遇到入场事件就 `+1`，遇到出场事件就 `-1`。
4.  在遍历的过程中，`current_clips` 的最大值，就是时间线上重叠片段最多的数量（也就是这一帧需要进行 Alpha 混合渲染的最大图层数）。

### 追问 3（架构进阶）：如果时间线非常长，包含上万个片段，用户在播放时，引擎如何快速找到当前时间点（Playhead）需要渲染哪些片段？
**回答思路（区间树 Interval Tree）**：
如果每次渲染一帧都要去遍历上万个片段，性能会极差。
在非编系统（NLE）的底层架构中，我们通常会使用**区间树（Interval Tree）**或**线段树（Segment Tree）**来管理时间线数据。
区间树可以在 $O(\log N + K)$ 的时间复杂度内（其中 $K$ 是重叠的片段数），快速检索出所有与当前播放时间点相交的片段，极大地提升了渲染调度引擎的效率。
