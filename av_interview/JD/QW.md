## 岗位解读

这是**夸克/千问体系下的浏览器与跨端容器底层岗**，核心不是音视频，而是：

| 方向 | 典型技术栈 |
|------|-----------|
| 浏览器内核 | Chromium / WebKit、多进程架构、Blink 渲染、网络/沙箱 |
| 跨端容器 | CEF、Electron、自研 Web 容器 |
| PDF 内核 | PDFium 或自研 PDF 解析/排版/渲染 |
| Flutter 容器 | Engine 嵌入、Skia、平台适配 |

JD 里的「深入底层优化、极致用户体验」偏**渲染管线、内存、启动、滚动、排版**，和当前的 **FFmpeg / MediaCodec / 零拷贝推流** 是相邻赛道，但不是同一条主线。

## 哪些「可以」——能写进简历、面试能讲

1. **C++ 底层与性能攻坚**（JD 第 2 条最强命中）  
   4K 直播 40ms→10ms、车载 1.5s→0.5s、异构 Pipeline，都是「全链路埋点 → 根因 → 架构改造」，和内核岗的工作方式一致。

2. **跨平台 SDK 与 ABI/生命周期**（JD「跨端」的侧面）  
   C++ 核心 + JNI/OC 桥接、向后兼容、跨线程对象安全，和「容器把 native 能力暴露给上层」是同一类工程问题。

3. **生产者-消费者、无锁队列、内存池**（补强.md 正在补的设计模式）  
   浏览器里 IO/渲染/合成/网络线程间调度大量用到这类模型。

4. **与「媒体在浏览器里」的弱相关**  
   若团队做 WebRTC、`<video>`、硬件解码、零拷贝 Surface 上传，MediaCodec / Surface / Fence 经验**可能**成为加分项，但 JD 主战场仍是 **HTML/CSS 布局 + 绘制 + PDF**，不是直播 Pipeline。

## 哪些仍是「短板」——但不挡投递，挡的是面试深度

> 内推已明确：**不要求浏览器相关经验**。下列项从「简历硬伤」降为「入职前/面试前建议了解」。

1. **Chromium/WebKit 体系**：进程模型、Blink 渲染主路径——面试能画一张架构图即可，不必声称做过。
2. **CEF/Electron / PDF / Flutter**：了解「是什么、解决什么问题」，细节入职后学。
3. **浏览器产品指标**：首屏、内存峰值、站点兼容——与「帧率/延时」不同，但都是**数据驱动优化**，方法论一致。

**真正要警惕的面试风险**（和内推诉求直接相关）：

- C++ 语言细节：内存模型、`std::move`、虚析构、RAII、模板基础、对象生命周期。
- 多线程：锁、条件变量、死锁、原子序、你的 DispatchQueue / 生产者-消费者要能讲透。
- 算法与数据结构：大厂内核岗常考，需单独刷题（链表/树/哈希/双指针/滑动窗口）。
- 系统设计：大型 C++ 模块如何分层、如何向后兼容（你的参数化动态路由是好例子）。

## 一句话总结（更新）

- **内推后的真实画像**：招 **C++ 特别扎实的底层同学** 做浏览器内核，**不要求** Chromium 经验。
- **你的命中点**：5 年 native 底层、性能溯源、多线程、零拷贝、跨平台 SDK —— 与「特别偏底层」高度一致。
- **真正的门槛**：C++ 语言 + 算法笔试 + 能否把现有项目讲到「内核级深度」。
- **建议**：**投递**；面试前 1～2 周主攻 C++ 与算法，浏览器概念扫一遍即可，不必先花 2 个月啃完 Chromium。
