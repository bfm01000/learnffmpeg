## 面试前建议加强的方向

### P0 — 投递前 1～2 周必补（决定技术面下限）

**1. WebRTC 连麦主线（最重要）**

- 弄清信令（SDP Offer/Answer）、ICE / STUN / TURN、SRTP、SFU 与 MCU 的区别。
- 对照你已掌握的 AJB，整理一份与 NetEQ / Jitter Buffer 的对照：时钟映射、快升慢降、丢帧策略各怎么取舍。
- 能口述 NACK / FEC / PLI 各解决什么问题；连麦为何常用 UDP + 可靠性机制，而不是纯 TCP。
- 推荐抓手：扫读 WebRTC 的 `modules/video_coding`（Jitter）、`modules/congestion_controller/goog_cc`（GCC），并画一张连麦端到端时序图。

**2. 把 4K 直播项目翻译成「SDK 架构语言」**

- 讲清分层：采集 / 渲染 / 编码 / mux / 发送 / 策略（ABR）的模块边界与线程模型。
- 强调参数化开关、向后兼容、JNI 生命周期——大厂 SDK 岗很爱问。
- 准备一页弱网降级链路：队列水位 → 码率 → 编码器参数 → 观众端表现。

**3. RTP / RTSP 速补（应对任职资格原文）**

- RTP：时间戳、SSRC、PT、与 H.264 FU-A 分片的关系（知道即可，不必实现完整协议栈）。
- RTSP：OPTIONS → DESCRIBE → SETUP → PLAY → TEARDOWN 流程；能说清与 RTMP、HLS 各自适用的场景。
- 面试话术示例：「生产主推 RTMP + HLS；RTP / RTSP 我系统学过，监控 / 拉流场景可以快速上手。」

### P1 — 面试当周强化（拉高通过率）

**4. 桌面端叙事**  
准备 C++ 核心 Pipeline 如何复用到 Win / Mac（渲染 API 差异：D3D / Metal vs GLES）。若 `av_interview/项目/桌面端面试文档` 已有材料，把「与移动端零拷贝同构的设计」串成 3 分钟答案。

**5. 编解码质量**  
码率控制（CBR / VBR）、GOP 长度对 Seek 和弱网的影响；H.265 vs H.264 在同画质码率、解码功耗、机型兼容上的取舍。车载项目里 High vs Main Profile 的排查经历可以直接复用。

**6. 网络基础深挖**  
从「TCP 阻塞导致编码掉帧」引申到「直播推流常用 TCP（RTMP）、RTC 常用 UDP」的原因。准备延迟 / 抖动 / 丢包 / 带宽四元组，以及如何用埋点区分网络问题、渲染问题、解码问题。

- 读行业分享里美颜、合流、PK 连麦等多路流架构，知道术语即可。
