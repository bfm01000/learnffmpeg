## 项目一 · 4K 直播（C++ 向）

| 段落 | 内容（请按你的数据微调） |
|------|--------------------------|
| 问题 | 4K RTMP 初始 22fps，10min 后跌至 5fps；`glReadPixels`+色彩转换 ~30ms |
| 方案 | `AHardwareBuffer` 零拷贝；Sync Fence 替代 `glFinish`；`AV_PIX_FMT_AHARDWAREBUFFER`；异步发送队列 + 水位 ABR；`shared_ptr` 保活 Muxer |
| 结果 | 单帧 40ms→10ms；长时 29-30fps；弱网 ABR 不幻灯片 |
| 追问 | 为何不加 `CPU_READ`？Gralloc Linear vs Tiled；为何 JNI 调 Java `setParameters` |

## 项目二 · 车载 AJB（C++ 向）

| 段落 | 内容 |
|------|------|
| 问题 | X5 预览 1.5s，X3 0.5s；解码不是瓶颈，首帧延时被渲染策略固化 |
| 方案 | `steady_clock` 媒体时钟映射；非对称 EMA；背压追赶；过期丢帧；250ms Resync |
| 结果 | 1.5s→0.5s，降 60%+，平滑度不降 |
| 追问 | 为何解码后做 AJB 而非 H264 队列；与 WebRTC NetEQ 的异同（了解即可） |

## 项目三 · 自动剪辑（C++ 向）

| 段落 | 内容 |
|------|------|
| 问题 | 抽帧 200ms 间隔，Seek 不复用导致重复解码；串行 Pipeline 慢 |
| 方案 | Smart Seek + `index_entries`；生产者-消费者三阶段并行；对象池；窗口化防抖内存 |
| 结果 | 出片数倍提升；修复 2.0 抽帧精度 |
| 追问 | GOP 内顺解条件；VPU/GPU/NPU 并行依据 |

## 浏览器 / 转型（被问到时）

**Q：没做过浏览器，为什么投？**

> 内推也提到岗位不要求浏览器背景，核心是 C++ 底层。我过去五年一直在做 **多线程 Pipeline、零拷贝 buffer 流转、跨平台 native 桥接和性能溯源**，和内核团队的工作方式一致。Chromium 的多进程、渲染管线我会在入职后系统学；面试前我已掌握架构级概念，并能把现有经验映射过去。

**Q：CEF 了解吗？**

> CEF 是 Chromium Embedded Framework，让桌面/移动端 App **内嵌完整网页能力**，本质是多进程 Chromium 的嵌入式发行版。和我做过的 **C++ SDK + JNI 暴露给上层** 类似，都是容器层封装 native 能力。
